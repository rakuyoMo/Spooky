Spooky에서 저장소에 하는 일은 대부분 <kbd>⌘Z</kbd>로 되돌릴 수 있습니다. 나머지는 Git의 Reflog가 브랜치가 거쳐 온 위치를 기억하므로, 커밋을 완전히 잃는 일은 드뭅니다.

## 실행 취소와 실행 복귀 {#undo}

마지막 작업을 되돌리려면 :ui[menu.edit > menu.undo](<kbd>⌘Z</kbd>)를 선택합니다. 메뉴 항목에는 작업의 이름이 들어 있습니다. 다시 실행하려면 :ui[menu.edit > menu.redo](<kbd>⇧⌘Z</kbd>)를 선택합니다. 가장 최근 작업부터 여러 작업을 차례로 되돌릴 수 있습니다.

예를 들어 다음을 실행 취소할 수 있습니다.

- 스테이지, 커밋, 커밋 수정
- 변경 사항 버리기와 파일을 휴지통으로 이동하기
- 스태시 저장, 적용, 삭제
- 브랜치 체크아웃, 생성, 이름 변경, 삭제와 태그 생성
- 브랜치 고정과 보관, 업스트림 설정, 빨리 감기
- 병합, 리베이스, 체리픽, 되돌리기, 재설정
- 원격 추가, 이름 변경, 제거와 원격 설정 변경
- 브랜치와 태그 게시, 원격 브랜치 이름 변경
- 파일을 assume-unchanged로 표시하기, Git LFS 켜기, 하위 모듈 변경

휴지통으로 간 파일은 휴지통에서 되돌려 놓습니다. 추적 중인 파일에 변경이 있는 상태에서 재설정을 실행 취소하면 Spooky가 먼저 스태시할지 묻습니다. 새 스태시는 목록에 남습니다.

커밋 메시지 같은 텍스트 필드에 입력하는 동안에는 <kbd>⌘Z</kbd>가 입력한 내용을 실행 취소합니다.

저장소마다 실행 취소 기록이 하나 있고, 그 저장소의 모든 윈도우가 함께 씁니다. Spooky는 종료할 때까지 이 기록을 유지합니다. 여기에 필요한 스냅샷은 저장소 자체의 Git 데이터베이스에 저장되고, 어디로도 푸시되지 않습니다.

:::note[서버 저장소]
스냅샷은 서버에 있는 저장소에 저장됩니다. 서버의 휴지통으로 간 파일은 거기에서 되돌려 놓습니다.
:::

## 실행 취소할 수 없는 것 {#cant-undo}

실행 취소는 저장소를 이전 상태로 되돌립니다. 다음 변경은 Spooky가 복원할 수 있는 범위 밖입니다.

- 원격의 브랜치와 태그 삭제. 로컬 브랜치를 원격 브랜치와 함께 삭제한 경우는 예외로, 실행 취소하면 둘 다 다시 만들어집니다.
- 커미터 정보, 무시 규칙, 그 밖의 Git 설정 변경.
- 병합, 리베이스 등의 작업이 진행 중인 동안 한 모든 일. 작업을 계속하거나 중단하는 것도 포함됩니다.
- 충돌에서 멈춘 리베이스나 체리픽. 충돌에서 멈춘 병합이나 되돌리기는 실행 취소할 수 있고, 그러면 작업이 중단됩니다.
- 완전히 삭제된 새 파일. 휴지통이 없는 서버에서 그렇게 됩니다.
- 하위 모듈 초기화, 동기화, 복구, 작업 트리로 하는 모든 일, Git LFS 훅 업데이트, 호스팅 서비스에 저장소 게시. [하위 모듈](/guide/advanced/submodules/#undo), [작업 트리](/guide/advanced/worktrees/#undo), [Git LFS](/guide/advanced/lfs/#undo), [저장소 게시하기](/guide/hosting/accounts/#publish)를 참고하세요.

이런 작업 뒤에는 메뉴 항목에 그 작업을 실행 취소할 수 없다고 표시됩니다. 그 전의 작업도 더는 실행 취소할 수 없습니다.

가져오기, 풀, 푸시, 동기화는 기록되지 않습니다. 실행 취소할 수 없습니다. 하위 모듈 가져오기와 업데이트, LFS 콘텐츠 가져오기, 풀, 푸시도 마찬가지입니다.

## 실행 취소가 막힐 때 {#blocked}

실행 취소는 저장소가 작업이 끝난 직후의 상태 그대로일 때만 됩니다. 그렇지 않으면 메뉴 항목이 흐리게 표시되고 괄호 안에 이유가 나옵니다.

| 이유 | 할 일 |
|---|---|
| :ui[undo.reason.busy] | 실행 중인 작업이 끝나기를 기다리거나, 진행 중인 병합, 리베이스 등의 작업을 마칩니다. |
| :ui[undo.reason.disconnected] | 서버에 다시 연결합니다. |
| :ui[undo.reason.changed] | 작업 이후에 저장소가 바뀌었습니다. 풀이나 동기화로 커밋이 들어왔거나, 터미널이나 다른 앱이 저장소를 바꿨습니다. 원래대로 돌려놓으면 실행 취소가 다시 됩니다. |

Spooky는 실행 취소하기 직전에 저장소를 한 번 더 확인합니다. 방해가 되는 것이 있으면 멈추고 이유를 알려 줍니다. 아무것도 바뀌지 않습니다.

| 메시지 | 이유 |
|---|---|
| :ui[undo.error.changed] | 저장소가 Spooky가 기록해 둔 상태와 더는 일치하지 않습니다. |
| :ui[undo.error.untracked] | 복원하면 추적되지 않는 파일을 덮어쓰거나 삭제하게 됩니다. |
| :ui[undo.error.hidden] | assume-unchanged로 표시한 파일에 로컬 변경이 있거나, 저장소가 skip-worktree를 사용합니다. |
| :ui[undo.error.inProgress] | 병합, 리베이스, 체리픽, 되돌리기를 먼저 마치거나 중단합니다. |
| :ui[undo.error.conflicts] | 충돌을 먼저 해결합니다. [충돌 해결하기](/guide/work/conflicts/)를 참고하세요. |
| :ui[undo.error.trash] | 일부 파일이 더는 휴지통에 없거나, 원래 자리에 다른 파일이 있습니다. |

## Reflog로 커밋 되찾기 {#reflog}

Git은 HEAD와 각 로컬 브랜치가 가리켜 온 위치를 기록해 둡니다. 재설정, 리베이스, 브랜치 삭제로 잃어버린 커밋은 대개 여기에 남아 있습니다. 한 번도 커밋하지 않은 변경은 없습니다.

1. :ui[menu.view > reflog.show](<kbd>⌘6</kbd>)를 선택합니다.
2. 맨 위의 :ui[reflog.ref] 메뉴에서 HEAD나 로컬 브랜치를 선택합니다.
3. 항목을 찾습니다. 항목마다 짧은 해시, 일어난 일, 시각이 표시되고 그 아래에 Git의 설명이 있습니다. 목록을 걸러 보려면 도구 막대의 검색 필드에 입력합니다.
4. 항목을 선택하면 커밋의 세부사항이 표시됩니다.

::screenshot[HEAD의 Reflog 보기. 항목마다 짧은 해시, commit, checkout, reset 같은 동작, 날짜가 있고 그 아래에 메시지가 있습니다. 선택한 항목의 커밋 세부사항이 오른쪽에 있습니다.]{name="work-reflog" frame="window" markers="33.5,9 44.1,37.1 84.4,21.3"}

1. :ui[reflog.ref] 메뉴
2. 선택한 항목
3. 커밋의 세부사항

커밋을 되찾으려면 항목을 오른쪽 클릭합니다.

- :ui[reflog.createBranch]{1="9e0d36a7"}는 그 지점에서 새 브랜치를 시작합니다. 지금 있는 브랜치는 그대로입니다.
- :ui[reflog.restore]{1="feature/units-toggle" 2="9e0d36a7"}은 보고 있는 브랜치를 그 커밋으로 되돌립니다. 작업 사본과 인덱스은 바뀌지 않습니다. Spooky가 먼저 묻고, 실행 취소할 수 있습니다.
- :ui[reflog.cherryPick]{1="9e0d36a7"}은 그 커밋을 현재 브랜치에 복사합니다. 항목을 사이드바의 :ui[workspace.title]이나 현재 브랜치로 드래그해도 됩니다.
- :ui[reflog.reset]{1="9e0d36a7"}은 재설정 대화상자를 엽니다. 현재 브랜치를 그 커밋으로 옮길 때 씁니다.
- :ui[patch.menu]{1="9e0d36a7"}은 그 커밋을 패치 파일로 저장합니다.

사이드바에 :ui[reflog.title]를 두려면 :ui[sidebar.viewSettings]에서 :ui[sidebar.showReflog]를 켭니다.

:::caution
Git은 오래된 Reflog 항목을 시간이 지나면 제거합니다. 기본적으로 항목은 90일 동안 유지되고, 커밋이 더는 브랜치에 없으면 30일 동안 유지됩니다. 잃어버린 커밋은 서둘러 되찾습니다.
:::

:::note[서버 저장소]
Reflog는 서버에 있는 저장소에 있습니다. Spooky는 거기에서 읽습니다.
:::
