---

ここで説明するコマンドのほとんどは、[履歴](/guide/history/browse/) の一覧から始めます。コミットを右クリックするか、先に複数のコミットを選択します。リバートとチェリーピックは新しいコミットを追加します。それ以外は、すでにあるコミットを書き換えます。

:::caution
書き換えたコミットには新しいハッシュが付きます。すでにプッシュしていた場合、ブランチと上流が分岐し、もう一度プッシュするには強制プッシュが必要です。古いコミットをすでに取得している人は、履歴を整理し直す必要があります。[強制プッシュ](/guide/branches/sync/#force-push) を参照してください。
:::

チェリーピックとリセットを除き、これらのコマンドは、一覧に現在のブランチだけを表示している間だけコミットのメニューに表示されます。その表示にするには、:ui[menu.view > history.showHead]（<kbd>⌘0</kbd>）を選ぶか、サイドバーでそのブランチをクリックします。

::screenshot[一覧に現在のブランチを表示しているときの、コミット 2daa6982 のコンテキストメニュー。リセット、リバート、別の場所へのリベースなどの項目があり、続いてこのコミットの修正、編集、コミットメッセージの編集、削除の項目が並んでいます。]{name="history-commit-menu" frame="closeup"}

## コミットをリバートする {#revert}

リバートは、以前のコミットの変更を打ち消すコミットを追加します。以前のコミットは履歴に残るため、すでにプッシュしたものを取り消すときの安全な方法です。

1. コミットを右クリックして、メニューから :ui[rewrite.menu.revert]{1="e2dda2bc"} を選びます。複数のコミットを選択している場合、項目は :ui[rewrite.menu.revertMany]{1="3"} になります。
2. :ui[rewrite.revert.commit] はデフォルトでオンになっていて、リバートするコミットごとに 1 つのコミットが作成されます。オフにすると、変更は作業コピーに残ります。この選択は記憶されます。
3. :ui[rewrite.revert.button] をクリックします。

複数のコミットは、新しいものから古いものへ順にリバートされます。マージコミットをリバートするには、:ui[rewrite.mainline] を選びます。これは、メインラインとして扱う側の親です。マージコミットは、単独でしかリバートできません。

コミットの詳細と [複数のコミットの選択](/guide/history/commit-details/#multiple) にも :ui[rewrite.revert.button] ボタンがあります。

## コミットをチェリーピックする {#cherry-pick}

チェリーピックは、別のブランチのコミットの変更を、新しいコミットとして現在のブランチにコピーします。

1. サイドバーで別のブランチをクリックして、その履歴を表示します。
2. コミットを右クリックして、メニューから :ui[rewrite.menu.cherryPick]{1="e2dda2bc"} を選びます。複数のコミットを選択している場合、項目は :ui[rewrite.menu.cherryPickMany]{1="3"} になり、右側の :ui[rewrite.cherryPick.button] をクリックすることもできます。
3. オプションを選びます。選択は記憶されます。
   - :ui[rewrite.cherryPick.commit]（デフォルトでオン）は、1 件ずつコミットします。オフにすると、変更を作業コピーに適用するだけになります。
   - :ui[rewrite.cherryPick.fastForward] は、ブランチがそのコミットの親の位置にあるとき、コミットをコピーする代わりにブランチをそのコミットまで進めます。最初のオプションがオンのときだけ適用されます。
4. :ui[rewrite.cherryPick.button] をクリックします。

コミットは、古いものから新しいものへ順に適用されます。マージコミットには、リバートと同じく :ui[rewrite.mainline] が必要です。

一覧に現在のブランチを表示している間は、この項目は、まだプルしていない上流のコミットにだけ表示されます。

一覧からコミットを、サイドバーの :ui[workspace.title] または現在のブランチにドラッグすることもできます。ドロップするときに <kbd>⌥</kbd> を押したままにすると、代わりにリバートします。

## 以前のコミットにリセットする {#reset}

リセットは、現在のブランチを別のコミットに移動します。それよりあとのコミットは、ブランチから外れます。

1. コミットを右クリックして、メニューから :ui[rewrite.menu.reset]{1="e2dda2bc"} を選びます。コミットの詳細の :ui[history.rollback] をクリックするか、メニューバーで :ui[workspace.title > rewrite.reset.menu] を選ぶこともできます。
2. :ui[rewrite.revision] を確認します。ブランチ、リモートブランチ、タグを選ぶか、ハッシュを入力できます。ダイアログには、ブランチから外れるコミットが一覧表示されます。
3. :ui[rewrite.reset.mode] を選びます。
   - :ui[rewrite.reset.soft] は、ステージングエリアと作業コピーをそのまま残します。外れるコミットの変更は、ステージされたままになります。
   - :ui[rewrite.reset.mixed] は、ステージングエリアをリセットし、作業コピーを残します。それらの変更は未ステージになります。
   - :ui[rewrite.reset.hard] は、両方をリセットします。コミットしていない変更と、外れるコミットの変更は破棄されます。
4. :ui[rewrite.reset.button] をクリックします。

ダイアログは、毎回 :ui[rewrite.reset.soft] が選ばれた状態で開きます。リセットでは、変更をスタッシュするかどうかは尋ねられません。

:::caution
:ui[rewrite.reset.hard] は、追跡中のファイルのコミットしていない変更を破棄します。そうした変更があるときは、ダイアログに警告が表示されます。<kbd>⌘Z</kbd> で元に戻せますが、Spooky を終了するまでの間だけです。
:::

## コミットを別のベースへリベースする {#rebase-onto}

:ui[rewrite.rebaseOnto] は、コミットを別のコミットの上に移動します。

- ブランチのひと続きの部分をまとめて移動するには、メニューバーで :ui[workspace.title > rewrite.rebaseOnto.menu] を選びます。:ui[rewrite.rebaseOnto.current] と :ui[rewrite.rebaseOnto.new] を入力します。現在のベースよりあとのコミットが、新しいベースの上に適用し直されます。
- 一部のコミットだけを移動するには、それらを選択して右クリックします。メニューから :ui[rewrite.menu.rebaseOntoMany]{1="3"}、コミットが 1 件の場合は :ui[rewrite.menu.rebaseOnto]{1="e2dda2bc"} を選び、:ui[rewrite.rebaseOnto.new] を入力します。同じひと続きの中で選択しなかったコミットは、ブランチから取り除かれます。

どちらのベースにも、チェックアウトしているコミットは指定できません。ダイアログには書き換えられるコミットが一覧表示され、すでにプッシュ済みのものやほかのブランチに含まれるものがあるときは警告が表示されます。:ui[sync.skipHooks] は、今回だけリポジトリの pre-rebase フックをスキップします。開始するには、:ui[rewrite.rebaseOnto.button] をクリックします。

ブランチを別のブランチにリベースするには、[リベース](/guide/branches/merge-rebase/#rebase) を参照してください。

## スカッシュ、Fixup、削除、移動 {#interactive}

これらのコマンドは、現在のブランチの連続したコミットを書き換えます。コミットを選択して右クリックし、次のいずれかを選びます。

- :ui[rewrite.menu.squashMany]{1="3"} は、選択したコミットを最も古いコミットにまとめます。メッセージは結合され、一覧では新しいコミットが選択されます。
- :ui[rewrite.menu.fixupMany]{1="3"} は、選択したコミットを最も古いコミットにまとめ、そのコミットのメッセージだけを残します。
- :ui[rewrite.menu.deleteMany]{1="3"} は、選択したコミットをブランチから取り除きます。コミットを 1 件だけ選択しているときは、:ui[rewrite.menu.delete]{1="e2dda2bc"} が同じ働きをします。

一覧の中でコミットをドラッグすることもできます。

- 別のコミットにドロップすると、そのコミットにスカッシュされます。ドロップするときに <kbd>⌥</kbd> を押したままにすると、代わりに Fixup になります。ドロップ先のラベルには :ui[rewrite.squash.button] または :ui[rewrite.fixup.button] と表示されます。
- 2 つの行の間にドロップすると、そこに移動します。ラベルには :ui[branch.moveHere] と表示されます。

どの操作でも、Spooky は書き換える前に確認を求めます。ダイアログには、書き換えられるすべてのコミットと、:ui[rewrite.note.squash] や :ui[rewrite.note.drop] のようにそれぞれがどうなるかが一覧表示されます。すでにプッシュ済みのコミットやほかのブランチに含まれるコミットには黄色の警告マークが付き、一覧の上の警告で説明されます。すでに上流にあるコミットを削除するときは、その前にもう 1 つ確認があります。

::screenshot[2 件のコミットを 10e44ab8 にスカッシュする前に確認を求めるダイアログ。上部の 2 つの警告は、一部のコミットがすでに上流ブランチやほかのブランチにあることを伝えています。その下の一覧には、書き換えられる 4 件のコミットと、それぞれがどうなるかが表示されています。プッシュ済みのコミットには、行の末尾に黄色の警告マークが付いています。ボタンは「キャンセル」と「コミットをスカッシュ」です。]{name="history-rewrite-confirm" frame="dialog"}

## コミットメッセージを編集する {#reword}

1. コミットを右クリックして、メニューから :ui[rewrite.menu.reword]{1="e2dda2bc"} を選びます。
2. :ui[working.subject] と :ui[working.body] を変更します。コメント行は、[コミットエリア](/guide/work/commit/#comments) と同じように扱われます。
3. :ui[rewrite.reword.button] をクリックします。

それよりあとのコミットも書き換えられ、一覧ではそのコミットが新しいハッシュで選択されます。コミットがすでに上流にある場合、Spooky はダイアログを開く前に確認を求めます。

## コミットを編集する {#edit}

編集は、コミットの位置で止まり、その変更を作業コピーに戻します。コミットを分割したり、やり直したりできます。

1. コミットを右クリックして :ui[rewrite.menu.edit]{1="e2dda2bc"} を選びます。:ui[rewrite.edit.button] で確定します。
2. バナーに :ui[conflict.title.edit]{1="e2dda2bc" 2="main"} と表示されます。コミットの変更は、未ステージの状態で作業コピーにあります。
3. いつものようにステージしてコミットします。コミットはいくつに分けてもかまいません。
4. バナーの :ui[working.endEditing] をクリックします。それよりあとのコミットが、その上に適用し直されます。

取りやめるには、バナーの :ui[working.abort] をクリックします。リポジトリの最初のコミットは編集できません。

## 以前のコミットを修正する {#amend}

以前のコミットの修正は、[直前のコミットの修正](/guide/work/commit/#amend) と同じように、そのコミットに変更を追加します。

1. コミットを右クリックして :ui[rewrite.menu.amend]{1="e2dda2bc"} を選びます。Spooky は確認なしですぐに開始します。
2. リベースがそのコミットで止まります。変更を加えて、ステージします。
3. コミットエリアで :ui[working.amend] を選択し、コミットします。
4. バナーの :ui[working.endEditing] をクリックします。それよりあとのコミットが、その上に適用し直されます。

開始するときにローカルの変更がある場合、Spooky は先にスタッシュすることを提案します。変更はその後もスタッシュに残るため、リベースが止まっている間でも、あとからでも適用できます。

## 自動スカッシュ {#autosquash}

コミットには、以前のコミットに対する修正であるという印を付けられます。件名を `fixup!`、`squash!`、`amend!` のいずれかで始め、そのあとに以前のコミットの件名を続けます。コミットエリアでは [件名が補完](/guide/work/commit/#autocomplete) されます。

一覧に検索なしで現在のブランチを表示していて、最新の 1,000 件のコミットにそうしたコミットが含まれているときは、ヘッダの下に :ui[rewrite.autosquash] というタイトルのバナーが表示されます。バナーの :ui[rewrite.autosquash.button] をクリックして、確定します。印の付いたコミットは、それぞれが指しているコミットにまとめられます。

- `fixup!` は、以前のコミットのメッセージを残します。
- `squash!` は、両方のメッセージを結合します。
- `amend!` は、以前のコミットのメッセージを自分のメッセージで置き換えます。

× をクリックすると、バナーがいったん隠れます。

## 書き換えを開始できないとき {#errors}

Spooky は、書き換える前にコミットを確認します。問題があれば理由を説明し、何も変更しません。

| メッセージ | 理由 |
|---|---|
| :ui[rewrite.error.notInHead] | コミットはすべて、現在のブランチの履歴の 1 本の線の上にある必要があります。 |
| :ui[rewrite.error.merges] | 途中にマージコミットがあり、書き換えるとそれが平坦になってしまいます。最後のマージよりあとのコミットを選びます。 |
| :ui[rewrite.error.root] | リポジトリの最初のコミットには、変更を戻す先の親がありません。 |
| :ui[rewrite.error.selection] | スカッシュには少なくとも 2 件のコミットが必要で、まとめる先を、まとめられるコミットの中から選ぶことはできません。 |
| :ui[rewrite.error.autosquash] | 以前のコミットに対する印の付いた最近のコミットがありません。 |
| :ui[rewrite.error.changed] | Spooky が読み込んだあとでブランチが変更されました。履歴を更新してから、もう一度試します。 |

## ローカルの変更と競合 {#local-changes}

リバート、チェリーピック、リベースには、妨げにならない状態の作業コピーが必要です。ローカルの変更がこれらの操作を妨げるときは、Spooky が [先にスタッシュする](/guide/work/stash/#auto-stash) ことを提案します。以前のコミットの修正では、開始する前に尋ねます。

途中でコミットが競合した場合、Spooky は止まって [操作のバナー](/guide/work/conflicts/#banner) を表示します。競合を解決してから、そこで続行または中止します。

## 書き換えを取り消す {#undo}

リバート、チェリーピック、リセット、書き換えを取り消すには、:ui[menu.edit > menu.undo]（<kbd>⌘Z</kbd>）を選びます。コミットの編集などでリベースが止まっている間は、先にそれを完了するか中止します。競合で止まったリベースまたはチェリーピックは取り消せません。[取り消しと復元](/guide/work/undo/) を参照してください。

古いコミットは、しばらくの間 [Reflog](/guide/work/undo/#reflog) にも残ります。

:::note[サーバーリポジトリ]
コミットはサーバー上で書き換えられます。履歴を書き換えるダイアログには、どれも実行先のサーバーの名前が表示されます。
:::
