title: "競合を解決する"
description: "マージ、リベースなどの進行中の操作で起きた競合を、競合ウィザードまたは外部のマージツールで解決し、操作を続行または中止する方法を説明します。"
---

競合は、双方がファイルの同じ部分を変更していて、どちらの変更を残すかを Git が判断できないときに起こります。マージ、リベース、チェリーピック、リバートはそこで止まり、スタッシュの適用も同じように止まります。それぞれのファイルに何を入れるかを決めてから、操作を完了します。

::screenshot[「feature/units-toggle」を「main」にマージしている途中の作業コピー。中央のカラムの上部にある黄色のバナーに、未解決の競合が 1 件、解決済みが 0 件と表示され、中止ボタンがあります。ファイル一覧では src/units.ts に競合の印が付いています。右側では、2 枚のカードにそれぞれのブランチの units.ts のバージョンが表示され、そこから下向きの矢印が空の結果ボックスと「マージツールを選択」ボタンを指しています。]{name="conflict" frame="window" markers="24,18 47,55 76,37 76,73 84,86"}

1. バナーには、進行中の操作と、残っている競合の数が表示されます。
2. 競合のあるファイル。選択すると競合ウィザードが開きます。
3. ファイルの 2 つのバージョン。双方から 1 つずつです。
4. 結果：ファイルがどうなるかを示します。
5. ファイルを解決するボタン、またはマージツールを開くボタン。

## 進行中の操作 {#banner}

マージ、リベース、チェリーピック、リバートが進行している間は、作業コピーの上部にバナーが表示されます。

- タイトルは、何が進行しているかを示します。たとえば :ui[conflict.title.merge]{1="feature/units-toggle" 2="main"} です。
- その下に、未解決の競合の数が表示されます。操作が競合で止まると、解決済みのファイルの数がかっこ内に続きます。
- 短いヒントが、次にすることを示します。リベースや一連のコミットの処理中は、進行状況バーでいまのステップがわかります。
- :ui[working.onlyConflicts] は、ファイル一覧をこの競合のファイルだけに絞り込みます。解決済みのファイルも一覧に残ります。この選択は、すべてのリポジトリで記憶されます。
- :ui[working.abort] は操作を取りやめます。[続行または中止する](#continue) を参照してください。

すべての競合が解決されるまで、コミットエリアは表示されません。

## 競合ウィザードを使う {#wizard}

作業コピーで競合のあるファイルを選択します。右側に競合ウィザードが開き、:ui[conflict.version]{1="main"} のように、双方のカードが 1 枚ずつ表示されます。それぞれのカードには、ファイル、その側がファイルに対して行ったこと（たとえば :ui[conflict.change.modified]）、元になったコミットが表示されます。

片方を残すには、次のようにします。

1. そのカードをクリックします。結果ボックスにそのバージョンが表示されます。
2. :ui[conflict.resolveUsing]{1="main"} をクリックします。

Spooky はそのバージョンをファイルに書き込み、ステージします。ファイルは解決済みとして扱われます。その側がファイルを削除していた場合、ファイルは削除されます。

双方を組み合わせるには、両方のカードをクリックしてから、結果ボックスの下のボタンをクリックします。[ほかのアプリケーションでマージする](#merge-tool) で説明しているとおり、マージツールが開きます。

テキストエディタなどですでにファイルを自分で編集している場合、結果ボックスには :ui[conflict.result] と表示されます。ファイルをそのままの状態でステージするには、:ui[conflict.resolveCurrent] をクリックします。Spooky に戻ると、ウィザードはファイルを読み込み直します。

カードの「…」ボタンをクリックすると、そのバージョンのメニューが開きます。

- :ui[conflict.open]{1="main"}、またはほかのアプリケーションで開く
- :ui[conflict.export]{1="main"}
- :ui[conflict.compareOther]{1="feature/units-toggle"}
- :ui[conflict.compareBase]

## ほかのアプリケーションでマージする {#merge-tool}

マージツールは、2 つのバージョンを並べて表示し、変更を 1 行ずつ選べるようにします。一度に 1 つのファイルを扱い、双方にそのファイルがあるときに使えます。

1. 競合ウィザードで :ui[externalTool.chooseMergeTool] をクリックし、アプリケーションを選びます。2 回目からは、ボタンは :ui[externalTool.mergeIn]{1="FileMerge"} になります。
2. そのアプリケーションでファイルをマージし、結果を保存して、アプリケーションを終了します。

Spooky は結果をファイルに書き込み、解決済みにします。アプリケーションが結果を保存しなかった場合、Spooky は :ui[externalTool.noResult] と表示し、競合は残ります。

FileMerge は少し動作が異なります。FileMerge が開いている間、Spooky は :ui[externalTool.finishMerge]{1="FileMerge"} と表示します。FileMerge で結果を保存してから、:ui[externalTool.done] をクリックします。

Spooky は Araxis Merge、Beyond Compare、DeltaWalker、FileMerge、Kaleidoscope、P4Merge、Visual Studio Code に対応しています。アプリケーションを切り替えるには、:ui[app.name > settings.title] › :ui[settings.gitConfig] の :ui[externalTool.mergeTool] を変更します。同じ場所で :ui[externalTool.keepBackups] をオンにすると、マージ前のファイルが `src/units.ts.orig` のような名前で残ります。[比較ツールとマージツール](/guide/settings/integration/#diff-merge-tools) を参照してください。

マージしている間にファイルがほかの場所で変更された場合、Spooky は上書きする前に確認を求めます。

:::note[サーバーリポジトリ]
マージツールには、この Mac 上の一時フォルダにある各バージョンのコピーが渡されます。Spooky は結果をサーバーに書き戻してから、ファイルを解決済みにします。このフォルダは、リポジトリを閉じると削除されます。
:::

## そのほかの解決方法 {#other-ways}

競合のあるファイルを 1 つ以上選んで右クリックします。

- :ui[conflict.menu.resolve]
  - :ui[conflict.markResolved.one]{1="src/units.ts"} は、ファイルをいまの状態のままステージします。チェックボックスを選択しても同じです。
  - :ui[conflict.resolveUsingVersion]{1="main"} は、ウィザードと同じように片方を残します。
- :ui[conflict.menu.restore]
  - :ui[conflict.restoreUnmerged.one]{1="src/units.ts"} は、すでに解決したファイルであっても、競合を元に戻します。
  - :ui[conflict.restoreVersion]{1="main"} と :ui[conflict.restoreAncestor] は、1 つのバージョンをファイルに書き込みます。ファイルは未解決のままです。

:::caution
復元すると、作業コピーのファイルが確認なしで上書きされます。そのファイルに加えた編集は失われます。
:::

スタッシュやパッチの適用が競合で止まった場合は、続行または中止する操作がなく、バナーも表示されません。ウィザードでは、取り込まれる側が :ui[conflict.version.applied] と表示されます。ファイルを解決すると、その変更はほかの変更と同じように作業コピーに入ります。

## 続行または中止する {#continue}

すべての競合が解決されると、コミットエリアが再び表示され、Git がその操作のために用意したメッセージが入っています。

- **マージ、または 1 件のコミットのチェリーピックやリバート**：メッセージを確認し、:ui[working.commit] をクリックします。
- **リベース、または複数のコミットのチェリーピックやリバート**：メッセージを確認し、:ui[working.continue] をクリックします。Spooky はこのステップをコミットして次のステップに進みます。次のステップでまた競合で止まることもあります。
- **コミットを編集するために止まるリベースのステップ**：コミットを作成してから、バナーの :ui[working.endEditing] をクリックします。

すでにあったバージョンを残した場合など、コミットするものが何も残らないことがあります。その状態で :ui[working.commit] または :ui[working.continue] をクリックすると、Spooky は :ui[commit.empty.title] と尋ねます。空のコミットを作成するには、:ui[commit.empty.use] をクリックします。もう一方のボタンは、マージを中止するか、リベースや一連のコミットのそのステップをスキップします。リベースや一連のコミットでは、バナーの :ui[working.skip] をクリックすることもできます。

取りやめるには、バナーの :ui[working.abort] をクリックします。リポジトリは、操作を始める前の状態に戻ります。

:::caution
中止は確認なしですぐに実行され、取り消せません。解決した競合は失われます。
:::
