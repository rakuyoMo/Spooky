GitHub または GitLab のアカウントを追加すると、Spooky でプルリクエストとマージリクエストを扱えます。Git もそのサービスの HTTPS リモートへのサインインにアカウントを使うので、ユーザ名とパスワードを尋ねられません。

## アカウントを追加する {#add}

:ui[app.name > settings.title] を開いて、:ui[settings.accounts] をクリックします。一覧の下の追加ボタンをクリックして、アカウントのある場所を選びます。

| 選ぶ項目 | 対象 | サインインの方法 |
|---|---|---|
| :ui[accounts.add.github] | github.com | ブラウザ、またはパーソナルアクセストークン |
| :ui[accounts.add.gitlab] | GitLab.com | パーソナルアクセストークン |
| :ui[accounts.add.gitlabSelfManaged] | 自分のサーバ上の GitLab | パーソナルアクセストークン、またはユーザ名とパスワード |

::screenshot[セルフマネージドの GitLab アカウントを追加するシート。ホストは https://gitlab.example.com で、認証方法はユーザ名とパスワードです。]{name="hosting-add-account" frame="dialog" markers="79.2,61 83.3,52.6"}

1. ホスト
2. 認証方法

Spooky がアカウントを確認している間は、ダイアログの下端に :ui[accounts.validating] と表示されます。:ui[action.cancel] は確認を止めますが、ダイアログは開いたままなので、入力した内容を直せます。確認に失敗すると、メッセージが理由を知らせます。入力した内容はそのまま残ります。

各アカウントは、サービス、インスタンス、ユーザ名と一緒に一覧に表示されます。同じサービスに複数のアカウントを追加できます。

### GitHub {#github}

:ui[accounts.authentication] の横で :ui[accounts.authentication.oauth] を選んだ状態で、:ui[accounts.add.submit] をクリックします。

1. Spooky はワンタイムコードを表示してコピーし、ブラウザで GitHub を開きます。
2. そこにコードをペーストして、Spooky を承認します。その間にほかのものをコピーしていた場合は、:ui[accounts.copyCode] をクリックするともう一度コピーできます。
3. Spooky を承認すると、ダイアログが閉じて、アカウントが一覧に加わります。

コードの期限が切れた場合や、ブラウザでアクセスを拒否した場合は、最初からやり直して新しいコードを取得します。

代わりにトークンを使うには、:ui[accounts.authentication] の横で :ui[accounts.authentication.token] を選びます。トークンには `repo` と `read:org` のスコープが必要です。

### GitLab.com {#gitlab-com}

`api` スコープのあるパーソナルアクセストークンをペーストします。

### セルフマネージドの GitLab {#self-managed}

:ui[accounts.host] の横に、GitLab サーバのアドレスを入力します。ポートやパスがあれば、それも含めます。たとえば `https://example.com:8443/gitlab` です。そのあと、サインインの方法を選びます。

- :ui[accounts.authentication.token]：`api` スコープのあるトークン。
- :ui[accounts.authentication.password]：Spooky はパスワードをトークンの取得にだけ使い、パスワードは保存しません。

ユーザ名とパスワードでサインインできるのは、次のすべてが当てはまる場合だけです。

- サーバが GitLab 18.11 以前で動いている。GitLab 19.0 以降は、パスワードと引き換えにトークンを発行しなくなりました。
- サーバが OAuth アプリケーションの資格情報を必須にしていない。GitLab 13.9 は常に必須で、GitLab 17.8 以降は必須に設定できます。
- サーバが、パスワードを使った HTTPS 経由の Git を許可している。
- アカウントに GitLab または LDAP のパスワードがあり、2 要素認証を使っておらず、シングルサインオンでしかサインインできないアカウントでもない。

この方法で取得したトークンには期限があり、Spooky が自動で更新します。GitLab が更新に応じなくなると、アカウントには再認証が必要というマークが付きます。

Spooky には GitLab 9.0 以降が必要です。サーバは Mac から到達できなければならず、Mac がその証明書を信頼していなければなりません。信頼していない場合は、**キーチェーンアクセス**で証明書を信頼してください。

## アカウントを管理する {#manage}

すべてのウインドウが同じアカウントを共有します。:ui[app.name > settings.title] › :ui[settings.accounts] では、次のことができます。

- アカウントを再認証するには、選択して、一覧の下の :ui[accounts.reauthenticate] をクリックします。もう一度サインインするか、新しいトークンを入力します。同じユーザでなければなりません。別のユーザとしてサインインするには、新しいアカウントを追加します。
- アカウントを削除するには、選択して、一覧の下の削除ボタンをクリックし、確認します。Spooky はそのトークンをキーチェーンから削除します。

:ui[accounts.needsReauthentication] と表示されたアカウントは、サービスがもう受け付けないトークンを持っています。期限切れや取り消しなどが理由です。もう一度使うには、再認証します。

Spooky は変更をすぐに反映します。開いているプルリクエストやマージリクエストの一覧は、ウインドウを開き直さなくても読み込み直されます。

## アカウントの使いみち {#uses}

アカウントは、そのサービス上のリモートで働きます。

- [プルリクエストとマージリクエスト](/guide/hosting/pull-requests/) の一覧
- コミットメッセージの `#` に続く Issue 番号。[自動補完](/guide/work/commit/#autocomplete) を参照してください。
- [ブランチの整理](/guide/branches/review/) でのプルリクエストとマージリクエストの状態
- サービスへの [リポジトリの公開](#publish)
- [HTTPS リモートへのサインイン](#git)

## リモートが使うアカウント {#remotes}

Spooky は、各リモートのアドレスを各アカウントのインスタンスと照合します。インスタンスは github.com、GitLab.com、自分の GitLab サーバのどれかです。

- **そのインスタンスにアカウントが 1 つ**：Spooky はそれを使います。
- **そのインスタンスにアカウントが複数**：プルリクエストの一覧が、どれを使うかを尋ねます。Spooky はそのリモートでの選択を覚えています。
- **アカウントがまだない**：github.com と GitLab.com では、一覧がそのことを知らせて、:ui[pullRequests.openAccounts] を表示します。
- **アドレスが一致しない**：たとえば、リモートが `~/.ssh/config` のホストエイリアスを使っている場合です。一覧には :ui[pullRequests.associate] ボタンの付いたメモが表示されます。リモートが自分のアカウントのどれかに属している場合は、ボタンをクリックして、アカウントとプロジェクトを選びます。

同じプロジェクトの HTTPS アドレスと SSH アドレスは、同じアカウントに一致します。

## HTTPS リモートにサインインする {#git}

HTTPS リモートが自分のアカウントのどれかに属していると、Git はそのアカウントのトークンでサインインします。クローン、フェッチ、プル、プッシュ、自動フェッチが対象です。

- SSH リモートは、これまでどおり SSH 鍵を使います。アカウントはそれを変えません。
- これらのアドレスでは、macOS のキーチェーンヘルパーなど、Git に設定してある資格情報ヘルパーの代わりに Spooky が応答します。それらのヘルパーがトークンを見たり保存したりすることはありません。
- 同じインスタンスに複数のアカウントがあり、リモートで使うものをまだ選んでいない場合、Git は通常どおりユーザ名とパスワードを尋ねます。

Git がトークンを拒否すると、そのコマンドは失敗します。それ以降、Git はそのアカウントのリモートでユーザ名とパスワードを尋ね、ダイアログはアカウントのトークンが受け付けられなかったことを知らせます。トークンでのサインインに戻すには、アカウントを再認証します。

:::note[サーバリポジトリ]
サーバ上の Git もトークンでサインインします。トークンは、必要になるたびに Mac の Spooky から受け取ります。トークンはサーバに保存されません。
:::

## トークンの保存場所 {#storage}

- アカウントの一覧は Spooky の設定にあります。トークンは含まれません。
- トークンはキーチェーンにあります。項目の名前は `com.rakuyo.spooky.hosting.<address>` です。
- セルフマネージドの GitLab にユーザ名とパスワードでサインインした場合、Spooky は引き換えに受け取ったトークンを保管します。パスワードは保管しません。

トークンが :ui[activity.title] の記録や Spooky のログに入ることはありません。

## リクエストの送り先 {#network}

Spooky は、サーバリポジトリの場合でも、Mac からサービスとやり取りします。

- GitHub：ブラウザで承認している間は `github.com`、それ以外はすべて `api.github.com`。
- GitLab：`gitlab.com`、または自分の GitLab のアドレス。

やり取りするのは、アカウントを追加または再認証するときと、アカウントの使いみちにあたる機能を使うときです。プルリクエストとマージリクエストの一覧とそこでの操作、`#` に続く Issue 番号、ブランチの整理での状態、リポジトリの公開です。ユーザ名とパスワードでサインインしたアカウントは、トークンの更新もそこで行います。

これらのリクエストは、どれも :ui[activity.title] ウインドウの :ui[activity.service] ページに表示されます。

GitHub と GitLab のユーザの画像は、それらのサービスが示すアドレスから取得します。ダウンロードした画像はメモリにだけ置かれ、Spooky を終了すると消えます。

Git 自体は、リポジトリのある場所からリモートに接続します。サーバリポジトリでは、それはサーバです。[データとプライバシー](/reference/data-privacy/#network) を参照してください。

## リポジトリを公開する {#publish}

開いているリポジトリから GitHub または GitLab にリポジトリを作成するには、メニューバーで :ui[menu.repository > publish.menu] を選びます。サイドバーで :ui[workspace.title] を右クリックしてメニューから :ui[workspace.publishMenu] を選ぶこともできます。リポジトリにまだリモートがない場合は、:ui[sync.push] もこのダイアログを開きます。アカウントが 1 つ以上必要です。

| フィールド | 働き |
|---|---|
| :ui[publish.remote] | 新しいリモートの名前。最初は `origin` です。リポジトリにすでに `origin` があれば `origin-2` です。 |
| :ui[pullRequests.account] | リポジトリを作成する場所。自分のユーザの下か、所属している組織またはグループの下です。 |
| :ui[publish.name] | サービス上の名前。最初はリポジトリのフォルダの名前です。 |
| :ui[pullRequests.description] | 省略できます |
| :ui[publish.visibility] | :ui[publish.visibility.private] または :ui[publish.visibility.public]。GitLab には :ui[publish.visibility.internal] もあります。 |
| :ui[publish.target] | リモートが使う HTTPS アドレス |

:ui[publish.submit] をクリックすると、Spooky は次のことを行います。

1. サービス上に空のリポジトリを作成します。
2. それを HTTPS アドレスでリモートとして追加します。
3. すべてのローカルブランチとタグをそこへプッシュします。上流のないブランチは、新しいリモートブランチの追跡を始めます。すでに上流のあるブランチは、そのままです。

その名前のリポジトリがすでにある場合、Spooky はそのことを知らせ、上書きしません。別の名前を選んでください。プッシュに失敗しても、新しいリモートとサービス上のリポジトリはどちらも残るので、もう一度プッシュできます。

公開は <kbd>⌘Z</kbd> で取り消せません。それより前の操作も取り消せなくなります。
