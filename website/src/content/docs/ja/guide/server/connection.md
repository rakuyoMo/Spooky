サーバリポジトリは SSH 接続に頼っています。このページでは、接続されているかどうかの見分け方、サーバからの質問の意味、接続が切れたときに起きることを説明します。

## 接続状態 {#status}

サーバリポジトリでは、各一覧の上部の帯に、ホストエイリアスと接続状態が表示されます。帯があるのは、作業コピー、履歴、スタッシュ、Reflog、ファイル履歴、コミットのファイル一覧です。

| 状態 | 意味 |
|---|---|
| :ui[connection.connecting] | Spooky が接続を開いています。 |
| :ui[connection.connected] | 接続は正常です。 |
| :ui[connection.reconnecting] | 接続が切れ、Spooky がもう一度試しています。 |
| :ui[connection.unavailable] | 直前の試行が失敗しました。Spooky は 5 秒後にもう一度試します。 |

リポジトリが接続されていない間、帯は黄色になり、次の内容も表示されます。

- Spooky が最後に取得した状態を表示していて、接続が復旧するまで書き込みは無効だという説明。
- :ui[remoteError.unavailable] などの理由。クリックすると、SSH の元の出力が表示されます。
- :ui[action.reconnect] ボタン。状態が :ui[connection.unavailable] の間に表示されます。

::screenshot[接続が切れたサーバリポジトリの作業コピーの上部。帯には「spooky-test: 利用不可」と表示され、「再接続」ボタンがあります。その下に、Spooky が最後に取得した状態を表示していて、接続が復旧するまで書き込みは無効だという説明があります。折りたたまれた行には、サーバ接続を利用できないと書かれています。]{name="server-unavailable" frame="closeup"}

## パスワードとパスフレーズの入力 {#prompts}

Spooky は何も尋ねずにサーバにログインします。ただし、サーバの Git が答えを必要とすることがあります。たとえば、HTTPS でリモートにプッシュするときのパスワードです。Spooky は質問を Mac に渡し、ダイアログで表示します。

| ダイアログ | 表示されるとき |
|---|---|
| :ui[callback.username.title]、:ui[callback.password.title] | リモートがユーザの確認を求めています。HTTPS でアクセスするリモートでよく起こります。 |
| :ui[callback.privateKey.title] | サーバがリモートに使う SSH 鍵が、パスフレーズで保護されています。 |
| :ui[signing.unlock] | コミットまたはタグに署名するために、Git がサーバの署名鍵のパスフレーズを必要としています。 |
| :ui[callback.editor] | メッセージなどのテキストを編集するよう、Git が求めています。 |

ダイアログの最初の行に、サーバの名前が表示されます。秘密鍵のダイアログには、サーバ上の鍵のパスも表示されます。

ユーザ名またはパスワードの場合、:ui[callback.saveKeychain] を選択すると答えが保存されます。そのサーバの Git が次に尋ねたときは、Spooky がキーチェーンから答えます。GitHub または GitLab のアカウントを追加している場合は、Spooky がまずそのアカウントで答えます。[ホスティングアカウント](/guide/hosting/accounts/) を参照してください。

知っておくとよい点がいくつかあります。

- 各ダイアログは 2 分間待ちます。時間内に答えないと、Git は答えを受け取れず、コマンドは失敗します。
- 自動フェッチが尋ねることはありません。アカウントと、キーチェーンに保存した答えだけを使います。それで足りないときは、キャンセルされます。
- サーバの Git のパスフレーズのダイアログには、サーバに OpenSSH 8.4 以降が必要です。

## 切断と再接続 {#reconnect}

接続が切れると、Spooky が自動的に再接続します。試行が失敗するたびに、状態は :ui[connection.unavailable] になります。Spooky は 5 秒後にもう一度試します。すぐに試すには、:ui[action.reconnect] をクリックします。接続が戻ると、Spooky はリポジトリを読み込み直します。

切断のあと、行った変更が繰り返されることはありません。

- リポジトリのキューで待っていた操作はキャンセルされます。再接続後に実行されることはありません。まだ必要なら、もう一度始めてください。
- 接続が切れたときに実行中だった操作は、再試行されません。再接続後、Spooky はブランチ、変更の数、インデックスのロック、マージまたはリベースが進行中かどうかを確認します。

確認の結果は :ui[recovery.title] ダイアログに表示されます。操作がそもそも始まっていたか、現在のコミットが動いたかがわかります。操作をもう一度試す前に、結果を見てください。

## 切断中 {#offline}

Spooky が最後に読み込んだ内容は、引き続き見られます。一覧、選択したファイル、その変更です。リポジトリを変更する操作は、接続が戻るまで使えません。

リポジトリを開くときにサーバにアクセスできないと、ウインドウに :ui[missing.unreachable.title]{1="driftwood-server"} と SSH の出力が表示されます。:ui[action.refresh] をクリックするともう一度試し、:ui[action.close] をクリックするとリポジトリウインドウに戻ります。

:::tip
ターミナルで `ssh -o BatchMode=yes driftwood-server git --version` を、自分のホストエイリアスに置き換えて実行します。失敗するなら、問題は Spooky ではなく、Mac とサーバの間にあります。[Spooky と同じ方法で接続を試す](/guide/server/prepare-ssh/#test) を参照してください。
:::
