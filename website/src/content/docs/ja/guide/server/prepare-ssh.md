---

Spooky は、ターミナルと同じように SSH でサーバーにログインします。Spooky が代わりにパスワードを入力することはできないので、SSH 鍵が必要です。このページでは、鍵とサーバーの短い名前を設定し、ターミナルが何も尋ねずに接続できることを確認します。それができれば、Spooky も接続できます。

`ssh` がすでにパスワードなしでサーバーにログインできるなら、[Spooky と同じ方法で接続を試す](#test) に進んでください。

## 必要なもの {#before}

- SSH でログインできるサーバーのアカウント。わからないときは、サーバーの管理者に尋ねてください。
- サーバー上の Git 2.41.0 以降。
- Mac の **ターミナル** アプリケーション。

このページのコマンドはターミナルに入力します。1 つずつ入力またはペーストして、Return キーを押します。

## 鍵があるか確認する {#key-check}

SSH 鍵は 2 つのファイルの組です。秘密鍵は Mac に置いたままにします。公開鍵は名前が `.pub` で終わり、サーバーに置きます。

```sh
ls ~/.ssh
```

一覧に `id_ed25519` と `id_ed25519.pub` があれば、鍵はすでにあります。[ホストエイリアスを追加する](#alias) に進んでください。`id_rsa` と `id_rsa.pub` のような別の組でもかまいません。以下の手順では、`id_ed25519` の代わりにその名前を使ってください。

「No such file or directory」と表示されるか、一覧に鍵の組がないときは、鍵を作成します。

## 鍵を作成する {#create-key}

```sh
ssh-keygen -t ed25519 -C "alex@example.com"
```

引用符の中には自分のメールアドレスを入れます。鍵を見分けるためのラベルにすぎません。

1. 鍵の保存先を尋ねられたら、Return キーを押して、提示された場所のままにします。
2. パスフレーズを入力し、もう一度入力します。入力中は何も表示されません。パスフレーズは、誰かがファイルをコピーしたときに鍵を守ります。

終わると、`~/.ssh` に `id_ed25519` と `id_ed25519.pub` ができています。

## ホストエイリアスを追加する {#alias}

ホストエイリアスは、サーバーの短い名前です。ターミナルと Spooky で、サーバーのアドレスとユーザ名の代わりに入力します。エイリアスは `~/.ssh/config` ファイルに書きます。

1. テキストエディットでファイルを開きます。次のコマンドは、ファイルがまだなければ作成します。

   ```sh
   touch ~/.ssh/config && open -e ~/.ssh/config
   ```

2. 末尾に次の行を追加し、自分の情報に書き換えます。

   ```
   Host driftwood-server
       HostName 203.0.113.10
       User alex
       IdentityFile ~/.ssh/id_ed25519
       AddKeysToAgent yes
       UseKeychain yes
   ```

3. ファイルを保存して、テキストエディットを閉じます。

| 行 | 書く内容 |
|---|---|
| `Host` | エイリアス。スペース、`@`、`:`、`/` を含まない 1 語にし、先頭を `-` にしないでください。 |
| `HostName` | サーバーのアドレスまたは名前。`203.0.113.10` や `server.example.com` など |
| `User` | サーバーでのユーザ名 |
| `IdentityFile` | 上で作成した、または見つけた秘密鍵 |
| `AddKeysToAgent`、`UseKeychain` | パスフレーズを初めて入力したとき、Mac がキーチェーンに保存します。以降、SSH は尋ねずに鍵のロックを解除します。Spooky はこれに頼っています。ログイン時にパスフレーズを尋ねることがないためです。 |

サーバーの SSH が 22 以外のポートを使っているときは、`Port 2222` のような行を追加します。

## 一度接続する {#fingerprint}

サーバーに初めて接続するとき、SSH はサーバーのフィンガープリントの確認を求めます。Spooky が代わりにフィンガープリントを受け入れることはないので、先にターミナルで済ませておきます。

```sh
ssh driftwood-server
```

1. SSH がサーバーのフィンガープリントを表示します。`SHA256:` で始まる行です。続けるかどうかを尋ねられます。
2. サーバーの管理者から受け取ったフィンガープリントと比べます。サーバー上では、次のコマンドで表示できます。

   ```sh
   ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
   ```

3. 一致していれば、`yes` と入力して Return キーを押します。Mac がサーバーを覚え、次からは尋ねません。

このあとどうなるかは、サーバーによって変わります。

- SSH が鍵のパスフレーズを尋ねたら、入力します。Mac がキーチェーンに保存します。
- ログインできたら、鍵はすでにサーバーにあります。`exit` と入力して、[Spooky と同じ方法で接続を試す](#test) に進んでください。
- SSH がサーバーのパスワードを尋ねたら、ひとまず <kbd>⌃C</kbd> を押します。次の手順で、鍵をサーバーに置きます。

:::caution
リモートホストの識別情報が変わったと SSH が警告したときは、続けないでください。サーバーが再インストールまたは交換されたかどうかを、サーバーの管理者に確認してください。
:::

## 公開鍵をサーバーに置く {#copy-key}

パスワードでサーバーにログインできるなら、次のコマンドで公開鍵をサーバーにコピーできます。尋ねられたら、サーバーのパスワードを入力します。

```sh
ssh-copy-id -i ~/.ssh/id_ed25519.pub driftwood-server
```

サーバーがパスワードを受け付けないときは、公開鍵をサーバーの管理者に送ります。次のコマンドでクリップボードにコピーできます。

```sh
pbcopy < ~/.ssh/id_ed25519.pub
```

サーバーのホームフォルダにある `~/.ssh/authorized_keys` に追加してもらってください。公開鍵は人に渡しても安全です。`.pub` の付かないファイルは決して送らないでください。

## Spooky と同じ方法で接続を試す {#test}

```sh
ssh -o BatchMode=yes driftwood-server git --version
```

Spooky と同じ方法で、何も尋ねずにログインします。`git version 2.47.1` のように、2.41.0 以降のバージョンがすぐに表示されれば成功です。これで [サーバーリポジトリを追加する](/guide/server/add/) 準備ができました。

ほかの内容が表示されたときは、次のようにします。

| 表示される内容 | 対処 |
|---|---|
| `Permission denied` | サーバーがまだ鍵を受け付けていないか、Mac が鍵のロックを解除できません。[公開鍵をサーバーに置く](#copy-key) と [Mac を再起動したあと](#after-restart) を確認してください。 |
| `Host key verification failed` | Mac がまだサーバーを知りません。[一度接続する](#fingerprint) を参照してください。 |
| `Could not resolve hostname`、`Connection refused`、`Operation timed out` | `~/.ssh/config` の `HostName` と `Port` を確認し、サーバーが起動していてアクセスできることを確かめてください。 |
| `command not found` を含むメッセージ | サーバーに Git がインストールされていないか、SSH でログインしたときに見つかりません。サーバーの管理者に尋ねてください。 |
| 2.41.0 より古いバージョン | サーバーの管理者に Git のアップデートを依頼してください。 |

## Mac を再起動したあと {#after-restart}

以前は成功したのに、再起動後に `Permission denied` で失敗するときは、鍵を読み込み直します。パスフレーズをキーチェーンに保存してある鍵は、次のコマンドで読み込めます。

```sh
ssh-add --apple-load-keychain
```

## 別の SSH エージェントを使う {#agent}

SSH エージェントは、ロックを解除した鍵を SSH のために保持します。Spooky はシステムのエージェント、つまり macOS が起動するエージェントを使います。鍵が別のエージェント（パスワードマネージャに付属するものなど）にあるときは、`SSH_AUTH_SOCK` にそのエージェントのソケットを設定します。:ui[app.name > settings.title] › :ui[settings.environment] でカスタム変数として追加するか、ログインシェルで設定します。Spooky はそのエージェントを使ってサーバーにログインします。[SSH エージェント](/guide/settings/integration/#ssh-agent) を参照してください。

## Mac をサーバーとして使う {#mac-server}

別の Mac をサーバーにできます。その Mac で次のようにします。

1. **アップルメニュー › システム設定** と選択し、**一般** をクリックしてから、**共有** をクリックします。
2. **リモートログイン** をオンにします。
3. リポジトリが「書類」や「デスクトップ」などの保護されたフォルダにあるときは、**リモートログイン** の横の情報ボタンをクリックして、**リモートユーザのフルディスクアクセスを許可** をオンにします。

そのあと、自分の Mac からこのページの手順を進めます。`HostName` にはその Mac のアドレスを書きます。
