title: "SSH を準備する"
description: "サーバリポジトリを追加する前に、SSH 鍵と ~/.ssh/config のホストエイリアスを設定し、ターミナルから接続できることを確認します。"
---

Spooky は、ターミナルと同じように SSH でサーバにログインします。Spooky が代わりにパスワードを入力することはできないので、SSH 鍵が必要です。このページでは、鍵とサーバの短い名前を設定し、ターミナルが何も尋ねずに接続できることを確認します。それができれば、Spooky も接続できます。

`ssh` がすでにパスワードなしでサーバにログインできるなら、[Spooky と同じ方法で接続を試す](#test) に進んでください。

## 必要なもの {#before}

- SSH でログインできるサーバのアカウント。わからないときは、サーバの管理者に尋ねてください。
- サーバ上の Git 2.41.0 以降。
- Mac の **ターミナル** アプリケーション。

このページのコマンドはターミナルに入力します。1 つずつ入力またはペーストして、Return キーを押します。

## 鍵があるか確認する {#key-check}

SSH 鍵は 2 つのファイルの組です。秘密鍵は Mac に置いたままにします。公開鍵は名前が `.pub` で終わり、サーバに置きます。

```sh
ls ~/.ssh
```

一覧に `id_ed25519` と `id_ed25519.pub` があれば、鍵はすでにあります。[ホストエイリアスを追加する](#alias) に進んでください。`id_rsa` と `id_rsa.pub` のような別の組でもかまいません。以下の手順では、`id_ed25519` の代わりにその名前を使ってください。

「No such file or directory」と表示されるか、一覧に鍵の組がないときは、鍵を作成します。

## 鍵を作成する {#create-key}

```sh
ssh-keygen -t ed25519 -C "alex@example.com"
```

引用符の中には自分のメールアドレスを入れます。鍵を見分けるためのラベルにすぎません。

1. 鍵の保存先を尋ねられたら、Return キーを押して、提示された場所のままにします。
2. パスフレーズを入力し、もう一度入力します。入力中は何も表示されません。パスフレーズは、誰かがファイルをコピーしたときに鍵を守ります。

終わると、`~/.ssh` に `id_ed25519` と `id_ed25519.pub` ができています。

## ホストエイリアスを追加する {#alias}

ホストエイリアスは、サーバの短い名前です。ターミナルと Spooky で、サーバのアドレスとユーザ名の代わりに入力します。エイリアスは `~/.ssh/config` ファイルに保存されます。追加は Spooky の設定で行います。

1. :ui[app.name > settings.title] › :ui[settings.sshHosts] を選びます。
2. 一覧の下の追加ボタンをクリックします。
3. 各フィールドに自分の情報を入力します。
4. :ui[sshHosts.create.submit] をクリックします。

::screenshot[ホストエイリアスを追加するダイアログ。エイリアスは driftwood-server、サーバのアドレスは 203.0.113.10、ユーザ名は alex、ポートは空欄、秘密鍵は ~/.ssh/id_ed25519 です。ボタンは「キャンセル」と「追加」です。]{name="settings-ssh-hosts-add" frame="dialog"}

| フィールド | 入力する内容 |
|---|---|
| :ui[sshHosts.alias] | エイリアス。スペース、`@`、`:`、`/`、`*`、`?` を含まない 1 語にし、先頭を `-` や `!` にしないでください。 |
| :ui[sshHosts.hostName] | サーバのアドレスまたは名前。`203.0.113.10` や `server.example.com` など |
| :ui[sshHosts.user] | サーバでのユーザ名 |
| :ui[sshHosts.port] | ポート。サーバの SSH が 22 以外のポートを使っているときだけ入力します |
| :ui[sshHosts.identityFile] | 上で作成した、または見つけた秘密鍵。`~/.ssh/id_ed25519` など |

必須なのは :ui[sshHosts.alias] だけです。Spooky は、エイリアスと入力したフィールドを `~/.ssh/config` に書き込みます。

```
Host driftwood-server
    HostName 203.0.113.10
    User alex
    IdentityFile ~/.ssh/id_ed25519
```

`Host *` のようにパターンを使うエントリや `Match` のエントリがあるときは、新しい行はその最初のエントリの上に入ります。そのエントリに上書きされないようにするためです。そうしたエントリがなければ、ファイルの末尾に入ります。

### エイリアスを変更または削除する {#manage-aliases}

:ui[settings.sshHosts] ページには、`~/.ssh/config` にあるエイリアスが並びます。テキストエディタで追加したものも含まれます。

::screenshot[設定ウインドウの SSH ホストページ。一覧には、エイリアス、サーバのアドレス、ユーザ名、ポート、秘密鍵の列があります。staging、backup-nas、driftwood-server の 3 つのエイリアスが並び、driftwood-server が選択されています。一覧の下に追加ボタンと削除ボタン、右側に「編集…」ボタンがあります。]{name="settings-ssh-hosts" frame="window"}

- エイリアスを変更するには、ダブルクリックするか、選択してから :ui[sshHosts.edit] をクリックするか <kbd>Return</kbd> を押します。Spooky は、編集したフィールドの行だけを書き換えます。そのサーバのほかの SSH オプション、ほかのサーバ、コメントはそのまま残ります。
- エイリアスを削除するには、選択して一覧の下の削除ボタンをクリックし、確認します。Spooky は、その `Host` の行と、その下のオプションを削除します。

複数の名前を持つエントリや、`Host *` のようにパターンを使うエントリは一覧に表示されず、Spooky が変更することもありません。これらはテキストエディタで編集してください。

Spooky に戻るたびに、Spooky はこのファイルを読み込み直します。ダイアログを開いている間にほかのアプリケーションがファイルを変更した場合、Spooky は変更を保存しません。一覧がファイルの現在の内容に切り替わるので、もう一度変更してください。

## Mac が鍵のロックを解除できるようにする {#keychain}

Spooky はログイン時に鍵のパスフレーズを尋ねないため、Mac が代わりに鍵のロックを解除する必要があります。`~/.ssh/config` に 2 行追加すると、すべてのサーバで有効になります。鍵にパスフレーズがなければ、この手順は不要です。

1. テキストエディットでファイルを開きます。

   ```sh
   open -e ~/.ssh/config
   ```

2. 末尾に次の行を追加します。

   ```
   Host *
       AddKeysToAgent yes
       UseKeychain yes
   ```

3. ファイルを保存して、テキストエディットを閉じます。

パスフレーズを初めて入力したとき、Mac がキーチェーンに保存します。以降、SSH は尋ねずに鍵のロックを解除します。

## 一度接続する {#fingerprint}

サーバに初めて接続するとき、SSH はサーバのフィンガープリントの確認を求めます。Spooky が代わりにフィンガープリントを受け入れることはないので、先にターミナルで済ませておきます。

```sh
ssh driftwood-server
```

1. SSH がサーバのフィンガープリントを表示します。`SHA256:` で始まる行です。続けるかどうかを尋ねられます。
2. サーバの管理者から受け取ったフィンガープリントと比べます。サーバ上では、次のコマンドで表示できます。

   ```sh
   ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
   ```

3. 一致していれば、`yes` と入力して Return キーを押します。Mac がサーバを覚え、次からは尋ねません。

このあとどうなるかは、サーバによって変わります。

- SSH が鍵のパスフレーズを尋ねたら、入力します。Mac がキーチェーンに保存します。
- ログインできたら、鍵はすでにサーバにあります。`exit` と入力して、[Spooky と同じ方法で接続を試す](#test) に進んでください。
- SSH がサーバのパスワードを尋ねたら、ひとまず <kbd>⌃C</kbd> を押します。次の手順で、鍵をサーバに置きます。

:::caution
リモートホストの識別情報が変わったと SSH が警告したときは、続けないでください。サーバが再インストールまたは交換されたかどうかを、サーバの管理者に確認してください。
:::

## 公開鍵をサーバに置く {#copy-key}

パスワードでサーバにログインできるなら、次のコマンドで公開鍵をサーバにコピーできます。尋ねられたら、サーバのパスワードを入力します。

```sh
ssh-copy-id -i ~/.ssh/id_ed25519.pub driftwood-server
```

サーバがパスワードを受け付けないときは、公開鍵をサーバの管理者に送ります。次のコマンドでクリップボードにコピーできます。

```sh
pbcopy < ~/.ssh/id_ed25519.pub
```

サーバのホームフォルダにある `~/.ssh/authorized_keys` に追加してもらってください。公開鍵は人に渡しても安全です。`.pub` の付かないファイルは決して送らないでください。

## Spooky と同じ方法で接続を試す {#test}

```sh
ssh -o BatchMode=yes driftwood-server git --version
```

Spooky と同じ方法で、何も尋ねずにログインします。`git version 2.47.1` のように、2.41.0 以降のバージョンがすぐに表示されれば成功です。これで [サーバリポジトリを追加する](/guide/server/add/) 準備ができました。

ほかの内容が表示されたときは、次のようにします。

| 表示される内容 | 対処 |
|---|---|
| `Permission denied` | サーバがまだ鍵を受け付けていないか、Mac が鍵のロックを解除できません。[Mac が鍵のロックを解除できるようにする](#keychain)、[公開鍵をサーバに置く](#copy-key)、[Mac を再起動したあと](#after-restart) を確認してください。 |
| `Host key verification failed` | Mac がまだサーバを知りません。[一度接続する](#fingerprint) を参照してください。 |
| `Could not resolve hostname`、`Connection refused`、`Operation timed out` | :ui[app.name > settings.title] › :ui[settings.sshHosts] でエイリアスの :ui[sshHosts.hostName] と :ui[sshHosts.port] を確認し、サーバが起動していてアクセスできることを確かめてください。 |
| `command not found` を含むメッセージ | サーバに Git がインストールされていないか、SSH でログインしたときに見つかりません。サーバの管理者に尋ねてください。 |
| 2.41.0 より古いバージョン | サーバの管理者に Git のアップデートを依頼してください。 |

## Mac を再起動したあと {#after-restart}

以前は成功したのに、再起動後に `Permission denied` で失敗するときは、鍵を読み込み直します。パスフレーズをキーチェーンに保存してある鍵は、次のコマンドで読み込めます。

```sh
ssh-add --apple-load-keychain
```

## 別の SSH エージェントを使う {#agent}

SSH エージェントは、ロックを解除した鍵を SSH のために保持します。Spooky はシステムのエージェント、つまり macOS が起動するエージェントを使います。鍵が別のエージェント（パスワードマネージャに付属するものなど）にあるときは、`SSH_AUTH_SOCK` にそのエージェントのソケットを設定します。:ui[app.name > settings.title] › :ui[settings.environment] でカスタム変数として追加するか、ログインシェルで設定します。Spooky はそのエージェントを使ってサーバにログインします。[SSH エージェント](/guide/settings/integration/#ssh-agent) を参照してください。

## Mac をサーバとして使う {#mac-server}

別の Mac をサーバにできます。その Mac で次のようにします。

1. **アップルメニュー › システム設定** と選択し、**一般** をクリックしてから、**共有** をクリックします。
2. **リモートログイン** をオンにします。
3. リポジトリが「書類」や「デスクトップ」などの保護されたフォルダにあるときは、**リモートログイン** の横の情報ボタンをクリックして、**リモートユーザのフルディスクアクセスを許可** をオンにします。

そのあと、自分の Mac からこのページの手順を進めます。:ui[sshHosts.hostName] にはその Mac のアドレスを入力します。
