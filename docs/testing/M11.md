# M11：历史与同步的对齐验收

M11 承接 [M10](M10.md)，在本机与服务器仓库上修正以下行为，M1–M10 的验收步骤继续适用：

- 历史列表头去掉领先与落后的数字；历史不限总条数，一直续载到根提交；回到排在第 10,000 个之后的提交先询问，询问时还没切换，取消后什么都不变
- 整页提交详情的短哈希改成按钮，点开版本选择器；选择器的搜索框是系统搜索框，↑ ↓ 移动高亮，Esc 关闭，高亮行在搜索框有焦点时也是强调色底、白字
- 历史搜索与版本选择器的说明、作者与提交人条件按 Git 的正则匹配、忽略大小写，写法跟随仓库生效的 `grep.patternType` 与 `grep.extendedRegexp`，没有配置时是基本正则；编译不了的正则列表为空，不报错；配了 Perl 正则而 Git 不支持时照 Git 原文报错
- Quick Save Patch 不询问保存位置，直接存进仓库根目录；仓库配了 `format.coverLetter` 时，两种保存都在补丁旁边另写 `0000-cover-letter.patch`，补丁标题随之编号，补丁文件里不混进封面信；两种保存结束后 Finder 来到前台，选中写出的文件，服务器仓库的快速保存写在服务器上，不打开 Finder；两种保存在 Activity 的 Repository 页每个提交记一条 Format Patch，取消后不再执行后面的提交
- 分支整理去掉完全合并的标记与筛选，归档建议只看陈旧与请求已合并，原因写 Stale 或 Merged；`trunk` 也是基准分支；Branches Review 默认按 `next`、`develop`、`dev`、`main`、`master` 取基准，历史比较没有父分支时按基准名单取，再取引用名排第一的其它分支
- HEAD 没有上游时 Push 打开 Publish Branch；App 在后台也自动获取；Publish Repository 推送全部本地分支与标签，没有分支与标签的仓库也推送，失败照常报错
- 操作对话框的仓库位置只在服务器仓库显示
- Activity 分 Remote、Repository、Service 三页，Remote 页的记录存在本机；输出不截断；分页、Clear All 与搜索框放进工具栏，分段每段宽度随文字，窗口窄时整组移进工具栏右边的 » 菜单；Service 页记下每一次托管服务请求，读取也记；Repository 页另记打开、手动刷新、回到前台与写入之后的读取，以及历史的分页、工作区 Diff、文件历史与 Blame，每条写耗时，分支、远端、储藏与子模块写出与上一次记录相比的增减，文件变化与服务器轮询引起的自动刷新不记；侧边栏底部只列本仓库本次运行里的远程操作

M11 新增与修改的自动测试覆盖：

- 历史：提交在历史里的位置与分页的顺序一致，包括只沿第一父与路径带空格、中文的文件条件；位置输出的解析，包括空输出与格式错误；10,050 个提交的仓库里，回到很靠后的提交先核对位置再询问：询问期间与取消后，视图、所选的引用、搜索条件、列表与选中的提交都不变，经链接、后退与前进时窗口的位置与记录也不变；同意后才切换，续载到它、选中它并读出变更，询问之后列表从第一页重读也不丢选择；核对期间又回到别的提交时只询问后一个；已加载在全部历史里的提交直接回到；一直续载到根提交；说明、作者与提交人没有配置时按基本正则匹配，写法跟随 `grep.patternType` 与 `grep.extendedRegexp`，几种配置下的列表都与直接执行 `git log` 相同、计数与列表一致；Git 支持时按 Perl 正则匹配，不支持时照原文报错；编译不了的正则列表为空、计数为 0、没有位置，不报错，能否编译的判断与 Git 相同
- 版本选择器：第一页高亮 HEAD，续载到底，按提交说明搜索，清空后保留高亮；↑ ↓ 移动高亮，到两端停住；按正则搜索，编译不了时列表为空、没有失败
- 补丁：快速保存写进仓库根目录，路径带空格、中文、引号与通配符；配了 `format.suffix` 时仍写 `.patch`；`format.coverLetter` 为 `true` 时两种保存都另写 `0000-cover-letter.patch`，存两个提交时封面信只返回一次、是较新的提交生成的，补丁标题随之编号、文件里只有一封邮件，两种保存写出的补丁逐字节相同；为 `auto` 或没配时没有封面信，补丁与 Git 只输出这一个提交时逐字节相同；两种保存把每个提交那一次 `format-patch` 交给调用方包住，按传入顺序各一次，合并提交不经过，闭包抛错或任务取消后后面的提交不再执行，已写好的补丁保留；快速保存两个提交在 Repository 页记两条写耗时的 Format Patch，没有整次的 Save Patch，第一个提交执行中取消时只有它记为 Cancelled，后面的提交不执行，也不打开 Finder、不提示失败
- 分支整理：跟踪错误与父分支基准；基准名单的顺序，`trunk` 不陈旧、不进归档建议；Branches Review 与历史比较的默认基准；归档建议只列陈旧与请求已合并的分支；请求状态的筛选
- 同步：推送全部本地分支与标签，只给没有上游的分支设上游；没有分支与标签时照样推送，失败的退出码与 Git 原文不变；HEAD 没有上游时 Push 改开 Publish Branch；自动获取按窗口是否显示仓库
- Activity：各动作记在哪一页；Repository 页的 100 条上限；Remote 记录的保存、读回与 7 天过期，读回的记录带标记；输出不截断，回车覆盖当前行；托管服务请求的记录：成功、失败、取消，以及不属于仓库的请求；读取的记录：成功、失败、取消与被取代，一次读取按类各记一条，结果与错误照常交给调用方；分支、远端、储藏与子模块的清单与增减计数，没有基准时全算新增，各仓库、各类的基准分开；引用快照按远端给出设置的摘要，名字含点与中文，只改一个远端的设置只换它的摘要；完整刷新记下的各读取与一行结果，选中文件读一侧的 Diff 记一条，不记录的刷新不新增记录、不动基准，随之换了暂存侧的 Diff 不再读第二次，同一仓库的两个会话共用基准；文件历史与 Blame 的第一页、总数、补丁、原文与逐行追溯各记一条，HEAD 移动引起的重读跟随引起它的刷新决定记不记，按版本范围筛选时不读总数；Repository 页的行写耗时与一行结果，Remote 页的行写时刻；工具栏的排布；分段每段宽度随文字，» 菜单里的子项与分段同名同提示，从分段与从子项换页时分段都选中当前页；当前页的过滤与 Clear All，没有仓库的记录只按日志搜索

`SPOOKY_REMOTE_TESTS=1` 开启的服务器测试里，快速保存的补丁写在 B 上的仓库根目录，A 上没有这个文件。`SPOOKY_PERFORMANCE_TESTS=1` 的性能测试把 6 万个提交的历史逐页读到根提交，命令见 [测试](README.md) 的 “性能”。

```sh
m11_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m11.XXXXXXXX")"
```

很长的历史用 `git fast-import` 生成，本机与服务器共用：

```sh
# 一条线上的 10,050 个提交，第 n 个的说明是 “Commit n”；根提交另有只在这里出现的 root.txt
m11_history() {
    awk 'BEGIN {
        for (i = 1; i <= 10050; i++) {
            printf "commit refs/heads/main\nmark :%d\n", i
            printf "committer Spooky Test <spooky@example.invalid> %d +0000\n", 1790000000 + i
            printf "data %d\nCommit %d\n", length("Commit " i) + 1, i

            if (i > 1) printf "from :%d\n", i - 1
            if (i == 1) printf "M 100644 inline root.txt\ndata 5\nroot\n"

            printf "M 100644 inline history.txt\ndata %d\n%d\n", length(i "") + 1, i
        }
    }'
}
```

测试仓库：


## 历史

打开 `本机 分支`，在侧边栏选 `main`。

1. 列表头写 “main › origin/main”，后面没有领先与落后的数字；`Local commit` 一行行尾是未推送的箭头，`Commit from other clone` 一行是未拉取的箭头。侧边栏 `main` 的 ↑1 ↓1 不变。

打开 `本机 历史`，选 History。

2. 窗口副标题写 10,050 Commits。滚到列表底部：每次续载 1,000 个，一直到 `Commit 1`，列表下方没有加载上限的提示。
3. 在侧边栏点一下 `main`，列表回到第一页。右键 Tags 里的 `v500` → Reveal in History：不询问，列表续载到 `Commit 9551` 并选中它，右侧是它的变更。
4. 再点一下 `main`，选中列表第二行，右键 `v0` → Reveal in History：弹出 Load More Commits，写明这个提交排在这段历史的前 10,000 个提交之后，载入可能要一会儿。点 Cancel：侧边栏仍选中 `main`，列表停在第一页，第二行仍然选中，没有说明。
5. 再右键 `v0` → Reveal in History，点 Load More Commits：列表续载到 `Commit 1` 并选中它，右侧列出新增的 `history.txt` 与 `root.txt`。
6. 从文件历史回到它：点一下 `main`，选中任一提交，详情切到 Tree，右键 `root.txt` → Show File History of “root.txt”，时间线只有 `Commit 1`。双击它：弹出同样的询问，窗口仍停在文件历史；点 Cancel 后不变。再双击一次，点 Load More Commits：切到 History 并打开 `Commit 1` 的整页详情；再点 Back to History，列表已续载到 `Commit 1` 并选中它。
7. 经链接回到它：点一下 `main`，切到 Working Copy，在终端执行 `open "spooky://open?repository=$(python3 -c 'import urllib.parse,sys; print(urllib.parse.quote(sys.argv[1]))' "$m11_long")&commit=$(git -C "$m11_long" rev-parse v0)"`：弹出同样的询问，窗口仍是 Working Copy；点 Cancel 后视图不变，工具栏的后退与前进按钮与之前相同。再执行一次，点 Load More Commits：切到 History 并打开 `Commit 1` 的整页详情；再点 Back to History，列表已续载到 `Commit 1` 并选中它。
8. 点一下 `main`，按 ⌘F，在搜索框（Search for Message）输入 `commit 99.9`：按正则只剩 `Commit 9999`、`Commit 9989`…`Commit 9909`，窗口副标题写 10 Commits。改成 `x[`：列表写 No commits，副标题写 0 Commits，没有错误提示。清空搜索框，在终端执行 `git -C "$m11_long" config grep.patternType extended`，再搜 `commit 9999|commit 9998`：按扩展正则只剩 `Commit 9999` 与 `Commit 9998`，副标题写 2 Commits。清空搜索框，执行 `git -C "$m11_long" config --unset grep.patternType` 后再搜同样的内容：列表为空。清空搜索框。

## 整页提交详情

在 `本机 历史` 的列表里双击任一提交。

1. 提交卡片下方的短哈希是等宽字体的按钮。点它弹出版本选择器：上面是搜索框，左边是放大镜，占位写 Search，没有焦点环，光标已在框里；下面每行是头像、作者、短哈希、标题与日期。高亮的是 HEAD 的 `Commit 10050`，不是当前提交，强调色底、白字。
2. 按 ↓ 两次：高亮移到第三行，光标仍在搜索框里；一直按 ↓，列表随高亮滚动；回到第一行后再按 ↑ 不动。单击另一行只移动高亮，光标仍在搜索框里；按回车也不换，整页详情仍是原来的提交。按 Esc：选择器关闭，整页详情不变。再点短哈希，双击一行：选择器关闭，整页详情换成那个提交。
3. 搜索框输入 `commit 999`：只剩 `Commit 9999`…`Commit 9990` 与 `Commit 999`，高亮第一行，右边出现清除按钮。改成 `commit 99.9`：按正则只剩 `Commit 9999`、`Commit 9989`…`Commit 9909` 这 10 个。改成 `x[`：列表为空，没有错误提示。点清除按钮后回到全部提交，滚到底一直续载。

## 补丁

回到 `本机 分支` 的历史，仓库配着 `format.coverLetter true`。

1. 右键 `Add merged file` → Save Patch for “<短哈希>”…，存到 `$m11_root/patches`：目录里有 `0000-cover-letter.patch` 与 `0001-Add-merged-file.patch`。封面信的标题是 `Subject: [PATCH 0/1] *** SUBJECT HERE ***`；`grep -c '^From ' "$m11_root/patches/0001-Add-merged-file.patch"` 输出 1，补丁的标题是 `Subject: [PATCH 1/1] Add merged file`。保存后 Finder 来到前台，打开 `patches` 目录并选中这两个文件。Window → Activity 的 Repository 页多一条 Format Patch，写耗时与 Finished，没有一行结果；每个提交记一条，没有 Save Patch 记录。
2. 按住 ⌥ 右键 `Add merged file`：菜单项换成 Quick Save Patch for “<短哈希>”，没有省略号。选中后不弹对话框与目录面板，`0000-cover-letter.patch` 与 `0001-Add-merged-file.patch` 出现在 `本机 分支` 的根目录，两个标题同第 1 步，补丁里同样只有一封邮件；Finder 来到前台，打开仓库根目录并只选中这两个文件，根目录里的其它文件不选中；Working Copy 多出这两个未跟踪文件；Activity 的 Repository 页同样多一条 Format Patch。核对后关掉这两个 Finder 窗口，执行 `rm "$m11_repo/0000-cover-letter.patch" "$m11_repo/0001-Add-merged-file.patch"` 删掉它们。

## 分支整理

仍在 `本机 分支`。

1. 侧边栏：已并入 `main` 的 `feature/merged` 没有 Merged 徽标，名字不变灰，悬停提示里没有 “is fully merged”；`old/stale` 显示陈旧的时钟与年数。底部的视图设置菜单里没有 Show Fully Merged Badge in Sidebar。
2. 历史选 `feature/merged`：顶部没有已完全合并的提示。选 `old/stale`：顶部是 Branch Appears Stale。
3. 右键 `feature/merged`：Archive “feature/merged” 下面只有 Skips Auto-Archiving，没有控制已完全合并提示的勾选项。
4. Branches Review：筛选菜单是 None、Stale、Active、Tracking Error、Mergeable、Merge Conflicts、With Pull Request 与 Without Pull Request，没有 Fully Merged；`feature/merged` 一行前面没有状态图标。
5. 侧边栏底部的归档按钮写 1，点开 Archive Branches 只列出 `old/stale`，右边的原因是 Stale；`feature/merged` 不在其中。点 Cancel。托管服务上请求已合并的分支（[M9](M9.md) 的 “分支整理的协作状态” 第 1 步）原因写 Merged。
6. 执行 `m11_git branch trunk old/stale`：侧边栏的 `trunk` 没有陈旧的时钟与年数，归档按钮仍写 1。
7. 执行 `m11_git branch develop main`：Branches Review 表头的 Compare local branches to 换成 `develop`。执行 `m11_git branch -D trunk develop` 后回到 `main`。

## 同步与发布

仍在 `本机 分支`，HEAD 在 `main`。

1. Repository → Push ⇧⌘U：Push 对话框只有 Local Branch、Remote、Branch Name 与 Options，没有 Track 一项。
2. 在终端执行 `m11_git switch -q topic`，再 Repository → Push：打开的是 Publish Branch，Local Branch 是 `topic`，Track This Remote Branch 默认勾上。点 Cancel 后，工具栏的 Push 与侧边栏 `topic` 右键的 Push 也打开它。在其中一个里发布：`m11_git rev-parse --abbrev-ref 'topic@{upstream}'` 输出 `origin/topic`；然后执行 `m11_git switch -q main`。
3. 右键 `old/stale`（不是 HEAD，也没有上游）→ Push：仍是 Push 对话框，没有 Track 一项。点 Cancel。
4. App 在后台也自动获取：执行下面的命令让另一个克隆再推一个提交，然后切到别的 App，让 Spooky 留在后台。至多 5 分钟后 `m11_git rev-parse --short origin/main` 是这个新提交，Activity 的 Remote 页多一条 Auto Fetch。窗口显示仓库管理界面时不自动获取。

```sh
git -C "$m11_root/other" pull -q --ff-only
git -C "$m11_root/other" commit -q --allow-empty -m 'Fetched in background'
git -C "$m11_root/other" push -q origin main
```

5. Publish Repository 需要 [M9](M9.md) 的托管账号。在 `本机 分支` 用 Repository → Publish Repository… 发布，Remote Name 填 `hosted`：说明写着把全部本地分支与标签推送过去，没有上游的分支跟踪新远端上的同名分支。发布后托管服务上的新仓库有 `main`、`feature/merged`、`old/stale`、`topic` 与 `v1`，没有 `origin/main` 这类别的远端的跟踪分支；`feature/merged`、`old/stale` 跟踪 `hosted` 上的同名分支，`main` 与 `topic` 仍跟踪 `origin`。
6. 执行 `git init -q "$m11_root/空仓库"`，在 Spooky 里打开这个仓库，再打开同一个对话框：说明与第 5 步相同，写着把全部本地分支与标签推送过去。发布后托管服务上有新建的空仓库，本仓库多一个远端，推送失败：弹出的错误与 Activity 的 Remote 页里 Add Remote and Push 的日志都是 Git 的原文 “No refs in common and none specified; doing nothing.”；新建的仓库与远端都还在。

## 对话框头部

在 `本机 分支` 依次打开 Repository → Fetch、Repository → Sync…、Working Copy → Reset HEAD to Revision…、Repository → Export Revision…、Working Copy → Save Stash…、Working Copy → Apply Patch… 与 Repository → Create New Tag…：标题下直接是说明，没有仓库位置一行。服务器仓库见 “服务器仓库” 一节。

## Activity

1. Window → Activity ⌃⌘0：内容区顶部没有分页一行，第一次打开在 Remote 页。
    - 初始的 551 pt 宽度下，工具栏从左到右是 Clear All、» 按钮与放大镜按钮；点 » 列出 Remote、Repository、Service 三项，选 Repository 换到 Repository 页
    - 把窗口拉宽到 760 pt：工具栏从左到右是 Clear All、Remote | Repository | Service 分段与搜索框，分段选中 Repository，每段宽度随文字，Repository 一段最宽；点 Remote 回到 Remote 页
    - 悬停三段分别提示 Shows Remote Activities、Shows Repository Activities 与 Shows Service Activities
2. Remote 页列出前面的 Auto Fetch 与 Publish Branch；Repository 页列出 Format Patch 等仓库操作，以及打开与刷新时的读取。没有托管账号时 Service 页为空，有空状态；做过 “同步与发布” 第 5、6 步时，Service 页列出 Load Owners、Check Repository Name 与 Publish Repository。
3. Repository 页的读取：在 Repository 页点 Clear All，再在 `本机 分支` 的工具栏点 Refresh。
    - 列出 Load Working Tree Status、Update Branches、Update Remotes、Update Tags、Update Stashes、Update Submodules、Update Worktrees、Load Commits 与 Load Commit Count；读取并发，顺序不固定
    - 每行右上角是两位小数的耗时，如 `0.02 sec`；Load Working Tree Status 的第三行是 `Loaded n working tree entries`，Update Branches、Update Remotes、Update Stashes、Update Submodules 是 `n updated, n added, n deleted`，Load Commits 是 `Loaded n Git commits`，其余写 Finished；选中一行，日志区就是这一行结果
    - 在终端执行 `m11_git branch m11-read` 后再点 Refresh：Update Branches 是 `0 updated, 1 added, 0 deleted`；执行 `m11_git branch -D m11-read` 删掉它
    - Working Copy 里改动 `readme.txt` 并选中它：多一条 Load Working Tree to Index Diff；暂存后选中已暂存的一侧：多一条 Load Index to Base Diff；执行 `m11_git restore --staged --worktree readme.txt` 还原
    - 文件历史与 Blame：在 History 里选中 `Start`，详情切到 Tree，右键 `readme.txt` → Show File History of “readme.txt”：多一条 Load Commits（`Loaded 1 Git commits`）与一条 Load Commit Count。单击时间线里的 `Start`，多一条 Load Commit Diffs；切到 Raw，多一条 Load Blob。右键 `Start` → Show Blame for “readme.txt” at Revision “…”：多一条 Load Blob 与一条 Load Blame，都写 Finished
    - 在终端改动工作区文件，不切回 Spooky：Spooky 的窗口自动刷新出这个改动，Activity 的 Repository 页不新增记录；切回 Spooky，新增一轮刷新的记录
4. 侧边栏底部只列本仓库的远程操作：在 `本机 分支` 用 Repository → Create Branch ⌘B 新建 `m11-sidebar`，侧边栏底部不出现 Create Branch，Activity 的 Repository 页有；再用 Repository → Fetch 获取，侧边栏底部出现这次 Fetch。
5. 在 Remote 页的搜索框输入 `enumerating`：只剩日志里有 “Enumerating objects” 的获取，不区分大小写。换到 Repository 页，同一个搜索词不列出 Remote 页的记录。清空搜索框。
6. 选一条取回了对象的 Auto Fetch：日志里 `remote: Counting objects` 只有一行 `100% (n/n), done.`，进度刷新没有留下多行。
7. 长输出完整保留：执行下面的命令让另一个克隆推上 2,000 个标签，再在 `本机 分支` 用 Repository → Fetch 获取。取回标签的那条记录（这次 Fetch，或在它之前发生的 Auto Fetch）的日志里，2,000 个 `refs/tags/bulk-` 开头的标签一个不少，滚到底是 `refs/tags/bulk-999`。

```sh
for i in $(seq 1 2000); do git -C "$m11_root/other" tag "bulk-$i"; done
git -C "$m11_root/other" push -q origin --tags
```

8. 在 Repository 页点 Clear All：这页已结束的记录清空，Remote 页不变；进行中的记录不被清掉。
9. 退出再启动：Remote 页仍列出前面的记录与完整日志，Repository 页没有退出前的记录。`~/Library/Application Support/Spooky/Activity/` 里每条 Remote 记录一个文件。打开 `本机 分支`，侧边栏底部不列这些读回的记录。
10. 7 天前的记录被删掉：退出 App，把其中一条记录的开始时间改成 8 天前，再启动。这条记录不再列出，它的文件也被删掉。

```sh
m11_activity="$HOME/Library/Application Support/Spooky/Activity"
m11_record="$(ls "$m11_activity"/*.json | head -n 1)"
m11_started="$(( $(date +%s) - 978307200 - 8 * 86400 ))"
sed -E -i '' "s/\"started\":[0-9.]+/\"started\":$m11_started/" "$m11_record"
```

11. Service 页也记托管服务的读取，需要 [M9](M9.md) 的托管账号。打开远端在托管服务上的仓库（如 M9 用的测试仓库），显示 Pull Requests 视图：Service 页出现 Load Pull Requests（GitLab 是 Load Merge Requests），行上是这个仓库的名字；有请求时点开一个，出现 Load Pull Request。在 Settings → Accounts 选中这个账号点 Re-authenticate… 重新认证：Service 页出现一条 Verify Account，行上没有仓库名，日志区没有仓库路径。

## 服务器仓库

在仓库管理窗口添加 `spooky-test` 上的 `$m11_remote/history` 与 `$m11_remote/workspace`。

1. `history`：滚到底一直续载到 `Commit 1`。点一下 `main`，右键 Tags 里的 `v0` → Reveal in History 先询问，点 Cancel 后侧边栏仍选中 `main`，列表停在第一页；再来一次点 Load More Commits，续载到 `Commit 1` 并选中它。
2. 双击 `history` 里的一个提交，点短哈希：版本选择器默认高亮 HEAD，↑ ↓ 移动高亮，双击一行换版本，单击与回车不换。搜索框输入 `commit 99.9`，按正则只剩 `Commit 9999`…`Commit 9909` 这 10 个；改成 `x[`，列表为空，没有错误提示。
3. 在 `workspace` 的历史里按住 ⌥ 右键 `Start` → Quick Save Patch for “<短哈希>”：不弹对话框与目录面板，封面信与补丁写在 B 上 `workspace` 的根目录，Finder 不打开，Working Copy 多出这两个未跟踪文件。下面第一条输出 `Subject: [PATCH 0/1] *** SUBJECT HERE ***`，第二条输出 `Subject: [PATCH 1/1] Start` 的补丁，第三条输出 absent：

```sh
m11_ssh "grep '^Subject' '$m11_remote/workspace/0000-cover-letter.patch'"
m11_ssh "cat '$m11_remote/workspace/0001-Start.patch'"
test -e "$m11_remote/workspace/0001-Start.patch" || echo absent
m11_ssh "rm '$m11_remote/workspace/0000-cover-letter.patch' '$m11_remote/workspace/0001-Start.patch'"
```

4. 右键 `Start` → Save Patch for “<短哈希>”…，存到 `$m11_root/patches`：封面信与补丁存在 A 上，`0000-cover-letter.patch` 的标题是 `Subject: [PATCH 0/1] *** SUBJECT HERE ***`，`0001-Start.patch` 里只有一封 `Subject: [PATCH 1/1] Start`；Finder 来到前台并选中这两个文件，核对后关掉这个 Finder 窗口。
5. 打开 “对话框头部” 一节的七个对话框：标题下都多一行 `spooky-test:` 开头的仓库位置。
6. 侧边栏、历史与 Branches Review 同样没有完全合并的标记与筛选。
7. 右键 `topic` → Check Out Branch，再 Repository → Push：打开 Publish Branch，Track This Remote Branch 默认勾上。发布后 `m11_ssh "git -C '$m11_remote/workspace' rev-parse --abbrev-ref 'topic@{upstream}'"` 输出 `origin/topic`；再检出 `main`。
8. App 在后台也自动获取：执行下面的命令后切到别的 App，至多 5 分钟后 Activity 的 Remote 页多一条 `spooky-test:workspace` 的 Auto Fetch，`m11_ssh "git -C '$m11_remote/workspace' rev-parse --short origin/main"` 是这个新提交。

```sh
m11_ssh "cd '$m11_remote/other' && git pull -q --ff-only && git commit -q --allow-empty -m 'Fetched in background' && git push -q origin main"
```

9. 服务器轮询不记读取：在 Activity 的 Repository 页点 Clear All，执行 `m11_ssh "printf 'poll\n' >> '$m11_remote/workspace/m11.txt'"`，不切回 Spooky：Spooky 轮询刷新出这个改动，Repository 页不新增记录；切回 Spooky，新增一轮刷新的记录，行上是 `spooky-test:workspace`。执行 `m11_ssh "git -C '$m11_remote/workspace' checkout -- m11.txt"` 还原。
10. 退出再启动：Remote 页仍列出服务器仓库的 Auto Fetch 与 Publish Branch。
