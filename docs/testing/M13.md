# M13：托管服务的对齐验收

M13 承接 [M12](M12.md)，修正 [M9](M9.md) 交付的托管服务，M1–M12 的验收步骤继续适用：

- 私有部署 GitLab 不设最低版本，9.0 起都能添加；旧版本缺的字段只让用到它的功能退化，合并的失败、冲突、权限与压缩按 GitLab 的响应分类
- 私有部署 GitLab 可以用用户名与密码登录，换来的令牌到期前自动续期
- HTTPS 远端属于已登录的账号时，Git 用账号的令牌认证，本机与服务器仓库都不弹框；令牌被拒时回到询问，并说明账号的令牌没能通过
- 讨论是可以选中的列表，按天列出请求里的提交；评论与描述有右键菜单与按钮，可以修改、删除评论与修改描述，GitLab 上还可以回复评论；讨论头部、评论与描述用头像版式，正文按完整的 Markdown 显示；Commits 段顶部是参与者条
- 请求列表有右键菜单与双击；账号、评论、描述、检出、新建与修改、合并、关闭、关联远端与发布仓库的对话框都是 480 宽的对话框骨架
- 对话框骨架与引用对话框的头部、错误文字对齐输入列，应用图标挂在头部文字左侧；克隆对话框的选项区对齐输入列；表单行在 VoiceOver 里同时读出标签与值
- 添加、移除账号或增删远端之后，请求视图不用重开窗口就随之更新
- 侧边栏底部的活动区列出本仓库进行中与刚结束的远程操作，带进度条与停止按钮，结束 4 s 后移除

## 自动验证

在仓库根目录执行：

```sh
mise run swift:lint
mise run build
mise run test
swift build --product Spooky
./scripts/build-app.sh
```

github.com 的实测默认跳过，开启方式见 [M9](M9.md) 的 “自动验证”；`GitHubLiveTests` 另外修改、删除评论与只改描述，并读回核对。

经辅助功能接口读窗口的测试只在有辅助功能权限时运行，见 [测试](README.md)。

M13 新增与修改的自动测试覆盖：

- 私有部署 GitLab 的版本：读用户前不查版本，没有 API v4 时接口不兼容；没有 `detailed_merge_status` 时按旧字段推出草稿、正在检查、冲突、讨论与流水线，流水线先取 `head_pipeline`；EE 的审批与 CE 的 404；`broken_status`；9.0–12.4 缺字段时的合并选项、指派人、`reopened`、比较基准与评论顺序；`%2F` 被解码时按编号重试并记住编号；合并回 200 而请求还开着、401 的两种含义、405 / 406 / 422 的冲突、合并时取消压缩
- 用户名与密码登录：换令牌的表单与到期时间，续期与何时续期，三种授权错误码，失败不重试，`Authorization: Bearer` 头；钥匙串里的令牌 JSON，到期前串行续期，刷新令牌被拒时标为需要重新认证
- 账号令牌认证：
  - 真实 Git 的 `credential fill`、`reject` 与 `approve`：作用域内只问 Spooky 的助手并带上路径，作用域外问仓库配的助手；前缀的过滤；服务器命令的凭据配置
  - 包装器：`get` 的回答成为凭据、输出里遮住令牌，不回答时 Git 改问 askpass，`erase` 不交出密码，`store` 不发请求
  - 回答者：前缀的来源，按服务的回答格式，手动关联选定账号，需要重新认证的账号不回答，令牌被拒后回到询问
- 讨论：
  - 提交按日历日分组并与评论按时间排列，组的标题，读出比较范围里的提交与参与者，头部的合并说明
  - 比较范围的参与者经 `.mailmap` 合并；托管用户的头像按地址读取与缓存；评论的作者、头像与更新时间
  - 两种服务上修改、删除、回复评论与修改描述的请求；评论与描述的可用条件与右键菜单
  - 正文的 Markdown：换行、标题、行内格式、代码块、引用块、两种外观的颜色、列表、链接与图片、HTML 与分隔线、表格、按宽度量高与缓存
- 请求列表与对话框：
  - 修改与检出请求的可用条件
  - 评论、描述、检出、关闭、新建、修改、合并、关联远端与发布仓库对话框的宽度、输入的位置、标题、说明与主按钮
  - 检出的分支名校验与预填，合并方式的预选，发布的远端名、下拉的项与菜单项的可用性
  - 账号对话框的标题、下拉的位置、地址的错误与重复添加
  - 对话框骨架底栏的转圈与进度文字，头部与错误文字对齐输入列，内容区读到输入列；引用对话框的对齐；克隆对话框选项区的位置；表单行在辅助功能里的名称
- 请求视图：账号变化与远端变化之后重新读取
- 侧边栏活动区：列出的记录、区高、进度条的值与停止按钮；Activity 行的标题与按传输方向的图标

## 准备

### 本机

本机的测试目录放在系统临时目录下，测试结束后删除。Git 只读写这里的一份全局配置：

```sh
m13_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m13.XXXXXXXX")"
mkdir "$m13_root/config"
export GIT_CONFIG_GLOBAL="$m13_root/config/gitconfig"
export GIT_CONFIG_NOSYSTEM=1
git config --global init.defaultBranch main
git config --global user.name 'Spooky Test'
git config --global user.email 'spooky@example.invalid'
git config --global commit.gpgSign false
```

用户自己的凭据助手由一个只做记录的脚本代表，`helper.log` 记下每次调用的动作与地址：

```sh
cat > "$m13_root/helper" <<'EOF'
#!/bin/sh
{ printf '%s ' "$1"; grep -E '^(protocol|host|path)=' | tr '\n' ' '; echo; } >> "${0%/*}/helper.log"
EOF
chmod +x "$m13_root/helper"
git config --global credential.helper "$m13_root/helper"
```

侧边栏活动区用的本机远端，在 “侧边栏底部的活动区” 一节加进测试仓库：

```sh
# local.git：本机远端背后的裸仓库
git init -q --bare "$m13_root/local.git"

# slow：获取时先停 10 秒，用来看进行中的行
printf '#!/bin/sh\nsleep 10\nexec git upload-pack "$@"\n' > "$m13_root/slow-upload-pack"
chmod +x "$m13_root/slow-upload-pack"
```

- github.com：[M9](M9.md) 的测试仓库，与一个 `repo`、`read:org` 权限的个人访问令牌；另一个账号能在测试仓库里评论
- GitLab.com：一个测试项目，与一个 `api` 权限的个人访问令牌；另一个账号能在项目里评论
- 私有部署 GitLab：没有测试实例，相关的行为只有自动测试，见 “还没实测”
- 在两个服务上各开一个自己的请求：源分支有两位作者、分在两天的几个提交，指派给自己与另一个账号；另一个账号另开一个请求
- 测试结束后删掉测试分支、请求与临时创建的仓库，撤销测试用的令牌

```sh
read -rs m13_token
```

## 账号

1. Settings › Accounts 表格上方的说明写明：这些账号用于 Pull Request 与 Merge Request，HTTPS 远端属于这些账号时 Git 也用它们认证，令牌只存在钥匙串里。
2. GitLab Self-Managed… 的标题是 Add GitLab Self-Managed Account。Authentication 下拉有 Personal Access Token 与 Username and Password，占满输入列；Host 的占位是 `https://example.com`，令牌框的占位是 Personal Access Token。
3. 选 Username and Password：多出 Username 与 Password 两行；说明写明密码只用来换令牌、不保存，以及能用的前提：GitLab 18.11 及以前，服务器不要求 OAuth 应用凭据、允许 Git over HTTPS 用密码，账号有 GitLab 或 LDAP 密码、没开双重验证。
4. Host 填 `not a url`：错误区写 Host is not valid，Add Account 不可用。填 `https://10.255.255.1` 与任意用户名、密码后提交：底栏左侧转圈写 Validating…，表单与主按钮不可用；按 Cancel 只停止校验，对话框留着。再提交一次等到失败：提示框挂在对话框上，写明 Can’t Reach the Hosting Service；关掉后对话框还在，输入没有清空。
5. GitHub… 与 GitLab.com… 的添加、重复添加、重新认证与 “−” 的确认，按 [M9](M9.md) “托管账号” 第 2–6 步验。

## 账号令牌用于 Git 认证

在 Settings › Accounts 用 `m13_token` 添加 github.com 的账号。

1. ⌃⌘C 打开克隆对话框：Remote URL 填测试仓库的 HTTPS 地址 `https://github.com/<owner>/<repo>.git`，Clone To 选 This Mac 与 `$m13_root`。私有仓库同样不弹框，克隆完成。之后用 `m13_repo` 指代这个克隆：

   ```sh
   m13_repo="$m13_root/<repo>"
   ```

2. 打开 `m13_repo`：打开时的自动获取成功。Repository → Fetch 获取 origin，新建分支 `m13-auth` 提交一次后推送发布，再拉取：都不弹框。`helper.log` 里没有 `host=github.com` 的记录。
3. 令牌不留在记录与日志里，下面三条命令都没有输出：

   ```sh
   log show --last 30m --info --predicate 'subsystem == "com.rakuyo.spooky"' | grep -F "$m13_token"
   printf '%s' "$m13_token" | grep -rlF -f /dev/stdin "$HOME/Library/Application Support/Spooky"
   printf '%s' "$m13_token" | grep -rlF -f /dev/stdin "$m13_repo/.git"
   ```

4. 把 origin 改成 SSH 地址 `git@github.com:<owner>/<repo>.git`：获取用系统的 SSH 密钥，与账号无关；核对后改回 HTTPS 地址。
5. 先不打开请求视图，在 github.com 上删掉 `m13_token`：
    - 下一次 Repository → Fetch 失败，写明认证失败
    - 再获取一次：弹出询问用户名与密码，说明里多出 The token of the account “<用户名>” wasn’t accepted. Enter a username and password.；点 Cancel
    - 新建一个令牌，在 Settings › Accounts 选中账号点 Re-authenticate… 换上：获取又不弹框
6. 移除账号后再获取：弹出询问用户名与密码，没有账号令牌的说明；点 Cancel，再用新令牌添加回账号，更新 `m13_token`。
7. 添加 GitLab.com 的账号，用 HTTPS 地址把 GitLab.com 的测试项目克隆到 `$m13_root`：克隆、获取与推送同样不弹框，`helper.log` 里没有 `host=gitlab.com` 的记录。

## 服务器仓库

1. ⌃⌘C 打开克隆对话框：Remote URL 同上，Clone To 选 `spooky-test` 与 `$m13_remote`：B 上克隆完成，不弹框。
2. 打开 B 上的这个仓库：获取、新建分支 `m13-server` 提交并发布都不弹框。
3. 令牌不在 B 上，下面的命令没有输出：

   ```sh
   printf '%s' "$m13_token" | m13_ssh "grep -rlF -f /dev/stdin ~/.spooky '$m13_remote'"
   ```

4. 令牌被拒时与本机相同：先不打开请求视图，在 github.com 上删掉令牌，第一次获取失败、第二次弹出带说明的询问；核对后用新令牌重新认证。

## 讨论

GitHub 与 GitLab.com 各验一遍，按 [M9](M9.md) “Pull Request 与 Merge Request” 第 4、5 步核对讨论与 Commits 段的版式，再核对下面几处，与托管服务网页上的结果一致：

1. 讨论里可以点选、⌘ / ⇧ 多选。提交按天合成组，组的标题前是历史图标，写 “<n> commits added on <日期>”，点三角折叠；组里每行是作者头像、等宽的短哈希、标题与行尾的签名状态。
2. 提交的右键菜单是 Copy Commit Hash to Clipboard、分隔线与 Show Commit “<短哈希>”；选中几个提交时是 Copy <n> Commit Hashes to Clipboard。双击或回车打开提交。
3. 讨论头部：Assignees 后是一排指派人头像，悬停写出名字，右侧是作者头像。
4. 自己的评论：标题一行右侧是 Edit 与 Delete（GitLab 另有 Reply）；右键是 Edit Comment…、Reply to Comment…（只有 GitLab）、分隔线与 Delete Comment…。别人的评论：GitLab 只有 Reply 与 Reply to Comment… 可用，GitHub 没有可用的项。选中两条评论时右键没有菜单。
5. Edit Comment…：对话框标题是 Edit Pull Request Comment（GitLab 是 Merge Request），文字区预填原文、占满对话框的宽度；改完按主按钮后评论写 edited on，网页上是新内容。双击自己的评论或选中后回车同样打开它，双击别人的评论只有提示音。
6. GitLab 的 Reply to Comment…：标题是 Reply to Merge Request Comment，主按钮 Reply to Comment；回复排在讨论最后，网页上在原评论的同一个讨论里。
7. Delete Comment…：标题是 Delete GitHub Pull Request Comment，说明写明删除不能撤销，没有输入，主按钮 Delete Comment；评论从讨论与网页上消失。
8. 自己的请求的描述：标题一行右侧有 Edit，右键是 Edit Description…，都打开 Edit Pull Request Description，文字区预填原文；清空后保存写 No description given。别人的请求没有 Edit，右键的 Edit Description… 不可用。
9. 在网页上发一条带标题、列表、引用块、代码块、表格、删除线与链接的评论：讨论里按 [M9](M9.md) 第 4 步的写法显示；在 Settings › Appearance 切换深浅外观，代码块的底色、文字与边框随之切换。
10. Commits 段顶部的参与者条：左边写 “<n> contributors” 与各参与者的头像，悬停写出姓名与邮箱；右边写 “<n> commits”。

## 请求列表与对话框

1. 自己的请求右键是 Edit Pull Request #<编号>… 与 Check Out Pull Request #<编号>…（GitLab 是 Merge Request !<编号>）；别人的请求 Edit 不可用。双击自己的请求打开修改对话框，双击别人的只有提示音。新建、修改、检出、合并与关闭按 [M9](M9.md) 第 6–9 步验。
2. 下面的对话框都是 480 宽，头部的应用图标在标题与说明左侧 16，标题、说明与错误文字从输入列开始；没有输入列时从 120 开始：
    - 账号的添加与重新认证
    - 发表、修改、回复与删除评论，修改描述
    - 检出、新建与修改、合并与关闭请求
    - 关联远端（Unsupported Remote 下的 Associate…）与 Repository › Publish Repository…
3. 移除账号的确认是 Settings 窗口里的提示框：标题 Remove Service Account，按钮 Cancel 与 Remove Account。
4. 用法语启动（先退出 Spooky，再执行 `m13_open --args -AppleLanguages '(fr)'`），打开 Publish Repository… 并把远端名改成 `origin`：“Nom du dépôt distant :” 让输入列右移，标题、说明、各行输入与错误文字都从同一列开始，输入框的右缘距对话框右边 20。核对后退出，再用 `m13_open` 启动。
5. Repository → Create New Tag… 填一个已有的标签名（仓库里没有标签时先建一个）：Name 输入框、标题、说明与 “A tag with this name already exists.” 都从 120 开始。
6. ⌃⌘C 打开克隆对话框并展开 Options：Use LFS Clone 与 Initialize Submodules 的左缘与 Remote URL 输入框对齐。
7. 打开 VoiceOver（⌘F5），在 GitLab.com 的请求上打开 Merge：Merge Strategy 一行读出标签与 Merge Commit 等值。
8. 在 GitLab.com 项目的窗口里打开请求视图，然后在 Settings › Accounts 移除 GitLab.com 的账号：请求视图回到 No GitLab Account；加回账号后不用重开窗口就读出列表。在仓库里添加一个远端并刷新：Remote 下拉随即出现它。

## 侧边栏底部的活动区

给 `m13_repo` 加上本机远端：

```sh
git -C "$m13_repo" push -q "$m13_root/local.git" HEAD:refs/heads/main
git -C "$m13_repo" remote add slow "$m13_root/local.git"
git -C "$m13_repo" config remote.slow.uploadpack "$m13_root/slow-upload-pack"
git -C "$m13_repo" remote add broken "$m13_root/missing.git"

# 获取全部远端与自动获取跳过这两个：broken 会让获取停下，slow 会让先结束的行在别的行出现前移除
git -C "$m13_repo" config remote.slow.skipFetchAll true
git -C "$m13_repo" config remote.broken.skipFetchAll true

# extra-1…extra-3：获取全部远端时与 origin 一起列出
for i in 1 2 3; do git -C "$m13_repo" remote add "extra-$i" "$m13_root/local.git"; done
```

在 `m13_repo` 的窗口里用 Repository → Fetch 获取：

1. 获取 `slow`：侧边栏底部展开，上方一条分隔线；行里是传输方向的图标与 Fetching slow，下面是进度条与停止按钮，再下面是 git 输出的最后一行。完成后写 Fetched slow，进度条满格，停止按钮变灰；约 4 s 后这一行移除，区收起。展开与收起约 0.2 s，侧边栏的列表跟着一起动。
2. 获取 `broken`：写 Fetching broken failed，进度条满格，摘要是 git 报错的最后一行；约 4 s 后移除。
3. 获取 `slow` 时点停止按钮：写 Fetching slow cancelled，进度条停在当时的位置，停止按钮变灰；不打开 Activity 窗口。
4. 获取时点行里停止按钮以外的地方：打开 Activity 窗口。
5. Fetch All Remotes：origin 与 `extra-1`…`extra-3` 各一行，最新的在上，行之间的分隔线左右缩进 14；最多露出三行，其余在区内滚动；结束的行各自约 4 s 后移除。
6. 只列本仓库本次运行里的远程操作：别的窗口里的获取不出现，新建分支等仓库操作不出现，重新启动 App 后不列出读回的记录。
7. Quick Pull、Quick Push 与 Publish Branch 同样出现，标题与 Activity 窗口 Remote 页的行相同。
8. 深浅两种外观下，活动区都没有底色，与侧边栏同色。
