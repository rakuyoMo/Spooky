# M23 服务器仓库挂载到本机的验收

范围：本机位置的四种方式，SMB 与 sshfs 挂载，仓库设置的 Location on This Mac 与本机位置对话框，Show in Finder 的连接、查找、挂载与表单，仓库管理与最近克隆的 Show in Finder，复制路径，添加服务器仓库时的挂载选项，重新挂载；侧边栏不再提示上游已不存在，服务器仓库工具栏的提示，新图标，侧边栏的展开状态，GitHub 登录的 Copy Code，失效的工作树。M1–M22 的验收步骤继续适用。

所有命令在仓库根目录执行。界面验收需要已解锁、显示器正常显示的 macOS 会话；深色与浅色外观各验一遍。

## 自动验证

```sh
mise run swift:lint
mise run build
mise run test
swift build --product Spooky
./scripts/build-app.sh
mise run bundle
```

- `RemoteMounterTests`：端口连得上、连不上与超时时列出的方式，sshfs 装了与没装，NetFS 状态的说明，sshfs 的命令行（主机别名、带空格与引号的路径、SSH 选项），运行、失败后卡住与后台进程开着标准错误时的结束方式。
- `RemoteMountTests`：从 `ssh -G` 的输出取主机、按后缀从长到短查找、标记核对与工作树的 Git 目录。
- `RepositoryMountStateTests`：本机位置的读写、旧的手动指定文件夹的迁移与 Reset User Defaults 后保留；重新连上后重查没有挂载的目录；后台挂载只做一次、不询问、失败只记原因；各状态的提示；Show in Finder 的先连接、连不上报错、等进行中的查找与挂载、不沿用 “没有挂载”、换成表单、挂载失败带错误、取消不改设置；仓库管理与最近克隆不经连接直接打开、取消后等工作结束再收尾。
- `LocalLocationFormTests`：方式菜单、各方式的主按钮与必填项，挂载失败与取消不改设置，指定文件夹的核对，改回自动查找后重新查找。
- `AddRemoteMountChoiceTests`、`AddRemoteRepositoryViewTests`：主机别名为空时不检测、改别名回到不挂载、选 sshfs 没选或选了不空的文件夹不能提交，仓库打开后允许询问地挂载、失败不影响添加。
- `WindowChromeTests`：服务器仓库工具栏的提示与本机仓库相同，Finder 项随本机位置及时换提示。
- `RepositoryBookmarksTests`、`CloneActivityTests`、`QuickActionTests`：书签与最近克隆的 Show in Finder 与 Copy Path，本机工作树的 Copy Path。
- `SidebarExpansionTests`、`RepositorySidebarViewTests`：展开状态按仓库记下与恢复，没有记录时是默认，过滤与拖动悬停的展开不记下。
- `InvalidWorktreeTests`、`RepositoryWorktreesTests`：失效工作树的菜单项、顺序与可用状态，详情两个按钮，服务器仓库的悬停提示带主机前缀；修复前核对所选目录的各种提示与修复成功。
- `SidebarSettingsTests`、`OperationBannerViewTests`：侧边栏分支行不再有跟踪错误的标记与提示，自绘图形有轮廓。
- `DeveloperMenuTests`、`LocalizationTests`：Reset User Defaults 保留本机位置，八种语言的资源完整性与格式参数。

## 准备

本机先装好 sshfs 与 FUSE-T 或 macFUSE，“没装” 一侧的步骤临时把 `sshfs` 移出 `PATH` 与 Homebrew 的目录再验。服务器上的测试目录只经 `spooky-test` 在 `/Users/wgy/spooky-test/` 下新建，测试结束后删除：

```sh
m23_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m23.XXXXXX")"
m23_ssh() { ssh -o BatchMode=yes spooky-test "$@"; }
m23_remote="$(m23_ssh 'umask 077; mkdir -p /Users/wgy/spooky-test && mktemp -d /Users/wgy/spooky-test/m23-app.XXXXXXXX')"
m23_ssh /bin/sh -s "$m23_remote" <<'EOF'
cd "$1"
git init -q --bare -b main remote.git
git init -q -b main workspace
cd workspace
git config user.name 'Spooky Test'
git config user.email 'spooky@example.invalid'
printf 'base\n' > readme.txt
git add -A
git commit -q -m 'Start'
git remote add origin "$1/remote.git"
git push -q -u origin main
git branch gone
git push -q origin gone
git branch -q --set-upstream-to=origin/gone gone
git push -q origin --delete gone
git fetch -q --prune
git worktree add -q -b moved ../moved-tree
git worktree add -q -b deleted ../deleted-tree
EOF

mkdir "$m23_root/sshfs-mount" "$m23_root/not-empty"
touch "$m23_root/not-empty/file"
```

本机仓库按同样的办法在 `$m23_root/local` 建一份，带 `moved-tree` 与 `deleted-tree` 两个工作树。启动 App 按 [M12](M12.md) 的 “启动 App” 进行，在仓库管理窗口添加 `$m23_remote/workspace` 前先做 “添加服务器仓库” 一节。

## 添加服务器仓库

1. 仓库管理窗口点 Add Server Repository…：路径下面有 Mount on This Mac，写 Don’t Mount；主机别名为空时不可用。
2. 填 `spooky-test`，点开 Mount on This Mac：检测中写不可选的 Checking…，之后列出 SMB 与 sshfs；两者都不可用时写不可选的 No Mount Method Available。
3. 改主机别名：Mount on This Mac 回到 Don’t Mount。
4. 选 sshfs：多出 Mount at 一行，高度随之动画；没选文件夹时 Open 不可用；选 `$m23_root/not-empty` 时错误区写 “not-empty” isn’t empty.，Open 不可用。
5. 选 SMB，路径填 `$m23_remote/workspace`，点 Open：仓库打开后弹出系统的共享列表或登录框；点取消时仓库照常打开，仓库设置的 Location on This Mac 写失败的原因。
6. 再添加一次并选 sshfs、Mount at 选 `$m23_root/sshfs-mount`：仓库打开后挂上，Show in Finder 直接打开挂载里的 `workspace`。
7. 主机缺少环境变量时先关掉提醒，之后才挂载；经备选底栏新建仓库后同样挂载。

## SMB

1. 仓库设置 General 的 Location on This Mac：悬停出现 Change…；没连上 B 时 Change… 不可用。
2. Change… 打开 Set Location on This Mac：说明写 Choose where “spooky-test:<路径>” is on this Mac.；Method 打开时写 Checking…，之后列出可用的方式，现在的方式总列出。
3. Method 选 SMB Mount，主按钮写 Mount；点 Mount：底栏左侧写 Mounting…，表单与主按钮不可用，Cancel 可用；在系统的共享列表里选含这个仓库的共享，挂上后对话框关闭，这一行写 SMB Mount: <本机路径>。
4. 共享已经挂着时再点 Show in Finder：直接打开，不再挂第二次（`mount` 里这个共享只有一行）。
5. 系统登录框点取消：对话框不关，错误区写出原因与原始输出，设置不变。
6. 选不含这个仓库的共享：错误区写 This repository isn’t in the mounted share.，卷保持挂载。
7. 从添加对话框、Show in Finder 与仓库设置各挂载一次。

## sshfs

1. 装了 sshfs：Method 选 sshfs Mount，多出 Mount at 一行；选 `$m23_root/not-empty` 时写 “not-empty” isn’t empty.，Mount 不可用；选 `$m23_root/sshfs-mount` 后点 Mount：挂上后核对通过，这一行写 sshfs Mount: <文件夹>，Show in Finder 打开它。
2. 核对前后各执行一次 `m23_ssh "ls -a '$m23_remote/workspace/.git'"`：两次列出的文件相同。
3. 没装 sshfs：Method 里没有 sshfs Mount；添加对话框的 Mount on This Mac 里也没有。

## Show in Finder

1. 推出挂载的卷后，File › Show in Finder、工具栏的 Finder、侧边栏 Working Copy 一行的右键与快捷操作都可以点，悬停提示 “spooky-test:<路径>” isn’t mounted on this Mac.；Working Copy 文件右键里已删除的文件仍不可用。
2. 方式是自动查找时点 Show in Finder：sheet 标题 Show in Finder，底栏左侧写 Searching…；没找到时换成 Set Location on This Mac，说明前面先写没有挂载的原因；点 Cancel，设置不变。
3. 方式是 SMB 或 sshfs 挂载时点 Show in Finder：写 Mounting…，挂上后关闭 sheet，打开 Finder 并选中目标；Working Copy 文件右键点时选中那些文件。
4. 挂载失败时换成表单，错误区写出原因与原始输出。
5. 推出卷后点 Show in Finder 重新挂载；退出 App 后再打开仓库，后台重新挂载，不弹任何询问。

## 连接

1. 断开网络后点 Show in Finder：sheet 写 Connecting to “spooky-test”…；恢复网络后连上并继续查找。
2. B 一直连不上时：错误区写出原因与原始输出，底栏只剩 Close。
3. Show in Finder 期间点 Cancel：sheet 关闭，已开始的连接照常完成。

## 仓库管理与最近克隆

1. 仓库管理里右键服务器仓库：Show in Finder、Copy Path 与 Open in Terminal 一组；方式是指定文件夹且文件夹在时，不经连接直接打开；方式是 SMB 挂载时先连接再挂载，不打开仓库。
2. File › Show in Finder 与工具栏的 Finder 作用于选中的服务器书签，一直可以点。
3. 有窗口开着这个仓库时，sheet 结束后那个窗口的连接仍在；没有窗口开着时，sheet 结束后连接关闭。
4. 克隆一个服务器仓库：克隆进行中 Show in Finder 不可用、Copy Path 可用；完成后经右键菜单与行右侧的放大镜按钮各点一次 Show in Finder，需要 sheet 时先关闭弹出框。

## 复制路径

1. 仓库管理、最近克隆与工作树的右键菜单里，本机与服务器仓库都有 Show in Finder 与 Copy Path；文件夹书签不可用；本机仓库的目录不在时 Copy Path 仍可用。
2. 各复制一次，粘贴核对：本机是完整路径，服务器带主机别名。

## 侧边栏、工具栏与图标

1. 侧边栏的 `gone` 分支名称后没有红色图标，悬停提示没有跟踪错误一行；Branches Review 的列表行仍有跟踪错误图标，Tracking Error 筛选仍列出它。
2. 服务器仓库在显示文字与只显示图标两种模式下、按住 ⌥ 前后悬停工具栏各项：提示与本机仓库相同，没有主机前缀；工具栏的主机标识项仍在。
3. 侧边栏的远端分支行是分叉图形，远端行仍是地球；工具栏的 Merge、Rebase 与 Create Branch 在两种显示模式下的图形与大小，VoiceOver 读出各项的标签。
4. Workspace 的 Pull Requests 与 Branches Review，快捷操作里的远端分支、Pull Requests 与 Branches Review，合并冲突与变基冲突时的横幅和 Working Copy 行，Pull Requests 视图的各个空状态，History 的 Autosquash 横幅，都换成新图。

## 展开状态

1. 展开 Branches 里的文件夹与 Tags 分组、收起 `origin` 后：关闭仓库再打开、换到别的仓库再换回来、退出 App 再打开，都保持。
2. 没打开过的仓库照默认：Tags 收起，`origin` 展开。
3. 过滤后清空、拖动悬停展开再结束后，回到记下的状态。
4. 本机与服务器仓库各验一次。

## GitHub 登录

1. Settings › Accounts 选 OAuth 添加 github.com 账号：拿到验证码后浏览器自动打开验证页。
2. 对话框里的按钮写 Copy Code，点了只更新剪贴板，不再打开浏览器；重新认证同样。

## 失效的工作树

本机与服务器仓库各验一次：在终端里把 `moved-tree` 移到 `moved-tree-new`，删掉 `deleted-tree`。

1. 侧边栏的行变淡、右端有告警图标，选中时图标反白；VoiceOver 读出 Worktree Warning；悬停提示与有效时相同，服务器仓库带主机前缀；双击响铃。
2. 右键菜单第二组依次是 Remove Worktree…、Move Worktree…、Repair Worktree…：Move 不可用，Repair 只在失效时列出；快捷操作里没有 Move。
3. 详情写 Worktree is not valid…，下面有 Repair… 与 Remove 两个按钮。
4. Repair…：位置弹出菜单写 None Selected，主按钮不可用；选原来的路径时主按钮不可用，没有说明；选一个不相干的文件夹，看到错误；再选 `moved-tree-new`，修复后行恢复正常。目录面板以 sheet 挂在对话框上。
5. `deleted-tree` 点 Remove：只删登记，`git worktree list` 里没有它。

## 顺带核对

在 Spooky 之外用 Finder 的 Connect to Server 挂载 SMB 共享、在终端里用 sshfs 挂载，方式是自动查找时 Show in Finder 能否找到，结果写进验收记录。

## 清理

```sh
umount "$m23_root/sshfs-mount" 2> /dev/null
m23_ssh "rm -rf '$m23_remote'"
rm -rf "$m23_root"
```

挂上的 SMB 卷在 Finder 里推出。
