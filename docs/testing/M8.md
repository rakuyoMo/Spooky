# M8：仓库管理与系统集成验收

M8 承接 [M7](M7.md)，在本机与服务器仓库上交付以下能力，M1–M7 的验收步骤继续适用：

- 仓库书签的文件夹、排序、改名、移动与失效标记，仓库管理的详情
- 本机新建仓库、在服务器路径初始化仓库、后台克隆与最近克隆、目录扫描，服务器目录的浏览
- 标签页、窗口恢复、启动窗口、后退 / 前进、快捷操作面板与工具栏自定义
- 外部比较与合并工具、Open With、编辑器副本与写回核对
- `spooky://` 链接与 github.com 仓库链接
- 完整的设置页与仓库设置
- Help 菜单、关于窗口、What’s New、诊断报告与崩溃报告
- Sparkle 自动更新、更新通道与发布流程

## 自动验证

在仓库根目录执行：

```sh
mise run swift:lint
mise run build
mise run test
swift build --product Spooky
./scripts/build-app.sh
./scripts/bundle.sh
```

服务器测试默认跳过。`SPOOKY_REMOTE_TESTS=1 swift test` 运行全部服务器回归；只运行 M8 新增的服务器测试：

```sh
SPOOKY_REMOTE_TESTS=1 swift test --filter RemoteHostOperationsTests
```

- `RemoteHostOperationsTests`：在 B 的测试目录里列子目录并标出工作区，新建带中间目录的仓库，扫描找到两个仓库，从 B 上的裸仓库克隆到 B 上的目录，目标已存在时 B 上的 Git 拒绝克隆

测试沿用 `spooky-test`、专用密钥、禁用 PTY 与 agent 转发的配置，每次只在 `/Users/wgy/spooky-test/` 下建立并清理独立目录。

## 准备

### 本机

本机的测试目录放在系统临时目录下，测试结束后删除。Git 只读写这里的一份全局配置：

```sh
m8_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m8.XXXXXXXX")"
mkdir "$m8_root/config"
export GIT_CONFIG_GLOBAL="$m8_root/config/gitconfig"
export GIT_CONFIG_NOSYSTEM=1
git config --global init.defaultBranch main
git config --global user.name 'Spooky Test'
git config --global user.email 'spooky@example.invalid'
git config --global commit.gpgSign false
```

测试仓库：

```sh
# 一个有远端的仓库，远端是测试目录里的裸仓库
git init -q --bare "$m8_root/origin 源.git"
git clone -q "$m8_root/origin 源.git" "$m8_root/本机 app"
git -C "$m8_root/本机 app" commit -q --allow-empty -m 'Start'
git -C "$m8_root/本机 app" push -q origin main

# 扫描用的目录：不同深度各有一个仓库，隐藏目录里的仓库不报告
mkdir -p "$m8_root/scan/a/b" "$m8_root/scan/.hidden"
git init -q "$m8_root/scan/a/第一个"
git init -q "$m8_root/scan/a/b/second"
git init -q "$m8_root/scan/.hidden/skip"
```

### 服务器

服务器上的测试目录只经 `spooky-test` 在 `/Users/wgy/spooky-test/` 下新建，测试结束后删除：

```sh
m8_ssh() { ssh -o BatchMode=yes spooky-test "$@"; }
m8_remote="$(m8_ssh 'umask 077; mkdir -p /Users/wgy/spooky-test && mktemp -d /Users/wgy/spooky-test/m8-app.XXXXXXXX')"
m8_ssh "git init -q --bare '$m8_remote/origin.git' && git init -q '$m8_remote/existing' && mkdir '$m8_remote/plain'"
```

### 启动 App

先退出正在运行的 Spooky，记下偏好域与应用支持目录的状态，验收结束后恢复。App 与它在本机执行的 Git 都只读写上面那份全局配置，Settings › Git Config 显示的文件也是它：

```sh
defaults export com.rakuyo.spooky "$m8_root/preferences.plist" 2> /dev/null || touch "$m8_root/no-preferences"
ditto "$HOME/Library/Application Support/Spooky" "$m8_root/application-support" 2> /dev/null || true

./scripts/build-app.sh
open --env "GIT_CONFIG_GLOBAL=$GIT_CONFIG_GLOBAL" --env GIT_CONFIG_NOSYSTEM=1 .build/Spooky.app
```

`swift run Spooky` 启动的进程不在 App Bundle 里：链接协议没有登记，App 菜单的 Check for Updates… 保持禁用。

## 仓库管理

1. ⌃⌘R 进入仓库管理。底栏 “+” 菜单依次是 New Group；Add Repository…、Add Server Repository…、Create New Local Repository…；Clone Git Repository…；Search for Repositories…。
2. 什么都不选时 Add Repository… 选 `本机 app`：书签加在最外层的最后，名称是目录名。New Group 建出名为 New Group 的文件夹并直接进入改名，改成 `工作 项目`。
3. 把 `本机 app` 拖进 `工作 项目`；再加入 `scan/a/第一个`，拖到 `本机 app` 前面：顺序按拖放的位置保存。右键文件夹的 Sort Child Items by Name 只排这一层；右键书签的 Sort Parent Folder by Name 排它所在的文件夹，名称里的数字按数值比较。重启 App 后文件夹、顺序与展开状态不变。
4. 右键书签的菜单依次是 Open “…”、Open “…” in New Window；Reveal in Finder（服务器仓库是 Copy Path）、Open in Terminal；Rename、Delete “…”…；两种排序。右键文件夹时打开、Finder 与终端几项禁用，删除写作 Delete Group…。多选时只有 Delete N Items…。删除只移除书签，磁盘上的仓库还在。
5. 选中 `本机 app`：右栏头部是图标与名称，下面依次是 Location、Current Branch、Last Commit 与它的时间、Last Opened、Committer Identity、User Description 与 Remotes。远端一行的 View in Browser 在浏览器里打开远端的网页；换算不出网页的地址时按钮禁用。
6. 悬停 User Description 一行点 Edit，改成 `测试 描述`：值随之更新，`.git/description` 是新内容。Committer Identity 的 Edit 写进仓库本地配置，之后出现 Unset；头像菜单列出身份档案，选中后先说明要写的配置项与位置。
7. 在终端里把 `本机 app` 改名为 `本机 app 2`：重新进入仓库管理后书签名称变灰并带警告标记，详情顶部写明 Repository does not exist.；双击打开时窗口换成丢失页，Refresh 重试、Close 回到仓库管理。改回原名后点 Refresh 恢复正常。
8. 什么都不选或选中文件夹时右栏是拖放页：虚线框与 Add、Add Server Repository…、Create、Clone 四个按钮；把 Finder 里的文件夹拖进来添加，把浏览器地址栏的仓库网址拖进来打开预填了地址的克隆对话框。多选时右栏写明选了几项，并有 Delete。
9. 添加一个不是仓库的文件夹：出现 No Git Repository Found，Create Repository 在那里新建仓库并加入书签。

## 新建、克隆与查找

1. Create New Local Repository…：名称含 `/` 或为 `.`、`..` 时提示名称无效；所选位置已有同名的文件时提示；Choose… 的面板里可以新建目录。Create 后书签出现在所选的文件夹里，窗口打开新仓库。
2. Add Server Repository…：主机别名填 `spooky-test`，Browse… 打开 B 上的目录浏览：列表只列子目录，Git 工作区标出 Git repository，Enclosing Folder 按钮与路径栏回车可以跳转，Choose 选定。选 `$m8_remote/plain` 后 Open：体检报告路径不是工作区，下方出现 Create Repository；点按后在 B 上 `git init`，随后照常体检并打开。路径填 `$m8_remote/new/子目录`（不存在）时同样可以新建，中间目录一并建出。
3. ⌃⌘C 打开克隆对话框：Remote URL 填 `$m8_root/origin 源.git`，Clone To 选 This Mac 与目录，下方写明将克隆到的完整路径；展开 Options 有 Use LFS Clone 与 Initialize Submodules。地址以 `-` 开头时提示 Invalid remote URL；本机目标已存在且不是空目录时提示已存在。
4. Clone 后对话框关闭，书签立即出现，行尾显示进度；工具栏出现 Clone 项，点开是 Recently Cloned Repositories：进行中的一行有进度条与停止按钮。克隆完成后行尾的进度消失，书签可以打开。
5. 克隆一个慢的地址并在进度中点停止：这一行写 Cancelled，有 Restart 与 Remove；Restart 再次开始；Remove 移除没有完成的克隆时书签一起删掉。Clear 清除所有不在进行中的克隆。双击还在克隆的书签时，窗口显示 Cloning “…”… 的进度页，完成后在这个窗口打开仓库。
6. 选 Use LFS Clone，在没有安装 Git LFS 的机器上克隆：克隆前失败，说明要在克隆的机器上安装 Git LFS 并执行 `git lfs install`，或者不用 LFS 克隆。
7. 克隆到服务器：Clone To 选 `spooky-test`（没有记住目录时取 B 上的主目录），Browse… 选 `$m8_remote`，地址填 `$m8_remote/origin.git`。克隆在 B 上执行，进度从 stderr 实时回传；之后再选 `spooky-test` 时目录是上次用的 `$m8_remote`。
8. Search for Repositories…：Search In 选 This Mac 与 `$m8_root/scan`，Search 后边找边列出 `第一个` 与 `second`，隐藏目录里的不报告，已有书签的仓库不列出；找到的默认勾选，Add Repositories (N) 加入书签。再选 `spooky-test` 与 `$m8_remote` 查找：结果按机器分组，组名是主机别名；查找在 B 上用 `find` 执行，只在所选目录里进行，Stop 随时停止。

## 窗口与导航

1. ⌘T 在当前窗口所在标签组的末尾加一个显示仓库管理的标签；标签栏的 “+” 同样。File › New Window ⌘N 即使系统设置为总是以标签页打开文稿，也开独立的窗口。同一个仓库已在某个窗口打开时，普通打开切到那个窗口，Open “…” in New Window 另开一个。
2. 在一个窗口里依次切到 History、Stashes、仓库设置与另一个仓库：⌘[ 与 ⌘] 按这个顺序后退、前进，工具栏的后退 | 前进两段随之可用或禁用；从中间的位置去别的视图后，前进的记录作废。
3. Settings › General 的 Window Restoration 选 Always：退出后再启动，窗口、标签组与每个窗口所在的视图都恢复，服务器仓库先连接并体检；选 Never 时启动只开仓库管理；选 System Setting 时按系统设置的 “退出 App 时关闭窗口” 决定，`defaults read com.rakuyo.spooky NSQuitAlwaysKeepsWindows` 读不到这个键。
4. 勾选 Show Quick Start Window on Launch 后重启：启动窗口居中显示，没有标题栏、不能全屏，可以拖背景移动；右栏列出最近打开的仓库，双击或回车打开，任何仓库窗口成为主窗口后它自己关闭。
5. View › Hide Window Title 隐藏所有仓库窗口的标题，菜单项换成 Show Window Title；Hide Toolbar / Show Toolbar 切换工具栏；Customize Toolbar… 打开自定义面板，可以加入 Create Branch、Force Push、Push To、Finder、Terminal、Stage All、Commit，开启 Gerrit 推送后另有 Gerrit Push。Server 与 Clone 两项不能移除，不需要时隐藏。⌃⌘F 进入全屏。
6. View 菜单的分组依次是：Show Repositories；五个主视图与 Show HEAD Branch；Back 与 Forward；三个子菜单；两个 Diff 子菜单；Refresh；窗口标题与工具栏的三项；全屏。
7. Window › Activity ⌃⌘0 汇总所有窗口里各仓库进行中与已完成的操作，详情里的日志可以选择并复制。

## 快捷操作

1. ⇧⌘A 或工具栏的 Quick Actions 在当前窗口的仓库上打开面板；仓库管理里不打开。
2. 输入为空时按种类依次列出：导航（工作区、历史、储藏、分支整理、Reflog 与仓库设置）、分支（HEAD 在前）、工作树、远端、子模块、远端分支、标签、储藏、身份档案、外观与主题。输入后种类的先后不变，同一种类里完全相同、前缀、词首开始的子串、其它子串与散落的字符依次靠后。
3. 输入文件名列出 HEAD 树里的文件，文件名匹配的排在只有路径匹配的前面。输入 5 到 64 位十六进制时只按哈希找那一个提交，其它文字从 HEAD 起按提交信息搜索，最多 100 条。
4. ↩ 执行默认动作；Tab 或光标在末尾时的 → 列出这个对象的全部动作；光标在开头时的 ←、⇧Tab 或 Esc 回到对象列表，Esc 先清空输入，输入为空时关闭面板。动作与菜单、右键菜单的可用性相同，不可用的不列出。提交另有 Open Diff Tool，文件另有 Open with External Editor。服务器仓库没有 Reveal in Finder，换成复制带主机前缀的路径。

## 外部工具

1. Settings › Git Config 的 Diff tool 与 Merge tool 列出支持的工具，没有安装的标出；Perform directory diff 与 Keep backup files for merge conflicts 写进偏好。没有选过工具时第一次使用先弹出 Configure Diff Tool / Configure Merge Tool。
2. 工作区选中改过的文件：Repository › Open Diff Tool ⇧⌘D 比较工作区与 HEAD；Working Copy › Compare ▸ 有 Working Tree to Base ⌃⇧⌘D、Working Tree to Index 与 Index to Base。历史选中一个提交、储藏选中一个储藏时 ⇧⌘D 比较它的全部改动；变更集、文件历史、版本比较与储藏里文件的右键菜单有 Open Diff Tool for “…” at Revision “…”。
3. 冲突向导的 Merge in <工具>（没有选过时是 Choose Merge Tool）启动合并工具：保存并退出后结果写回、暂存并刷新，勾选了保留备份时留下 `<文件>.orig`；没有保存就退出时提示 No Merge Result 并重新读取状态。FileMerge 的命令行先于合并窗口退出，先显示 Finish Merging in FileMerge，保存后选 Done 再写回。服务器仓库的三方内容取到本机的临时目录，结果经 SFTP 写回 B 后再 `git add`。
4. 工作区文件右键的 Open With ▸ 列出能打开它的程序与 Other…。服务器仓库的文件交给 TextEdit 时打开本机副本，每秒检查一次，保存后写回 B；在 B 上另行改动同一文件后再在 TextEdit 里保存：询问是否覆盖，取消时不写回。交给 VS Code 时经 Remote - SSH 直接打开 B 上的文件。
5. 本机仓库的 Reveal in Finder 与 Copy Path 可用；服务器仓库只有带主机前缀的 Copy Path。

## 链接

1. 在终端执行 `open "spooky://open?repository=$(python3 -c 'import urllib.parse,sys; print(urllib.parse.quote(sys.argv[1]))' "$m8_root/本机 app")&view=history"`：打开这个仓库并切到历史。参数换成 `&branch=main` 时显示 main 的历史，换成 `&commit=<哈希>` 时打开这个提交的整页详情。
2. `open 'spooky://open?repository=spooky-test:<$m8_remote 下的仓库路径>&view=stashes'` 连接 B 并打开服务器仓库的储藏。
3. `open 'spooky://clone?url=https://github.com/rakuyoMo/Spooky.git'` 打开预填地址的克隆对话框；克隆仍要用户确认。
4. Settings › Integration 的 Open repositories from github.com 选 Spooky 后，github.com 仓库页的 “Open with GitHub Desktop” 链接打开预填 https 克隆地址的对话框。

## 发布与自动更新

1. `scripts/check-release.sh 1.2` 报版本号格式不对；`scripts/check-release.sh 1.2.0 nightly` 报通道不认识；缺少某种语言的更新说明时一次列出全部缺少的文件；远端已有同名标签时拒绝。`mise run release` 不在 main、工作区有更新说明以外的改动、本地 main 与远端不一致时拒绝。
2. 更新链在一份独立的工作树里验证，测试密钥放在钥匙串的单独账户里，与发布用的密钥分开：

```sh
m8_tools="$PWD/.build/artifacts/sparkle/Sparkle/bin"
m8_update="$m8_root/update"
m8_feed="$m8_root/feed"
m8_plist="$m8_update/Sources/Spooky/Info.plist"

"$m8_tools/generate_keys" --account spooky-update-test
"$m8_tools/generate_keys" --account spooky-update-test -x "$m8_root/update.key"

git worktree add --detach "$m8_update" HEAD
mkdir "$m8_feed"
m8_build="$(/usr/libexec/PlistBuddy -c 'Print :CFBundleVersion' "$m8_plist")"
plutil -replace SUPublicEDKey -string "$("$m8_tools/generate_keys" --account spooky-update-test -p)" "$m8_plist"
plutil -replace SUFeedURL -string 'http://127.0.0.1:8765/appcast.xml' "$m8_plist"

# 旧版留一份原样的副本，每次验证前从它恢复
"$m8_update/scripts/bundle.sh"
ditto "$m8_update/build/Spooky.app" "$m8_root/pristine/Spooky.app"
m8_restore() { rm -rf "$m8_root/old" && ditto "$m8_root/pristine/Spooky.app" "$m8_root/old/Spooky.app"; }

# 打出一版：生成更新清单后把下载地址换成本机的服务，再用测试密钥重签清单
m8_release() {
    plutil -replace CFBundleShortVersionString -string "$1" "$m8_plist"
    plutil -replace CFBundleVersion -string "$2" "$m8_plist"
    mkdir -p "$m8_update/docs/release-notes/$1"

    for language in en zh-Hans zh-Hant ja ko de fr es; do
        printf '### %s\n\n- Update test\n' "$1" > "$m8_update/docs/release-notes/$1/$language.md"
    done

    "$m8_update/scripts/bundle.sh"
    SPARKLE_PRIVATE_KEY="$(cat "$m8_root/update.key")" "$m8_update/scripts/appcast.sh" "$3" ${4:+"$4"}
    cp "$m8_update/build/updates/Spooky-$1.zip" "$m8_feed/"
    sed -E 's#https://github.com/rakuyoMo/Spooky/releases/download/v[0-9.]+/#http://127.0.0.1:8765/#' \
        "$m8_update/build/updates/appcast.xml" > "$m8_feed/appcast.xml"
    "$m8_tools/sign_update" --ed-key-file="$m8_root/update.key" "$m8_feed/appcast.xml"
}

m8_release 0.8.1 "$((m8_build + 1))" stable
```

在另一个终端里执行 `python3 -m http.server 8765 --bind 127.0.0.1 --directory "$m8_feed"`，再依次核对：

1. `m8_restore` 后用 `open --env "GIT_CONFIG_GLOBAL=$GIT_CONFIG_GLOBAL" --env GIT_CONFIG_NOSYSTEM=1 "$m8_root/old/Spooky.app"` 启动旧版。Check for Updates… 找到 0.8.1，显示系统语言的更新说明；安装后 App 重启，About Spooky 显示 0.8.1 与加 1 的构建号。
2. 退出 App 后 `m8_restore`，`printf x | dd of="$m8_feed/Spooky-0.8.1.zip" bs=1 seek=4096 conv=notrunc` 改掉安装包的一个字节：下载后签名校验失败，不安装，About 仍是 0.8.0。把 `$m8_update/build/updates/Spooky-0.8.1.zip` 拷回 `$m8_feed`。
3. 在 `$m8_feed/appcast.xml` 里改动任意一个字符而不重签：更新器拒绝这份清单。再执行一次 `sign_update` 恢复。
4. 停掉 HTTP 服务后 Check for Updates…：提示框的说明是原始的网络错误，当前安装不变。
5. 重新启动 HTTP 服务，执行 `m8_release 0.8.2 "$((m8_build + 2))" beta "$m8_feed/appcast.xml"`，清单里有 beta 通道的 0.8.2 与稳定版 0.8.1。`m8_restore` 后启动旧版：Release channel 为 Stable 时找到的是 0.8.1；换成 Beta 或 Development 后找到 0.8.2。

## 服务器差异

1. 第一次添加服务器仓库时的体检：B 的非交互环境找不到 Git 时，错误详情写出 B 上非交互 shell 的 PATH；仓库在 B 上受隐私保护的目录里（如 “文稿” “桌面” “下载”）、B 没有给远程登录完全磁盘访问权限时，错误写明是隐私设置阻止，与文件权限无关；B 的非交互环境设置了 GIT_ 变量时，体检通过后先提示这些变量名，再打开仓库。
2. 服务器仓库的未跟踪文件达到 1,000 个时，工作区文件列表上方出现提示：建议补充忽略规则，Speed Up… 列出 `core.untrackedCache`、`core.fsmonitor` 与 commit-graph 三项的作用；Apply Settings 后才写进 B 上这个仓库的本地配置并写出 commit-graph，取消时不改动；关闭提示后这个仓库不再提示。
3. 服务器上的克隆、扫描、目录浏览与初始化都可以取消，取消不算失败，也不会自动重试；在 B 上用 `pgrep -f "$m8_remote"` 确认进程已经结束。
4. 服务器仓库的 Open in Terminal 在 A 上经 `ssh -t` 进入远端路径；外部工具都在 A 上启动，不在 B 上启动 A 的程序。
5. 在服务器仓库完成克隆或扫描 → 打开 → 外部比较工具与终端 → 关闭 → 重启后按窗口恢复回到同一个仓库与视图。

## 实现说明

- 书签存在偏好 `repositoryBookmarks`，第一次启动时把旧版本的最近记录迁移成同样顺序的书签；打开成功的仓库自动加入书签并记下打开时间；仓库管理只在后台检查本机书签，服务器书签在选中或打开时才连接。
- 新建、克隆、扫描与目录浏览在仓库存在之前进行：服务器的经主机连接在 B 上执行，与工作区连接一样只用自己的 ControlMaster；本机与服务器执行同一份脚本。目录浏览经主连接在 B 上用 Perl 列出子目录。扫描用 `find -H` 不跟随符号链接、跳过隐藏目录，找到的仓库内部不再报告其它仓库。
- 克隆执行 `git clone --progress [--recurse-submodules] -- <地址> <目标>`；选 LFS 时先确认目标机器上有 Git LFS 且登记了过滤器。本机克隆失败或取消时删掉这次新建的目录。每台主机记住的克隆目录存在偏好 `serverCloneDirectories`。
- 视图引用写成 `repository?location=<位置>&view=…`，服务器位置写 `<主机别名>:<远端路径>`；窗口恢复把它存进窗口的恢复状态。链接 `spooky://open` 的仓库位置写在 `repository`，视图参数与视图引用相同。
- 仓库设置只写仓库本地配置；`spooky.commitbodylimit`、`spooky.commitshowsguide` 覆盖 Editor 页的折行，Issue 追踪写 `spooky.issuetrackertemplate` 与 `spooky.issuenumberprefix`。
- 崩溃报告在启动时检查上次处理之后的 `Spooky-*.ips`，处理过的最新时间记在偏好 `lastHandledCrashReport`；第一次启动只记下时间，不提示安装前的报告。预填的正文最长 6,000 字符。
- 更新清单在 `https://github.com/rakuyoMo/Spooky/releases/latest/download/appcast.xml`；App 只接受签名的清单（`SURequireSignedFeed`），解压前校验更新包的签名（`SUVerifyUpdateBeforeExtraction`）。
