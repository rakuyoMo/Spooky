# M25 全量验收

范围：按 M1–M24 的需求逐项验收，覆盖本机、服务器、协作、系统与错误五组手动矩阵，性能、资源与安全检查，以及发布前检查。各里程碑的验收步骤继续适用；本文只写五组端到端的走法与全量检查的命令。

所有命令在仓库根目录执行。界面验收需要已解锁、显示器正常显示的 macOS 会话；深色与浅色外观各验一遍。

## 自动验证

```sh
mise run swift:lint
mise run build
mise run test
swift build --product Spooky
./scripts/build-app.sh
```

默认关闭的测试按 [测试](README.md) 的 “显式开启的测试” 逐组开启：

```sh
SPOOKY_REMOTE_TESTS=1 swift test --no-parallel
SPOOKY_PERFORMANCE_TESTS=1 swift test -c release -Xswiftc -enable-testing --filter PerformanceTests
SPOOKY_GITHUB_TESTS=1 SPOOKY_GITHUB_TOKEN=<令牌> SPOOKY_GITHUB_REPOSITORY=<owner/repo> swift test --filter GitHubLiveTests
```

- 默认测试里经辅助功能接口读窗口的几项，只在运行测试的进程有辅助功能权限时运行；全量验收时要确认它们实际运行，而不是跳过
- 服务器测试要求服务器的非交互 `PATH` 里有 `git-lfs`；没有时 LFS 一组如实报出找不到

## 准备

测试仓库都以 `m25-` 开头。本机仓库建在临时目录里，服务器仓库建在 B 的 `/Users/wgy/spooky-test/` 下新建的测试目录里，远端都指向同一测试目录里的裸仓库：

```sh
m25_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m25.XXXXXX")"
m25_ssh() { ssh -o BatchMode=yes spooky-test "$@"; }
m25_remote="$(m25_ssh 'umask 077; mkdir -p /Users/wgy/spooky-test && mktemp -d /Users/wgy/spooky-test/m25-app.XXXXXXXX')"
m25_ssh git init -q --bare -b main "$m25_remote/remote.git"

export GIT_CONFIG_GLOBAL="$m25_root/gitconfig"
git config --global init.defaultBranch main
git config --global user.name 'Spooky Test'
git config --global user.email 'spooky@example.invalid'
```

启动 App 按 [M12](M12.md) 的 “启动 App” 进行。

## 本机

1. 没有书签时启动，看到仓库管理的空状态。
2. 用 ⌘O 打开一个仓库，用 Create New Local Repository… 新建 `m25-local`，用 Clone Git Repository… 克隆 `spooky-test:$m25_remote/remote.git`。
3. 在 `m25-local` 新建、修改与删除文件：Working Copy 列出三种状态，选中后右侧显示 Diff；在 Diff 里选几行暂存，再撤回其中一行。
4. 写提交信息提交：History 出现新提交，详情与变更集和刚才的改动一致。
5. 新建分支与标签并检出：侧边栏、工具栏与窗口标题一起变化。
6. 加上 `origin`，首次 Push 时发布分支；在克隆的仓库里提交并推送，再在 `m25-local` 里 Fetch 与 Pull：领先 / 落后的计数随之变化。
7. 改一个文件后储藏，工作区变干净；应用储藏后改动回来，储藏列表按选择保留或删掉。
8. 添加子模块、新建工作树，跟踪一个 LFS 文件并推送：侧边栏的子模块与工作树都能打开，LFS 文件在 Diff 里显示指针以外的内容。
9. 托管账号的 Pull Request 列表与检出见 “协作”。

## 服务器

1. 在仓库管理里添加服务器仓库：主机别名填 `spooky-test`，路径选测试目录里的工作区；连接体检通过后窗口打开。
2. 在 B 上改文件：前台约 2 s 内 Working Copy 更新；选中后读出 Diff，图片与大文件同样显示。
3. 暂存、提交、看历史与分支，Fetch、Pull、Push 到测试目录里的裸仓库；每一步都用 `ssh spooky-test git -C <路径> …` 在 B 上核对结果。
4. 只结束 Spooky 为 `spooky-test` 建立的 SSH 主连接：窗口显示断开，写操作不可用；点重连后恢复，状态与断开前一致。
5. 用慢的 `uploadpack` 让获取停在中途，从活动区停掉：B 上没有遗留的 Git 进程，仓库状态不变。
6. 经仓库管理在 B 上克隆、扫描测试目录：新仓库出现在列表里。
7. 在服务器仓库里添加子模块、新建工作树，B 的非交互 `PATH` 里有 `git-lfs` 时跟踪并推送一个 LFS 文件。

## 协作

GitHub、GitLab.com 与私有部署 GitLab 各用一个隔离的测试项目，本机与服务器仓库各走一遍：

1. 在 Settings › Accounts 登录。
2. 推送一个分支后新建 Pull Request / Merge Request，打开详情查看说明、提交与改动。
3. 发表评论、修改标题或说明，刷新后看到更新。
4. 检出它：本机与服务器仓库都切到对应分支。
5. 合并或关闭，列表随之更新；GitLab 记下实例的版本与不支持的能力。

## 系统

1. 用 `-AppleLanguages` 依次以八种支持语言与一种不支持的语言启动：仓库管理、仓库窗口、设置与一个对话框都显示对应语言，不支持的语言显示英文，没有资源键泄漏。
2. 浅色与深色下各看一遍仓库窗口、设置与对话框。
3. 把仓库窗口缩到最小宽度、再进入全屏：分栏、工具栏与横幅都完整，没有被截掉的按钮。
4. 打开 VoiceOver，在仓库管理、侧边栏、文件列表、提交区与一个对话框里逐项移动：每项都读出名称与状态；只用键盘完成一次暂存与提交。
5. 用 Quick Actions 搜索并执行一个仓库操作；打开 Activity 窗口，看到刚才的操作记录。
6. 用 Open in Terminal 在默认终端与 Otty 里打开仓库目录，用 Show in Finder 与外部工具打开文件。
7. 用 `open 'spooky://…'` 打开仓库与视图；退出后重启，窗口、视图与选中都恢复。

## 错误

1. 让 Git 版本不足、路径不存在、目录没有读权限：各自显示对应的错误与恢复说明。
2. 用不在 `~/.ssh/config` 里的别名连接：显示连不上的错误；指纹异常与认证失败以 `RemoteConnectionTests` 为证，不改双方的 SSH 配置与 `known_hosts`。
3. 在没有 upstream 的分支上 Pull、在落后的分支上 Push：分别提示设置上游与推送被拒绝。
4. 让 `pre-commit` 钩子以非零退出：提交失败，Git 原文保持不变，提交信息保留。
5. 解析失败、超时与取消以自动测试为证；远端写操作期间断线见 “服务器” 第 4 步。

## 性能、资源与安全

1. 用 `mise run bundle` 生成的发布 Bundle 打开本机的代表性仓库与 `spooky-test` 上的仓库：首屏状态分别在 2 s 与 5 s 内出现。
2. 打开一个有 6 万个提交的仓库并滚动 History，Activity Monitor 里的内存稳定在 512 MB 以内。
3. 成功、失败、取消与退出之后，`lsof -p <pid>` 里没有遗留的 Git 进程、SSH 会话与临时文件；B 上 `/tmp` 里没有本次会话的目录。
4. 会话目录、控制 socket 与中继 socket 所在的目录都是 0700。
5. 生成诊断报告，在错误框与 Activity 的输出里搜索口令、私钥、令牌与环境变量：都没有出现。

## 发布检查

```sh
mise run bundle
codesign --verify --deep --strict build/Spooky.app
plutil -extract CFBundleIdentifier raw build/Spooky.app/Contents/Info.plist
```

- 生成 `build/Spooky.app`，签名校验通过，Bundle ID 为 `com.rakuyo.spooky`，版本为 Info.plist 里的版本
- 完整构建只输出已审计的 `#warning`；`swift run Spooky` 启动后完成一次本机冒烟
