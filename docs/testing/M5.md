# M5：集成验收与稳定化

M5 承接 [M1](M1.md)、[M2](M2.md)、[M3](M3.md) 和 [M4](M4.md)，不新增功能入口：把本机与服务器仓库的核心闭环收敛为可长期运行、可恢复、可打包发布的 App。

## 自动验证

在仓库根目录执行：

```sh
swift build --package-path SpookyKit
swift test --package-path SpookyKit
swift build --package-path SpookyKit --product Spooky
./scripts/build-app.sh
./scripts/bundle.sh
```

服务器与性能测试默认跳过，需要显式开启：

```sh
# 全部服务器回归，包括 M2–M4 的连接、提交、历史、同步与取消
SPOOKY_REMOTE_TESTS=1 swift test --package-path SpookyKit

# 本机大仓库性能，使用发布构建
SPOOKY_PERFORMANCE_TESTS=1 swift test --package-path SpookyKit -c release -Xswiftc -enable-testing --filter PerformanceTests

# 服务器大仓库性能
SPOOKY_PERFORMANCE_TESTS=1 SPOOKY_REMOTE_TESTS=1 \
    swift test --package-path SpookyKit -c release -Xswiftc -enable-testing --filter PerformanceTests
```

M5 新增的自动测试覆盖：

- 固定 Git 输出夹具（`Tests/SpookyKitTests/Fixtures/`）：status 的上游计数、重命名、冲突、删除、中文与引号路径和 NFD 文件名；diff 的多块、末尾无换行、按行补丁、二进制与重命名；SHA-1 / SHA-256 的 log；引用；fetch 与 push 的 porcelain 输出。
- 核心写操作闭环：SHA-1 与 SHA-256 临时仓库各走一遍状态 → Diff → 按行暂存 → 提交 → 历史 → 建分支 → 首次发布 → 另一工作区推送 → 获取 → 显式合并拉取 → 推送。
- 资源释放：取消先发 TERM，2 秒宽限期后发 KILL，Git 有机会清理锁文件；成功、失败、取消三条路径都释放文件描述符和本机凭据会话目录。
- 读取缓存：只由对象哈希决定的结果按字节和条目数淘汰最久未使用的记录，同一查询只启动一次 Git；只计算哈希的 `hash-object` 按读取调度。
- App 状态：同一仓库同一时间只有一个写操作；切回仓库恢复视图状态，每个窗口最多缓存 15 个仓库；刷新进行中的完整刷新请求不会丢失；退出等待任务结束并释放写锁；菜单、工具栏与右键菜单共用同一套可用性规则。
- 错误呈现：连接断开、Git 失败、输出解析失败、用户取消、版本不支持和仓库条件分别归类；写入中途断线提示先核对，写操作失败使用写入的恢复说明；错误与原文不含进程环境变量；中断写入的核对报告；窗口位置与分栏宽度的恢复校验；Activity 输出与数量上限。
- 资源完整性：各支持语言的资源键与格式参数一致，Swift 界面引用的资源键全部存在；界面源码不写死颜色数值。

## 准备本机测试仓库

工作区、裸仓库、第二个工作区和另一个仓库都放在同一个临时目录。提交身份只写入测试仓库：

```sh
m5_directory="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m5.XXXXXX")"

m5_git() {
    env GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null GIT_CONFIG_NOSYSTEM=1 \
        /usr/bin/git "$@"
}

m5_identity() {
    m5_git -C "$1" config --local user.name "$2"
    m5_git -C "$1" config --local user.email spooky@example.invalid
    m5_git -C "$1" config --local commit.gpgSign false
}

m5_git init -q --bare -b main "$m5_directory/remote.git"
m5_git -c init.templateDir= init -q -b main "$m5_directory/workspace"
m5_identity "$m5_directory/workspace" 'Spooky Test'
printf 'alpha\nbravo\ncharlie\n' > "$m5_directory/workspace/notes.txt"
m5_git -C "$m5_directory/workspace" add notes.txt
m5_git -C "$m5_directory/workspace" commit -q -m 'Initial notes'
m5_git -C "$m5_directory/workspace" remote add origin "$m5_directory/remote.git"
m5_git -C "$m5_directory/workspace" push -q -u origin main
printf 'alpha\nbravo\ncharlie\none\ntwo\nthree\n' > "$m5_directory/workspace/notes.txt"

m5_git clone -q "$m5_directory/remote.git" "$m5_directory/other"
m5_identity "$m5_directory/other" 'Other Test'

m5_git -c init.templateDir= init -q -b main "$m5_directory/second"
m5_identity "$m5_directory/second" 'Spooky Test'
printf 'second\n' > "$m5_directory/second/readme.txt"
m5_git -C "$m5_directory/second" add readme.txt
m5_git -C "$m5_directory/second" commit -q -m 'Second repository'
```

## 本机 App 闭环

1. 从干净的构建目录编译并启动，进入仓库管理的空状态：

```sh
swift build --package-path SpookyKit --scratch-path "$m5_directory/build"
"$m5_directory/build/out/Products/Debug/Spooky"
```

2. 首次启动的窗口内容区为 1000 × 540，侧边栏宽 260 pt；侧边栏上方的两个按钮完整显示，没有挤进溢出菜单。
3. ⌘O 打开 `workspace`。选中 `notes.txt` 查看 Diff，只选新增的第一、三行暂存；文件显示为部分暂存，Diff 中只剩第二行。填写标题与正文提交，再暂存剩余改动提交一次，确认工作区干净。
4. ⌘2 查看历史，选中最新提交核对变更集；⌘B 新建并检出 `topic/smoke`。每次写入完成后，工作区、历史、侧边栏分支与工具栏同时更新。
5. 选择 Publish Branch 发布到 `origin`。然后在第二个工作区推送一个提交：

```sh
m5_git -C "$m5_directory/other" fetch -q origin
m5_git -C "$m5_directory/other" checkout -q -B topic/smoke origin/topic/smoke
printf 'remote update\n' > "$m5_directory/other/remote.txt"
m5_git -C "$m5_directory/other" add --all
m5_git -C "$m5_directory/other" commit -q -m 'Other workspace update'
m5_git -C "$m5_directory/other" push -q origin topic/smoke
```

6. 在 App 中 Fetch，确认落后 1；以 merge 拉取后落后归零。再在本机提交一次并 Push，领先与落后都归零，裸仓库的 `topic/smoke` 指向本机 HEAD。
7. ⌃⌘0 打开 Activity，核对每个同步操作的状态与原始输出。窗口首次以 551 × 299 打开，调整后的位置与尺寸在下次打开时沿用。
8. 构造 Git 失败：

```sh
m5_git -C "$m5_directory/workspace" remote add broken "$m5_directory/missing.git"
```

   向 `broken` 推送，错误 sheet 显示标题、写操作的恢复说明、“类别：Git 命令失败” “仓库：<路径>” 与可选择复制的原始输出和退出码；“刷新” 重新读取仓库。完成后删除这个远端。
9. 写入一个必定失败的 `pre-commit` 钩子后提交，确认错误显示钩子输出，提交信息草稿保留；删除钩子后可以直接重试。
10. ⌘N 打开第二个窗口并打开同一仓库。一个窗口执行写操作期间，另一个窗口的写入口禁用；完成后两个窗口都显示新状态。重复点击提交、推送按钮不会产生第二次写操作。
11. 在历史中选中一个提交、在提交区留下未提交的标题，然后打开 `second` 再切回 `workspace`：恢复历史视图、所选提交和标题草稿；`second` 没有远端，Fetch / Pull / Push 三段都禁用。
12. 调整窗口位置与尺寸、侧边栏和列表宽度后 ⌘Q 退出再启动：窗口位置尺寸与各分栏宽度恢复，最近记录包含两个仓库。删除 `second` 后再次启动，记录保留并标记为不可用。
13. 退出后写入损坏的分栏记录与屏幕外的窗口位置，再启动验证恢复失败的回退：

```sh
defaults write com.rakuyo.spooky "NSSplitView Subview Frames Spooky.Repository" -array \
    "0.000000, 0.000000, 1000.000000, 540.000000, NO, NO" \
    "1001.000000, 0.000000, 0.000000, 540.000000, NO, NO"
defaults write com.rakuyo.spooky "NSWindow Frame Spooky.RepositoryWindow" "5000 100 1000 540 0 0 1470 923 "
```

   窗口完整出现在屏幕内；打开仓库后侧边栏回到 260 pt，工作区列表 400 pt、历史列表 320 pt。拖动得到的宽度不受影响。
14. ⌘Q 退出，确认进程正常结束，没有遗留由 Spooky 启动的 `git` 子进程。

## 服务器 App 闭环

按 [M2](M2.md#准备-app-测试仓库) 建立本次测试子目录，只使用 `spooky-test` 和 `~/.ssh/spooky-test_ed25519`。裸仓库与第二个工作区都放在同一次 `/Users/wgy/spooky-test/` 子目录内。

1. 添加服务器工作区，重复本机闭环的第 3–6 步与第 11 步；标题、错误、Activity 和复制的路径都带主机前缀。
2. 前台每 2 秒、后台每 10 秒轮询；轮询只读状态和所选文件的内容哈希，有变化才读取其它内容。窗口重新激活后立即刷新一次。
3. 发起 Push 后仅对本次 Spooky 的专属主连接执行 `ssh -S <该路径> -O exit -- spooky-test` 模拟断线：写入不重试，断线期间写入口禁用。重连后完整刷新并显示核对报告：HEAD 已变化时说明操作可能已经完成，未变化时提示先检查工作区；报告同时列出当前分支、改动数、暂存区锁、合并与变基状态。没有新的核对结果时，报告写入没有在服务器上开始。
4. 运行中的 Fetch 在 Activity 中取消：远端进程组先收到 TERM，2 秒后收到 KILL，取消确认后控件恢复可用；无法确认时提示并保持禁用写入。
5. 关闭最后一个显示该仓库的窗口或退出 App，确认专属主连接与会话目录被清理，用户的其它 SSH 连接保持可用。
6. 按下文性能方法测量服务器首屏，目标 5 秒以内。关闭测试工作区后，清理本次创建的服务器子目录。

## 入口与禁用规则核对

同一动作的菜单、工具栏、右键菜单与拖放共用 `RepositorySession` 的 `can…` 规则；没有仓库、正在写入、连接不可写或缺少前提时一起禁用，文案一致。

| 动作 | 菜单与快捷键 | 工具栏 | 右键与拖放 |
|---|---|---|---|
| Fetch | Repository → Fetch ⇧⌘F、Fetch All Remotes | 同步组第一段 | 远端分组右键 |
| Pull | Repository → Pull ⇧⌘P | 同步组第二段 | 工作区行、远端分支右键；远端分支拖到 HEAD |
| Push | Repository → Push ⇧⌘U | 同步组第三段 | 工作区行、本地分支右键；本地分支拖到远端分支 |
| Publish Branch | Repository → Publish Branch | — | 工作区行、本地分支右键；本地分支拖到远端 |
| Merge | Working Copy → Merge ⇧⌘M | Merge | 工作区行、分支右键；本地分支拖到 HEAD |
| 新建分支 | Repository → Create Branch ⌘B | — | 侧边栏 “+”、分支与提交右键；本地分支或提交拖到 Branches |
| 跟踪远端分支 | — | — | 远端分支右键；远端分支拖到 Branches |
| 检出 | Working Copy → Check Out Branch ⇧⌘B | — | 双击分支、本地分支右键 |
| 删除分支 | — | — | 本地分支右键、多选右键，始终确认 |
| 暂存 / 取消暂存 | Working Copy → Stage、Unstage；Stage All ⇧⌘E、Unstage All ⌥⇧⌘E | Stage All，按住 ⌥ 切换 | 文件右键、勾选框、Diff 块与行 |
| 丢弃 | Working Copy → Discard Changes ⇧⌘⌫、Discard All Changes… | — | 文件右键、工作区行右键、Diff 块与行，始终确认 |
| 提交 | Working Copy → Commit ⇧⌘C | Commit | 提交区按钮 |
| 刷新 | View → Refresh ⌘R | Refresh | — |
| 在终端中打开 / 在 Finder 中显示 | File → Open in Terminal、Reveal in Finder | Terminal、Finder | 工作区行与最近记录右键；服务器仓库禁用 Finder |

## 性能

验收目标：本机仓库打开后 2 秒内显示首屏状态，服务器仓库在同一局域网 SSH 链路下 5 秒内显示；App 稳态内存不超过 512 MB。

- `PerformanceTests` 在临时目录生成 10 万个文件、5 万个提交的仓库，其中 2,000 个已修改的跟踪文件和 1,000 个未跟踪文件。
- 首屏时间与打开仓库相同：检查 Git 版本、识别工作区，再读取并解析状态。
- 历史按界面的分页逐页读到 5 万个提交的加载上限，测试期间持有全部结果，再测量进程物理内存的增量。
- 历史达到上限后不再续载，并提示选择分支缩小范围；单个 Activity 每路输出只保留最近 512 KiB，Activity 最多保留 200 条记录。
- 必须使用发布构建测量；调试构建的数字不能作为验收结果。

## 实现说明

- 写操作统一经 `RepositorySession.performGit` 发起：同一仓库在整个 App 中只有一个活动写操作；写入完成后，显示该仓库的所有窗口执行完整刷新。
- 本机仓库由 FSEvents 触发刷新；服务器轮询只读状态和所选文件的内容哈希，有变化才读取身份、引用、历史与 Diff。写入完成、重连、窗口重新激活和手动刷新时执行完整刷新。
- 历史分页、提交变更集与补丁、双向计数等只由对象哈希决定的结果进入 64 MiB、4,096 条的进程内缓存。
- 错误界面包含标题、类别与仓库位置、恢复说明和可选择复制的原始输出；内嵌错误与错误 sheet 使用同一份内容。
- 取消子进程先发 TERM，2 秒后发 KILL；退出 App 时最多等待 10 秒，让读取、写入与子进程结束，再关闭 Spooky 的专属主连接。
- 窗口使用 frame autosave；外层侧边栏、工作区列表、历史列表分别保存宽度。记录不可用时回到默认的 1000 × 540 窗口、260 pt 侧边栏、400 pt 工作区列表与 320 pt 历史列表。
- 每个窗口按最近使用顺序缓存 15 个仓库的视图、选择和提交草稿；视图状态无法恢复时回到 Working Copy。
