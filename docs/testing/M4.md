# M4：历史、分支与同步验收

M4 承接 [M1](M1.md)、[M2](M2.md) 和 [M3](M3.md)。本机和服务器使用相同的历史、引用与同步服务；服务器工作区始终留在 B。

## 自动验证

在仓库根目录执行：

```sh
swift build --package-path SpookyKit
swift test --package-path SpookyKit
swift build --package-path SpookyKit --product Spooky
./scripts/build-app.sh
```

远端测试默认跳过，显式启用全部回归：

```sh
SPOOKY_REMOTE_TESTS=1 swift test --package-path SpookyKit
```

只运行 M4 服务器场景：

```sh
SPOOKY_REMOTE_TESTS=1 swift test --package-path SpookyKit --filter RemoteHistorySyncTests
```

自动测试覆盖：

- 历史：空仓库、根提交、合并提交、Unicode 作者、长标题、正文控制字符、固定根分页、SHA-1 / SHA-256 和损坏格式。
- 提交详情：二进制统计、含换行和通配符的路径、重命名、第一父比较、大 Diff 警告与补丁加载。
- 引用：未出生分支、分离 HEAD、跟踪分支、双向计数、引用名规范化、检出保护和未合并删除。
- 同步：首次发布、获取、显式 merge / rebase、推送拒绝、无上游、缺失远端，以及合并预览的冲突和不可用状态。
- 传输：真实 Git 配合受控 SSH 程序验证认证失败、超时和连接中断；流式日志、排队取消和仓库写槽释放。
- 凭据：临时加密私钥、独立测试 SSH agent、socket 口令回调，以及日志和结果脱敏。
- App 状态：取消后恢复可写、Activity 保留结果、工作区与引用刷新、历史两侧归属、关闭仓库后的过期请求隔离。
- 五语资源键、格式参数和命名色资源完整性。
- B 上的历史、分支、首次发布、两种拉取、推送、运行中取消和仅关闭 Spooky 专属主连接后的恢复。

## 本机 App 闭环

准备独立的工作区和裸仓库。所有提交身份只写入测试仓库：

```sh
m4_directory="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m4.XXXXXX")"
mkdir -p "$m4_directory/workspace"

m4_git() {
    env GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null GIT_CONFIG_NOSYSTEM=1 \
        /usr/bin/git "$@"
}

m4_git -c init.templateDir= init -q -b main "$m4_directory/workspace"
m4_git -C "$m4_directory/workspace" config --local user.name 'Spooky Test'
m4_git -C "$m4_directory/workspace" config --local user.email spooky@example.invalid
m4_git -C "$m4_directory/workspace" config --local commit.gpgSign false
m4_git init --bare "$m4_directory/remote.git"
m4_git -C "$m4_directory/workspace" remote add origin "$m4_directory/remote.git"
printf 'first\nsecond\nthird\n' > "$m4_directory/workspace/你好 [draft].txt"
```

1. 实际启动 `swift run --package-path SpookyKit Spooky`，截图核对管理页。⌘O 打开测试工作区，按 M3 完成查看 Diff、按行暂存、填写信息和提交；再提交剩余改动，确认工作区干净。
2. ⌘2 查看历史。核对根提交的哈希、作者、日期和引用；选择后查看完整信息、展开文件 Diff。⌘C 应复制完整哈希。双击进入左文件列表、右 Diff 的详情页，再返回历史。
3. ⌘B 新建 `topic/test`，核对起点、跟踪和创建后检出。输入空白、非法字符、已有名称，确认实时规范化和错误状态。创建后确认 HEAD、工作区与历史同步更新。
4. 在终端修改测试文件，再从 App 暂存、提交。选择 Publish Branch，指定 `origin`、目标 `topic/test`，勾选跟踪。提交表单后立即关闭 sheet，Activity 持续追加输出；成功后上游与 ahead / behind 更新。
5. 在第二个测试工作区更新远端：

```sh
m4_git clone -b topic/test "$m4_directory/remote.git" "$m4_directory/other"
m4_git -C "$m4_directory/other" config --local user.name 'Other Test'
m4_git -C "$m4_directory/other" config --local user.email other@example.invalid
m4_git -C "$m4_directory/other" config --local commit.gpgSign false
printf 'remote update\n' > "$m4_directory/other/remote.txt"
m4_git -C "$m4_directory/other" add --all
m4_git -C "$m4_directory/other" commit -m 'Other workspace update'
m4_git -C "$m4_directory/other" push origin topic/test
```

6. 在 App Fetch，核对远端分支、落后数与历史未拉取标记；选择 Pull，分别验证 merge 与 rebase 两种显式策略。形成两侧各一个提交时，未推送和未拉取标记应各自正确。再 Push，核对裸仓库结果。
7. 创建另一条分支，在不同文件提交后切回当前分支。打开 Merge，核对预览、压缩、总是生成合并提交、直接提交、验证签名和跳过钩子选项；执行成功后四处快照一致。
8. 对同一文件构造冲突。预览应显示冲突；执行后复用 M3 的冲突横幅、采用一侧、标记解决、继续提交与中止。预览不可用时不能显示为可干净合并。
9. 保留未提交改动并尝试检出会覆盖该文件的分支，确认 Git 原文可复制且文件不变。删除未合并分支时先确认，再显示普通删除失败，不能强制删除。
10. 关闭仓库，确认回到管理页。按 M1 验证窗口复用、刷新、错误恢复和最近记录；按 M2 验证终端、主机前缀与主题。

## 历史、入口与状态核对

| 功能 | 入口与快捷键 | 核对内容 |
|---|---|---|
| 主视图 | ⌘1 / ⌘2 / ⌘0 | 工作区、全部历史、当前 HEAD；侧边栏选择保持一致 |
| 新建分支 | ⌘B、底部 “+”、分支和提交右键 | 起点预填、名称校验、跟踪与创建后检出 |
| 检出 | 双击本地 / 远端分支、⇧⌘B | 远端新建或复用跟踪分支；同名冲突打开表单 |
| 删除 | 本地分支右键、多选右键 | 始终确认，当前分支禁用，未合并删除失败 |
| Fetch / Pull / Push | 工具栏、Repository 菜单、右键 | ⇧⌘F / ⇧⌘P / ⇧⌘U，空远端和断线时禁用 |
| Merge | 工具栏、Working Copy 菜单、分支右键 | ⇧⌘M；预览随目标变化取消旧请求 |
| Activity | 侧边栏活动行、Window 菜单 | ⌃⌘0；进行中、完成、失败、取消与原始日志 |
| 提交图 | 列表头、View → History | ⌃⌘G；24 / 46 pt 行高；分页连线连续 |
| 变更集 | 文件展开、View → Diffs in Changeset | ⌃⌘→ / ⌃⌘←；自动展开阈值；大 Diff 放行只作用当前文件 |
| 拖放 | 分支 / 提交 → Branches；分支 → HEAD / 远端 | 悬停显示动作，落下打开对应表单，跨仓库与不支持的组合拒绝 |

分页使用至少 101 个提交验证滚动续载、取消、重试与选择保留；加载期间新增提交后刷新，确认没有重复或漏页。空仓库、空远端、分离 HEAD、多选提交与无选择分别检查空状态。

在深浅外观和 `en`、`zh-Hans`、`zh-Hant`、`ja`、`ko` 下截图核对文字、徽标与对话框。使用 Tab 和 VoiceOver 检查提交行、文件、名称输入、错误正文、预览与取消按钮。M3 的 ⌥ 暂存 / 修补变体继续工作；M4 的 Quick 同步变体按需求由 M7 交付。

## 实现说明

- 历史字段使用 NUL 分隔，支持动态哈希长度；引用一次 `for-each-ref` 读取，ahead / behind 使用结构化 `rev-list --left-right --count`。
- Fetch 使用 porcelain；Pull 拆成 Fetch 与显式 merge / rebase；Push 使用 porcelain 和明确的目标 refspec。
- 合并预览使用 `merge-tree --write-tree`；预览失败保持未知状态，执行前要求工作区干净。
- 本机和服务器凭据均可通过应用回调输入；服务器的凭据请求经既有 SSH 中继回到 A。
- M4 不提供强制删除、强推、自动储藏、同步按钮或 Quick 同步变体，对应完整能力由后续里程碑交付。
