# M15 Diff 与文本验收

范围：语言识别、语法记号与主题颜色。

所有命令在仓库根目录执行。界面验收使用临时仓库，需要已解锁、显示器正常显示的 macOS 会话。

## 自动验证

```sh
mise run swift:lint
mise run build
mise run test
swift build --product Spooky
./scripts/build-app.sh
```

- `SyntaxHighlighterTests`：完整文件名与扩展名、头文件语言、20,000 个字符边界、全部语言自动识别、非法记号回退、Diff 两侧独立识别、语法颜色与 UTF-16 片段长度。
- `ThemeColorSpaceTests`、`ThemeAndTerminalTests`、`ThemeStoreTests`、`FileViewsTests` 与 `DiffDisplayTests`：直接主题色、推导色与命名色的空间边界，面板转换、透明度与重复写入，真实文本和色块的颜色。

## 准备

测试只使用临时的全局配置和仓库，不改用户的 Git 配置：

```sh
m15_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m15.XXXXXXXX")"
mkdir "$m15_root/config" "$m15_root/workspace"
export GIT_CONFIG_GLOBAL="$m15_root/config/gitconfig"
export GIT_CONFIG_NOSYSTEM=1
git config --global user.name 'Spooky Test'
git config --global user.email 'spooky@example.invalid'
git config --global commit.gpgSign false
git -C "$m15_root/workspace" -c init.templateDir= init -q -b main

printf '#import <Foundation/Foundation.h>\n@interface Bridge : NSObject\n@end\n' > "$m15_root/workspace/Bridge.h"
printf '#include <vector>\nnamespace geo { template <typename T> struct Box { T value; }; }\n' > "$m15_root/workspace/Vector.h"
printf '// !$*UTF8*$!\n{\n  archiveVersion = 1;\n}\n' > "$m15_root/workspace/project.pbxproj"
printf 'function area(x)\n  return x * x\nend\n' > "$m15_root/workspace/area.jl"
printf 'let square x = x * x\n' > "$m15_root/workspace/square.ml"
printf '/* Greeting */\n"hello" = "Hello";\n' > "$m15_root/workspace/Localizable.strings"
printf '<a href="https://example.com" title="Home">link</a>\n' > "$m15_root/workspace/page.html"
printf 'const re = /a+b/g;\nrender(<div className="a">{run()}</div>);\n' > "$m15_root/workspace/app.js"
printf '{"a": [1, true, null]}\n' > "$m15_root/workspace/data.json"
printf 'FROM node:22\nWORKDIR /app\nCOPY . .\nRUN npm install\nCMD ["node", "index.js"]\n' > "$m15_root/workspace/build"
cp "$m15_root/workspace/build" "$m15_root/workspace/big"
printf '%020001d\n' 0 >> "$m15_root/workspace/big"
git -C "$m15_root/workspace" add -A
git -C "$m15_root/workspace" commit -q -m 'Add syntax samples'

# 第二版让提交详情和 Blame 有变更可看，未暂存的第三版用于工作区 Diff。
printf 'let twice x = x + x\n' >> "$m15_root/workspace/square.ml"
git -C "$m15_root/workspace" commit -q -am 'Add another function'
printf 'let cube x = x * x * x\n' >> "$m15_root/workspace/square.ml"
printf '<a title="Changed">new</a>\n' >> "$m15_root/workspace/page.html"
printf 'namespace next {}\n' >> "$m15_root/workspace/Vector.h"
printf '@class Next;\n' >> "$m15_root/workspace/Bridge.h"
```

记下文本、外观、主题相关偏好以及当前选中的浅色 / 深色主题，验收后恢复原值。需要备份用户偏好或主题文件时，先取得该目标的许可，不退出其它会话的程序。

```sh
m15_open() {
    open --env "GIT_CONFIG_GLOBAL=$GIT_CONFIG_GLOBAL" \
        --env GIT_CONFIG_NOSYSTEM=1 \
        -a "$PWD/.build/Spooky.app" "$@"
}
m15_open "$m15_root/workspace"
```

## 语法着色

1. Settings → Text 打开 Enable Syntax Coloring 与 Syntax Coloring in Diffs。
2. 工作区查看 `Bridge.h` 与 `Vector.h`：前者的 `@interface`、`@end` 为关键字色，后者的 `namespace`、`template`、`typename`、`struct` 为关键字色。
3. History 选中第一条提交，在只读 Diff 中逐个核对：
   - `project.pbxproj` 整份按纯文本显示。
   - `area.jl` 的 `function`、`return`、`end` 和 `square.ml` 的 `let` 为关键字色。
   - `Localizable.strings` 的注释与字符串分别着色。
   - `page.html` 的两个属性值使用属性值色；`app.js` 的 `render` 使用函数色，`/a+b/g` 与 JSX 内的 `run` 使用正文色，JSX 的 `"a"` 使用属性值色。
   - `data.json` 的括号与逗号使用符号色。
   - `build` 按 Dockerfile 着色；`big` 超过 20,000 个字符，按纯文本显示。
4. 逐个打开 View File 与 Blame，核对相同记号与 Diff 的颜色类别一致。工作区有未提交修改时，原文与 Blame 显示的是提交过的版本。
5. 在 Themes 页复制主题，将 Function、Symbol、Attribute Value 设为三种明显不同的颜色，并选用复制后的主题。函数名、运算符与标点、属性值分别随对应颜色变化，普通字符串与其它标识符不变。
6. 分别在浅色与深色外观截图，核对文本完整、颜色清晰，切换文件或关闭视图不会把旧着色套到新内容上。

### 服务器

仅经 `spooky-test` 和测试专用密钥操作测试目录；不可达时记录为未验证，不改网络与 SSH 配置。

```sh
m15_ssh() {
    ssh -T -o BatchMode=yes -o ForwardAgent=no -o IdentitiesOnly=yes \
        -i "$HOME/.ssh/spooky-test_ed25519" spooky-test "$@"
}
m15_remote="$(m15_ssh 'umask 077; mkdir -p /Users/wgy/spooky-test && mktemp -d /Users/wgy/spooky-test/m15-app.XXXXXXXX')"
tar -C "$m15_root/workspace" -cf - . | m15_ssh "tar -xf - -C '$m15_remote'"
```

在 Spooky 打开 `spooky-test` 上的 `$m15_remote`，重复本节步骤。客户端读取远端文本着色，远端仓库内容不交给本机文件 API。

## 主题色的色彩空间

1. 分别选用 Default 与 Default (Dark)，核对工作区 Diff、History 的只读 Diff、原文与 Blame 的正文、背景、语法色及增删底色；直接主题色均按 Generic RGB 显示，行号、块描边、Blame 的段高亮与分隔线仍按原始 sRGB 分量推导。
2. Settings → Themes 的记号列表、选中行、字体颜色色块与 Diff 预览使用同一套直接主题色。深色主题背景 `#161819` 不应被当作 sRGB 分量直接显示。
3. 在本次复制的测试主题上打开系统颜色面板，改变一种中间色与不透明度。切换记号、切换主题、关闭再打开设置，颜色与保存的六位十六进制、两位不透明度不应反复漂移；未改动颜色时不重复写盘。
4. 文本选择的底色跟随主题，文件状态徽标、行内高亮等命名色不随主题构色方式改变。用同一显示管线的色样比较截图，保留截图的色彩配置，不把不同配置下的原始像素值直接对比。

### 服务器

在前文创建的服务器测试仓库重复本节的视图检查。主题与面板在客户端解释颜色，不依赖仓库所在机器。

## 收尾

恢复本次修改的文本、主题与外观偏好，删除本次复制的测试主题，关闭本次打开的仓库窗口。只清理自己创建的临时目录：

```sh
rm -rf -- "$m15_root"

# 已执行服务器验收时才运行，并确认变量指向本次创建的测试目录。
m15_ssh "rm -rf -- '$m15_remote'"
```
