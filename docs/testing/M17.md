# M17 分支与同步验收

范围：分支名的规范化与校验原因，新建、跟踪、改名与删除分支的对话框，获取的临时预选与保存的偏好，添加远端后获取，拉取与合并的候选、预览与未跟踪文件，推送 HEAD 的 Destination、发布与没有远端时的入口，按远端计时的自动获取，以及自动储藏默认不恢复改动。

所有命令在仓库根目录执行。界面验收使用临时仓库，需要已解锁、显示器正常显示的 macOS 会话。

## 准备

测试只使用临时的全局配置和仓库，不改用户的 Git 配置；`auto` 的两个远端在 B 的测试目录里，一个可以获取，一个不存在：

```sh
m17_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m17.XXXXXXXX")"
m17_remote=/Users/wgy/spooky-test/m17
mkdir "$m17_root/config"
export GIT_CONFIG_GLOBAL="$m17_root/config/gitconfig"
export GIT_CONFIG_NOSYSTEM=1
git config --global user.name 'Spooky Test'
git config --global user.email 'spooky@example.invalid'
git config --global commit.gpgSign false
git config --global init.defaultBranch main

m17_commit() { git -C "$1" add -A && git -C "$1" commit -q -m "$2"; }

git init -q --bare "$m17_root/remote.git"
git clone -q "$m17_root/remote.git" "$m17_root/demo"
d="$m17_root/demo"
printf 'one\ntwo\nthree\n' > "$d/notes.txt"
m17_commit "$d" 'Initial'
git -C "$d" push -q -u origin main
for name in feature/search release/1.x; do
  git -C "$d" switch -q -c "$name" main
  printf '%s\n' "$name" > "$d/${name//\//-}.txt"
  m17_commit "$d" "Add $name"
  git -C "$d" push -q origin "$name"
done
git -C "$d" switch -q -c feature/a-very-long-branch-name-for-checking-how-dialogs-truncate-and-wrap main
git -C "$d" push -q -u origin HEAD
git -C "$d" switch -q -c clash main
printf 'one\nTWO (clash)\nthree\n' > "$d/notes.txt"
m17_commit "$d" 'Clash on line two'
git -C "$d" switch -q -c side main
printf 'side\n' > "$d/side.txt"
m17_commit "$d" 'Side work'
git -C "$d" switch -q main
printf 'one\ntwo (main)\nthree\n' > "$d/notes.txt"
m17_commit "$d" 'Main on line two'
git -C "$d" tag v1.0
git -C "$d" branch -q -D feature/search release/1.x
printf 'scratch\n' > "$d/scratch.txt"

git init -q "$m17_root/noremote"
printf 'x\n' > "$m17_root/noremote/a.txt"
m17_commit "$m17_root/noremote" 'Only commit'

ssh spooky-test "umask 077; mkdir -p '$m17_remote' && git init -q --bare '$m17_remote/origin.git'"
git init -q "$m17_root/auto"
printf 'auto\n' > "$m17_root/auto/a.txt"
m17_commit "$m17_root/auto" 'Auto base'
git -C "$m17_root/auto" remote add b "spooky-test:$m17_remote/origin.git"
git -C "$m17_root/auto" remote add broken "spooky-test:$m17_remote/missing.git"
git -C "$m17_root/auto" push -q b main
git -C "$m17_root/auto" update-ref -d refs/remotes/b/main
```

## 分支

在 Spooky 中打开 `demo`。

1. Repository › Create New Branch… ⌘B：名称一行的标签是 Name，Check Out Branch 默认不勾；说明写新分支从所选版本开始，跟踪与检出的说明分别写推送与拉取的对象、建好后切换过去。名称为空时 Create Branch 不可用，不显示提示。输入 `bad..name`：输入框里变成 `bad.name`。改为 `-x`：表单最后一行提示名字不能以 “-” 开头，Create Branch 不可用；改为 `main` 时提示本地已有名为 “main” 的分支。
2. 名字改为 `topic one`：输入框里显示为 `topic-one`。按 Return：`git -C "$d" rev-parse --abbrev-ref HEAD` 仍是 `main`，`git -C "$d" branch --list topic-one` 列出新分支。
3. 再打开 Create New Branch…，勾上 Check Out Branch 后建 `topic/two`：HEAD 换到 `topic/two`。再打开一次时 Check Out Branch 保持勾上。双击 `main` 回去。
4. 侧边栏 Remotes › origin 下右键 `release/1.x` → Track：名称一行的标签是 Name，Checkout Branch 默认勾上，不受上一步的勾选影响。点 Create：`git -C "$d" rev-parse --abbrev-ref 'release/1.x@{upstream}'` 输出 `origin/release/1.x`，HEAD 是 `release/1.x`。双击 `main` 回去。
5. 右键 `topic-one` → Rename：说明不带旧名。输入 `topic one renamed`，输入框里是 `topic-one-renamed`；改名后 `git -C "$d" branch --list 'topic-one*'` 只有新名字。
6. 右键 `side` → Delete：说明写删除后分支从这个 Git 仓库移除，Force Deletion 默认不勾；分支有上游时 Delete Tracked Branch 在它下面。直接点 Delete Branch：`side` 没有合并，Spooky 先询问是否强制删除，取消后 `git -C "$d" branch --list side` 仍列出它。

## 获取

1. 在 Spooky 中打开 `auto`，按 Repository › Fetch… ⇧⌘F：Fetch All Remotes 默认不勾；展开 Options，Prune Obsolete Remote Branches 默认勾上，说明写清理范围由获取映射决定、映射含标签时本地标签也可能被删。
2. 右键侧边栏的远端 `b` → Prune Obsolete Remote Branches：对话框里 Prune 勾上；点 Cancel 后 `defaults read com.rakuyo.spooky fetchPrune` 报不存在。再打开 Fetch…，取消勾选 Prune 后点 Cancel：`fetchPrune` 是 `0`。重新勾上。
3. Repository › Add New Remote…，名称 `again`、地址 `spooky-test:$m17_remote/origin.git`：Activity 的 Repository 页有一条添加远端的记录，Remote 页随后多一条 Fetched again，侧边栏出现 `again/main`。再添加一个地址是 `spooky-test:$m17_remote/missing.git` 的远端 `gone`：远端加上了，获取失败只报一次，原文是 B 上 Git 的错误。删掉 `again` 与 `gone`。

## 拉取与合并

回到 `demo`，工作区只有未跟踪的 `scratch.txt`。

1. Repository › Pull… ⇧⌘P：来源一行的标签是 Remote Branch，只列远端分支；不弹出自动储藏的询问。
2. 右键 `clash` → Merge：候选有本地分支、远端分支与 `v1.0` 标签，预选是 `clash`；预览在最后一条说明下方，写出与 HEAD 分支 “main” 冲突的文件数（1 个文件时用单数），放不下一行时换行。改选 `side`：预览一行不显示也不占高度。
3. 点 Merge：直接合并，没有自动储藏的询问，`scratch.txt` 内容不变。Edit › Undo 撤销合并。
4. 执行 `printf 'blocked\n' > "$d/side.txt"` 后再合并 `side`：Git 拒绝合并，`side.txt` 仍是 `blocked`，HEAD 不变；错误原文写着未跟踪文件会被覆盖。删掉 `side.txt`。

## 推送与发布

1. Repository › Push HEAD… ⇧⌘U：只有一行 Destination，列出 `origin` 上的远端分支，不含 `origin/HEAD` 与本地分支；预选 `origin/main`。说明写出把 HEAD 分支 “main” 的新提交推送到所选远端分支。
2. 双击长分支名的那个分支后再 Push HEAD…：预选它的上游，说明里的长分支名换行显示，Destination 里过长的名字以省略号结尾，对话框不变宽。把窗口拖到最窄，再打开 Push HEAD…、Create New Branch… 与 Sync…：对话框宽度不变，按钮与下拉完整可见。双击 `main` 回去。
3. 执行 `git -C "$d" switch -q -c fresh`，再 Push HEAD…：打开 Publish Branch，Track This New Remote Branch 默认勾上。点 Cancel，执行 `git -C "$d" switch -q main; git -C "$d" branch -q -D fresh`。
4. Repository › Force Push with Lease…，Destination 选 `origin/main`：对话框写出这次推送带上的提交数，0、1 与多个各自的写法。在另一个克隆里往 `main` 推一个提交后再强推：远端拒绝，原文含 `stale info`，`git -C "$m17_root/remote.git" log -1 --format=%s main` 是另一个克隆的提交。
5. 在 Spooky 中打开 `noremote`：没有托管账号时工具栏的 Push、Repository › Push HEAD… 与 Publish Repository… 不可用，Fetch… 与 Pull… 不可用。Sync… 与 Push To… 可以打开，对话框写着尚未配置远端，主按钮不可用。登录 [M9](M9.md) 的托管账号后，Push 打开 Publish Repository。

## 自动获取

1. 在 Spooky 中打开 `auto`，打开后立刻按 ⇧⌘F 挂上 Fetch 对话框，等 30 秒：`git -C "$m17_root/auto" for-each-ref refs/remotes` 没有输出，`defaults read com.rakuyo.spooky remoteLastFetch` 没有 `auto` 的记录。
2. 点 Cancel，约 10 秒后 `refs/remotes/b/main` 出现，`remoteLastFetch` 里 `b` 与 `broken` 各有一个时刻；Activity 的 Remote 页有 Fetched b，`broken` 的失败只记在 Activity 里，不弹出错误。
3. Repository › Fetch All Remotes：两个远端的时刻都更新为这次获取的时刻，失败的 `broken` 也更新。
4. 在 B 的另一个克隆里往 `origin.git` 推一个提交，退出并重新打开 Spooky：30 秒内 `b/main` 不变，两个时刻都不变。
5. 退出 Spooky，把 `remoteLastFetch` 里 `b` 的时刻改到两小时前，再打开：约 10 秒后 `b/main` 是刚推的提交，只有 `b` 的时刻更新。
6. 服务器仓库：照 [M8](M8.md) 打开 B 上的一个仓库，给它加一个 `ssh://internal.invalid/repo.git` 这类 A 解析不出的地址，再加一个设了 `remote.<名>.skipFetchAll` 的远端。约 10 秒后 Activity 有 Fetched origin 与这个地址的获取失败，失败原文来自 B 上的 Git；`remoteLastFetch` 里这个仓库有 `origin` 与这个地址的时刻，没有 skipFetchAll 的远端。

## 自动储藏

1. 在 `demo` 里改动 `notes.txt` 后合并 `side`：弹出 Stash Current Local Changes，Re-Apply Changes After Operation is Finished 默认不勾。选 Stash Changes：合并完成，`notes.txt` 回到 HEAD 的内容，`git -C "$d" stash list` 有这次的储藏。
2. 撤销合并、套用储藏后再合并，这次勾上恢复：合并完成，改动回到 `notes.txt`，储藏清掉；再出现询问时恢复保持勾上。
3. 询问里点 Abort：不合并，工作区与储藏都不变。
