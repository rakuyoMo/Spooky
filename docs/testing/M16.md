# M16 提交区、冲突与进行中操作验收

范围：提交区的显示与提交进度、编辑模式与草稿、头像与身份菜单，进行中操作的分类、步数与横幅，Show only conflicts，合并冲突的反馈，提交信息预填与编辑后继续，空提交确认，冲突向导，以及历史中旧提交的 Amend。

所有命令在仓库根目录执行。界面验收使用临时仓库，需要已解锁、显示器正常显示的 macOS 会话。

## 自动验证

```sh
mise run swift:lint
```

- `IdentityProfileMenuTests`、`UserProfilesTests`：身份菜单的文字、当前项匹配与重复校验。

- `MergeConflictTests+Sequences`、`MergeConflictParsingTests`、`RepositorySessionTests+Operations`、`RepositorySessionTests+Conflicts`：单个 / 序列 / edit / 尚未开始的分类、步数、Skip 的显隐，冲突过滤的全局偏好，合并冲突直接显示工作区，合并进行中修补不可用。

## 准备

测试只使用临时的全局配置和仓库，不改用户的 Git 配置：

```sh
m16_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m16.XXXXXXXX")"
mkdir "$m16_root/config"
export GIT_CONFIG_GLOBAL="$m16_root/config/gitconfig"
export GIT_CONFIG_NOSYSTEM=1
git config --global user.name 'Spooky Test'
git config --global user.email 'spooky@example.invalid'
git config --global commit.gpgSign false
git config --global init.defaultBranch main

m16_commit() { git -C "$1" add -A && git -C "$1" commit -q -m "$2"; }

git init -q "$m16_root/commit"
printf 'one\n' > "$m16_root/commit/notes.txt"
m16_commit "$m16_root/commit" 'Add notes'
printf '#!/bin/sh\nsleep 3\ntest ! -e .git/fail-commit\n' > "$m16_root/commit/.git/hooks/pre-commit"
chmod +x "$m16_root/commit/.git/hooks/pre-commit"

r="$m16_root/conflicts"
git init -q "$r"
printf 'first\nsecond\nthird\n' > "$r/conflict.txt"
printf 'remove me\n' > "$r/removed.txt"
printf 'parser v0\n' > "$r/sequence.txt"
m16_commit "$r" 'Initial'
git -C "$r" switch -q -c topic
printf 'parser v1\n' > "$r/sequence.txt"
m16_commit "$r" 'Rework the parser'
printf 'parser v3\n' > "$r/sequence.txt"
m16_commit "$r" 'Tune the parser'
git -C "$r" switch -q -c side main
printf 'first\nsecond (side)\nthird\n' > "$r/conflict.txt"
git -C "$r" rm -q removed.txt
printf 'added on side\n' > "$r/added.txt"
m16_commit "$r" 'Change on side'
git -C "$r" switch -q main
printf 'first\nsecond (main)\nthird\n' > "$r/conflict.txt"
printf 'remove me (main)\n' > "$r/removed.txt"
printf 'added on main\n' > "$r/added.txt"
printf 'parser v2\n' > "$r/sequence.txt"
m16_commit "$r" 'Change on main'

git init -q "$m16_root/rewrite"
for name in parser lexer printer formatter; do
  printf '%s\n' "$name" > "$m16_root/rewrite/$name.txt"
  m16_commit "$m16_root/rewrite" "Add the $name"
done
```

用同一组环境变量启动 Spooky：

```sh
swift run Spooky
```

## 提交区

打开 `commit`。

1. 把 `notes.txt` 改为 `two` 并暂存，在标题输入几个字：标题框右侧显示剩余字数的浮层；点进正文后提交区展开，离开且正文为空时收起。分别在浅色与深色外观、活跃与非活跃窗口下核对提交区的材质。
2. 点 Commit：`pre-commit` 钩子耗时 3 s，前 1 s 按钮不可用但不转圈，之后按钮旁出现转圈；成功后信息清空、提交区收起，焦点回到文件列表。
3. 再改一次 `notes.txt` 并暂存，执行 `touch "$m16_root/commit/.git/fail-commit"` 后提交：钩子失败，弹出带 Git 原文的错误；关闭后标题与正文保留，按钮恢复可用。之后删掉 `fail-commit`。
4. 提交区右侧的头像：有 Gravatar 的邮箱显示 Gravatar，测试身份显示首字母 `ST`。点身份打开菜单，当前身份打勾；Settings → User Profiles 的详情头像为 50 pt。

## 进行中操作的横幅

打开 `conflicts`，在终端开始合并：

```sh
git -C "$m16_root/conflicts" merge side
```

1. 横幅为黄色底（浅色与深色都核对）：标题 “Merging “side” into “main””，下面是 “3 unresolved conflicts (0 resolved)”、说明、Show only conflicts 与 Abort。悬停状态徽标，分别提示 “File requires merging: Both Added” “Both Modified” “Deleted By Them”。
2. 在冲突向导里逐个解决（步骤见下一节）：解决一个后为 “2 unresolved conflicts (1 resolved)”；全部解决后为 “No unresolved conflicts (3 resolved)”，说明改为提示检查提交信息后点 Commit，提交区显示预填的 `Merge branch 'side'` 与 `# Conflicts:` 注释。
3. 勾选 Show only conflicts：列表只留下本次冲突的文件，已解决的也保留。再让 `commit` 停在冲突上并打开它的窗口，开关同样勾选；退出并重新启动 Spooky 后仍勾选：

```sh
git -C "$m16_root/commit" switch -q -c other
printf 'other\n' > "$m16_root/commit/notes.txt"
git -C "$m16_root/commit" commit -q --no-verify -am 'Change on other'
git -C "$m16_root/commit" switch -q main
printf 'main\n' > "$m16_root/commit/notes.txt"
git -C "$m16_root/commit" commit -q --no-verify -am 'Change on main'
git -C "$m16_root/commit" merge other
```

4. 点 Commit：先询问 “Remove comments from the commit message?”，选 Remove Comments 后完成合并，提交信息不含注释行。

## 冲突向导

在上一节的合并冲突里选中各文件：

1. `conflict.txt`：两张版本卡片显示文件图标、文件名、MODIFIED 徽标与日期，以及这一侧提交的头像、作者、日期、短哈希与标题；箭头指向结果框 “Please select a version above”，按钮为 Choose Merge Tool，没有冲突类型标题、Reload 与预览。
2. 点 “main” 卡片：结果框显示这一侧，按钮为 Resolve Using “main”。⌘ 点 “side” 卡片：结果框为带 MERGE 徽标的 Resolve Using Both Versions，按钮回到 Choose Merge Tool。再点已选的卡片取消选择；只选择时 `git status --porcelain=v2` 不变。
3. 版本菜单为 Open、Open With、Export…、Compare with Other Version 与 Compare with Common Ancestor。`removed.txt` 中删除一侧的菜单项都不可用，`added.txt` 的 Compare with Common Ancestor 不可用。
4. 没有设置差异工具时，选 Compare with Other Version 先弹出 Configure Diff Tool；选 FileMerge 后，两侧的副本经本机缓存交给 FileMerge 比较，Compare with Common Ancestor 同样打开。核对后关闭本次打开的 FileMerge 窗口。
5. 合并提交之后，制造一个储藏套用产生的冲突：

```sh
printf 'first\nsecond (stash)\nthird\n' > "$m16_root/conflicts/conflict.txt"
git -C "$m16_root/conflicts" stash -q
printf 'first\nsecond (main 3)\nthird\n' > "$m16_root/conflicts/conflict.txt"
git -C "$m16_root/conflicts" commit -q -am 'Change on main 3'
git -C "$m16_root/conflicts" stash apply
```

   对方卡片为 “Version from Applied Patch or Stash”，没有提交来源，不显示时间。把窗口缩到约 900 pt 宽，卡片标题截断，版本菜单与结果框保持完整。之后执行 `git -C "$m16_root/conflicts" reset -q --hard` 与 `git -C "$m16_root/conflicts" stash drop -q`。

## 序列与空提交

1. 合并完成后摘取两个提交：

```sh
git -C "$m16_root/conflicts" cherry-pick 'topic~1' topic
```

   横幅为 “Cherry-Picking 2 commits onto “main””，进度条下是 “Rebase 1 of 2: Applying “Rework the parser””。在向导中采用 “main” 后，这一步没有改动，说明提示可以 Skip 或 Continue。
2. 点 Continue：先询问注释，再弹出 “Do you want to create an empty commit?”，按钮为 Use Empty Commit、Skip Commit 与 Cancel，带 “Do not show this warning again”。选 Use Empty Commit：保留空提交并进入下一步。之后执行 `git -C "$m16_root/conflicts" cherry-pick --abort`。
3. 单个摘取：

```sh
git -C "$m16_root/conflicts" cherry-pick 'topic~1'
```

   横幅为 “Cherry-Picking 1 commit onto “main””，没有进度条，主按钮为 Commit。采用 “main” 后点 Commit：确认框的按钮为 Use Empty Commit、Abort Merge 与 Cancel；Cancel 不写仓库。再点 Commit，勾选不再提示后选 Use Empty Commit。
4. 再摘取一次 `topic` 并采用 “main”：点 Commit 直接提交，不再确认；重新启动 Spooky 后同样不确认。

## 合并冲突的反馈

```sh
git -C "$m16_root/conflicts" switch -q -c other
printf 'first\nsecond (other)\nthird\n' > "$m16_root/conflicts/conflict.txt"
git -C "$m16_root/conflicts" commit -q -am 'Change on other'
git -C "$m16_root/conflicts" switch -q main
printf 'first\nsecond (main again)\nthird\n' > "$m16_root/conflicts/conflict.txt"
git -C "$m16_root/conflicts" commit -q -am 'Change on main again'
```

1. 右键侧边栏的 `other` → Merge，在对话框点 Merge：停在冲突上时直接显示工作区与横幅，不弹出错误。之后执行 `git -C "$m16_root/conflicts" merge --abort`。
2. 把 `conflict.txt` 改成别的内容但不提交，再次 Merge：先询问储藏，选 Stash Changes；合并停在冲突上时提示 “Conflicts After Stashing”，说明改动留在储藏里，`git stash list` 有这条储藏。

## 旧提交 Amend

打开 `rewrite`，在侧边栏选中 `main` 的历史。

1. 右键 “Add the lexer” → Amend：不弹确认，直接停在这个提交。工作区横幅为 “Editing <短哈希> on “main””，进度行 “Rebase 1 of 3: Editing “Add the lexer””，按钮为 Abort 与 End Editing。
2. 展开提交区，Amend 可用；打开后载入 “Add the lexer”。改标题后点 Amend，再点 End Editing：历史中这个提交带上新标题，后面的提交照原样重放。
3. 改动一个文件但不提交，右键 “Add the printer” → Amend：弹出 “Stash Current Local Changes”，只有 Message，没有恢复改动的选项，按钮为 Abort、Do Not Stash 与 Stash Changes。点 Abort，HEAD、工作区与储藏列表都不变；之后还原这个文件。
4. 右键 “Add the printer” → Edit，在确认框点 Edit：停下后提交区的 Amend 不可用。执行 `git -C "$m16_root/rewrite" rebase --abort` 结束。

## 服务器

仅经 `spooky-test` 和测试专用密钥操作测试目录；不可达时记录为未验证，不改网络与 SSH 配置。

```sh
m16_ssh() {
    ssh -T -o BatchMode=yes -o ForwardAgent=no -o IdentitiesOnly=yes \
        -i "$HOME/.ssh/spooky-test_ed25519" spooky-test "$@"
}
m16_remote="$(m16_ssh 'umask 077; mkdir -p /Users/wgy/spooky-test && mktemp -d /Users/wgy/spooky-test/m16-app.XXXXXXXX')"
m16_ssh "cd '$m16_remote' && git init -q -b main \
    && git config user.name 'Spooky Test' && git config user.email spooky@example.invalid \
    && printf 'first\nsecond\n' > conflict.txt && git add . && git commit -qm Initial \
    && git switch -qc side && printf 'first\nsecond (side)\n' > conflict.txt && git commit -qam 'Change on side' \
    && git switch -q main && printf 'first\nsecond (main)\n' > conflict.txt && git commit -qam 'Change on main' \
    && git merge side"
```

1. 在 Spooky 打开 `spooky-test` 上的 `$m16_remote`：横幅与本机相同，向导的两张卡片可选。
2. 采用一侧后，服务器上的文件变为这一侧的内容并暂存，横幅更新已解决的数量。
3. 结束后删除测试目录：`m16_ssh "rm -rf '$m16_remote'"`。
