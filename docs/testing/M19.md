# M19 界面细节验收

范围：设置窗口各页居中、按冒号对齐的表单，组距与分隔线，弹出菜单的图标，大 Diff 阈值组合框与各页的调整；Working Copy 的分支栏、提交区、标题框与正文框，视图选项按钮；侧边栏的行高、分组标题与计数徽标；关于窗口的说明文字；刷新时历史、变更集与文件历史保持选中、展开与滚动位置。

所有命令在仓库根目录执行。界面验收使用临时仓库，需要已解锁、显示器正常显示的 macOS 会话。

## 自动验证

```sh
mise run swift:lint
mise run build
mise run test
swift build --product Spooky
./scripts/build-app.sh
```

- `SettingsWindowTests`、`SettingsPreferencesTests`：弹出菜单的取图入口每次给出 16 × 16 pt 的新图标，不改动系统共享的图标；打开设置窗口时焦点不在输入框；大 Diff 阈值组合框的输入、预设与越界钳制；Editor 在软折行时停用正文字数上限与参考线；Environment 两张表的横向网格、行高 24 与 Key 列宽 260，结束编辑后立即保存；Git Config 的姓名与邮箱输入框画出的边框各高 24，相隔 8，写入一个键后重读全局配置不冲掉另一个框里正在输入的文字；输入框编辑中显示外部对绑定的修改，组字不被打断，结束输入交出显示的文字。
- `WorkingCopyCommitViewTests`：分支栏底边的 1 pt 线、标题框与正文框画在材质里，与输入区左右对齐、顶边相同；正文框内的分隔线紧接输入区下沿、在 24 pt 动作栏上方。
- `RepositorySidebarViewTests`：小、中、大三档的条目行高 24 / 28 / 32 pt，分组标题 20 pt；程序化选中在各档下都滚到整行可见。
- `AboutTests`：八种语言下说明第一行大写字母的顶边与图标底板的顶边对齐，与版权行至少相隔 20，版权行与按钮的位置不随语言变化。
- `HistoryListTests`、`FileViewsTests`、`RepositoryHistoryTests`：刷新后选中的提交与文件、展开的文件与已读出的补丁保持；选中的提交消失时清空选择；文件历史在 HEAD 移动后保留时间线与详情；超过 1000 条的历史分段读回。
- `LocalizationTests`：八种语言的资源完整性与格式参数。

## 准备

测试只使用临时的全局配置和仓库，不改用户的 Git 配置。`demo` 有 1500 个提交、一个储藏、一个分支，工作区有一个修改和一个未跟踪文件：

```sh
m19_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m19.XXXXXXXX")"
export GIT_CONFIG_GLOBAL="$m19_root/gitconfig"
export GIT_CONFIG_NOSYSTEM=1
git config --global user.name 'Spooky Test'
git config --global user.email 'spooky@example.invalid'
git config --global commit.gpgSign false
git config --global init.defaultBranch main

# 每个提交改一个文件，每三个提交再改一篇文档与 README
m19_stream() {
  t=1700000000
  for i in $(seq 1 1500); do
    t=$((t + 3600))
    msg="Commit number $i"
    line="line $i"
    printf 'commit refs/heads/main\nmark :%s\n' "$i"
    printf 'committer Spooky Test <spooky@example.invalid> %s +0000\n' "$t"
    printf 'data %s\n%s\n' "${#msg}" "$msg"
    [ "$i" -gt 1 ] && printf 'from :%s\n' "$((i - 1))"
    printf 'M 100644 inline src/mod%s/file%s.txt\ndata %s\n%s\n' "$((i % 20))" "$((i % 7))" "${#line}" "$line"

    if [ $((i % 3)) -eq 0 ]; then
      printf 'M 100644 inline docs/guide/part%s.md\ndata %s\n%s\n' "$((i % 5))" "${#line}" "$line"
      printf 'M 100644 inline README.md\ndata %s\n%s\n' "${#line}" "$line"
    fi
  done
}

git init -q "$m19_root/demo"
m19_stream | git -C "$m19_root/demo" fast-import --quiet
git -C "$m19_root/demo" checkout -q main
git -C "$m19_root/demo" branch feature/demo HEAD~10

echo stash >> "$m19_root/demo/README.md"
git -C "$m19_root/demo" stash push -q -m 'demo stash'
echo change >> "$m19_root/demo/src/mod1/file1.txt"
echo new > "$m19_root/demo/untracked.txt"

./scripts/build-app.sh
open -n -a .build/Spooky.app "$m19_root/demo"
```

服务器仓库按 [M2](M2.md) 的准备在 `spooky-test` 上建测试工作区。

深色与浅色外观各验一遍；只想让这一次启动用另一种外观或语言时，在 `open` 的末尾加 `--args -AppleLanguages '(zh-Hans)'` 一类启动参数。截图用 2×，坐标以窗口左上角为原点，单位 pt。

## 设置窗口

1. 打开 Settings，窗口宽 900，各页内容距顶 20。表单页分标签列与控件列：
   - 标签右对齐，冒号排成一条竖线，标签与控件的可见间隔约 9
   - 每一行都从控件列的左缘起（弹出菜单的可见边框、组合框的内底、勾选框的方块），没有标签的勾选框与说明文字也是；勾选框下的说明与子选项比勾选框缩进 20
   - 同一页的弹出菜单、组合框与输入框都充满控件列，右缘排成一条竖线；勾选框与说明文字在控件列内折行
   - 组合行保持内部组成，从控件列左缘起：Text 的 Tab 宽度数字框、步进器与单位，Git Config 的姓名与邮箱框加右端的头像，Appearance 的应用图标、组名与 “Change…”
   - 两列合起来在窗口里水平居中，各页分别居中：最左的标签到窗口左缘与控件列右缘到窗口右缘相差不超过 1；切换语言后同样如此
   - 各页的控件列宽：

   | 页 | 控件列宽 |
   |---|---|
   | General、Appearance、Text、Editor | 278 |
   | Git Config | 310 |
   | Integration | 254 |
   | Updates | 250 |

   Environment、Accounts、User Profiles 与 Themes 不分标签列，内容四周留 20。
2. 纵向间距，按可见边框量：
   - 弹出菜单之间 10，弹出菜单到下面的勾选框组 12，勾选框之间 6（两行的勾选框也是 6）
   - 附在弹出菜单下的勾选框距弹出菜单 8，到下一个弹出菜单 20
   - 说明文字或组合框与下面的弹出菜单相隔 20：Git Config 的 “Allowed signers file:”，Editor 的 “Body line wrapping mode:”
   - 弹出菜单与相邻的组合框相隔 7；大 Diff 阈值组合框到下一条分隔线 6.5
   - 输入框高 24，之间相隔 8：Git Config 的姓名与邮箱，User Profiles 新建与编辑档案的三个输入框；Add User Profile 的标题输入框同样高 24
   - Git Config 的头像 54 × 54，右缘与弹出菜单右缘齐平；上缘比姓名框可见边框低 1，下缘比邮箱框可见边框高 1，左缘距姓名框 7
3. 分组分隔线横贯整页，左右各距窗口边缘 40；与上一组最后一个控件相距 16，下一组第一行是弹出菜单或输入框时到控件顶 12，是勾选框时 16。
4. General
   - “Default directory for cloned repositories:” 与 “Terminal application:” 收起时图标是 16 × 16 pt、保持原比例，名字完整；展开的菜单里同样如此。换选另一项、经 “Select…” 选一个新目录后再看一次。
   - 打开设置窗口、从别的页切回 General 时，焦点不在任何输入框。
   - “Show warning for diffs larger than (kB):” 是 278 pt 宽的组合框，预设依次为 20、50、500、1000、5000、10000；可以直接输入，空白或不是整数时恢复为当前值。
   - “Always offer to stash local changes” 在 “Always update submodules automatically” 前面。
5. Integration：“Open repositories from github.com:” 与 “SSH Agent:” 的候选图标同第 4 步；崩溃报告的勾选框没有行标签，下面 4 pt 是缩进 20 的 11 pt 次要色说明。
6. Git Config：分组依次是 Git 程序、身份、签名、Diff 与 Merge 工具，组间有分隔线；Diff tool、Merge tool 两个弹出菜单与外部工具选择对话框里的图标同第 4 步。
7. Text：没有分隔线，组间留 33；“Show invisible characters” 的方块底到 Tab 宽度数字框的可见顶边 32。
8. Editor：“Enable service integration plugins” 上方有分隔线，说明比勾选框缩进 20；页高至少 360，切换到德语、法语或西班牙语时随折行增高，最后一行说明完整可见；Body line wrapping mode 为 Soft Wrap 时 “Body line character limit” 与 “Show guide” 置灰，换成 Hard Wrap 后立即可用。
9. Themes 的主题列表在行与行之间有分隔线；User Profiles 的左侧列表没有表头。
10. Environment：两张表画实线横向网格，空行也画，Key 列宽 260；点按已选中行的格子编辑，Tab 在格子间移动，“+” 后直接输入变量名，“−” 删除多选的行。
11. Updates：“Last check for updates at:” 后面的时间是灰色。

## Working Copy 与 History

1. 在窗口活跃与不活跃时各截一张图，沿提交区中间的一列读像素：
   - 分支栏与提交区同一底色，提交区与文件表头之间没有线
   - 分支栏底边的 1 pt 线与标题框、正文框的描边同色：深色下比底色亮约 40，浅色下暗约 20
   - 标题框与正文框的底：深色下比底色亮约 20，浅色下暗约 10
   - 正文框内输入区与动作栏之间的分隔线与描边同色；动作栏不填底色，与提交区同色
   - 读数随窗口状态与桌面略有不同，以相对底色的差判断
2. 标题框上沿距分支栏底边线 20、高 29；Stage All 与 Commit 一行，与标题框、文件表头各相距 15。
3. 在标题框里输入后展开正文框，正文框跟随输入框的位置；横幅出现与消失、正文展开与收起时，两个框都跟着输入区移动。按住 ⌥ 的快速修补与提交行为不变。
4. Working Copy 状态头与 History 列表头的视图选项按钮只有 `slider.horizontal.3`，没有箭头，图标宽 15。

## 侧边栏

1. 在系统设置 “外观 → 侧边栏图标大小” 的小、中、大三档下，条目行高依次为 24、28、32，分组标题行 20；只想让这一次启动换档时，用启动参数 `-NSTableViewDefaultSizeMode 1`（小）、`2`（中）、`3`（大）。
2. 分组标题的文字距侧边栏左缘 20。
3. 选中 Workspace 行且窗口活跃时，计数没有底色、数字为白色；没选中或窗口不活跃时是深色胶囊。子模块的改动数相同。
4. 中档下从快捷操作、后退 / 前进或 `spooky://` 链接选中列表靠后的引用，侧边栏直接滚到整行可见。

## 关于窗口

1. 分别以八种语言启动，打开关于窗口：说明是该语言的自我介绍，简体中文为 “Spooky 没有什么宏大的愿景，它只是一只单纯的，喜欢在各个 Git 仓库之间飘来飘去的小幽灵罢了，嘿嘿。”
2. 说明第一行大写字母的顶边与图标底板（四周透明边以内的部分）的顶边对齐；说明与版权行至少相隔 20，不重叠；版权行与两个按钮的位置在各语言下相同。

## 刷新

1. 在 History 选中一个提交，展开变更集里的目录与文件，读出补丁，把列表滚到中间。
2. 依次触发刷新：改动工作区里的文件；手动刷新；切到别的 App 再切回；服务器仓库在 B 上改动文件，等轮询。每次之后选中的提交与文件、展开的目录与文件、已读出的补丁与各列表的滚动位置都不变，行不闪烁，列表下方不出现读取进度。
3. 把提交列表滚过第 1000 条再刷新，位置不变。
4. reset 掉选中的提交后刷新，选择清空。
5. 储藏详情、比较视图与文件历史按第 1–2 步再核对一次。
