# M24 写操作排队的验收

范围：仓库写队列与入口可用性的两层，轮到时的核对、取消与失败后的处理，对话框、文件列表、提交区、撤销与重做，侧边栏底部的活动区与 Activity 窗口的等待行，后台自动获取的让路，断线、关窗、换仓库与退出；仓库管理里删除书签与分组时移到废纸篓，列出工作树与显示 SSH 主机别名两个选项。M1–M23 的验收步骤继续适用。

所有命令在仓库根目录执行。界面验收需要已解锁、显示器正常显示的 macOS 会话；深色与浅色外观各验一遍。

## 自动验证

```sh
mise run swift:lint
mise run build
mise run test
swift build --product Spooky
./scripts/build-app.sh
```

- `RepositoryWriteQueueTests`：同一仓库的写操作按提交的先后一次执行一个，两个会话共用一条队列；服务器仓库没连上时不接受写入；轮到时核对不通过的不执行 Git、记为已跳过并写明原因，在队列里取消的不执行、不记成失败，停掉执行中的只停这一个；前一个失败后排着的全部取消；服务器仓库断开时取消排着的；换仓库只取消本窗口排着的；退出时排着的不再执行。执行中的写操作由 `ProcessGate` 停在中途。
- `SidebarSessionTests`：仓库正被占用时各入口的规则照常可用，双击排队、不响铃；检出的确认在点的时候出现，轮到时有已跟踪的修改才询问储藏，中止询问记为取消、后面的接着执行；等待期间进入合并的检出跳过。
- `RepositoryDialogLayoutTests`：对话框的 `dialog.blocked` 只在服务器已断开时出现。
- `WorkingCopyFileListTests`：获取执行时文件列表不变灰，改动索引的写操作执行时变灰；排队的暂存先显示目标状态、刷新不撤回、取消后撤回；提交排队期间提交区只读，取消后恢复、草稿不变。
- `UndoSessionTests`：有用户发起的写操作在执行或排队时不能撤销，只有自动获取在执行时可以。
- `RepositorySessionTests`：自动获取在仓库不空闲时不开始，用户的写操作进来时让路，记为取消并写明让给了哪个操作。
- `SidebarActivityViewTests`、`ActivityRowTests`、`ActivityWindowTests`：等待中的行排在进行中的下面、先轮到的在上，第三行写 Waiting…，有停止按钮；在队列里取消与跳过的行留 4 s；Activity 窗口里等待中的记录不计时、状态写 Waiting。
- `BookmarkDeletionTests`：删除书签与分组时要不要询问（空分组、只有空子分组、只有目录已不存在的本机仓库、有服务器仓库、有目录还在的本机仓库，单项与多选），勾选框的个数与两种说明；认出目录已不存在的服务器仓库不算进个数，要问的都是这样的仓库时勾选框不能勾；不勾选只移除书签；勾选后书签删除，本机与服务器仓库分别经可替换的入口移走，认出目录已不存在的服务器仓库不交给入口，移不走的列进错误框，克隆中的先停止。
- `RepositoryTrashTests`：服务器上移走仓库目录前的核对，家目录、它的上级与挂载点的顶层不移走，没有废纸篓时报错。
- `RepositoryManagerListTests`：服务器仓库行上的主机别名随设置显示，悬停提示与 VoiceOver 的名字不变；列出工作树的选项关着时不读取，打开后读取列表里看得到的仓库，工作树行的内容、样子、菜单与双击；回车给单选的书签改名，名称平时不能编辑，提交或取消后复原。
- `LocalizationTests`：八种语言的资源完整性与格式参数。

## 准备

测试仓库都以 `m24-` 开头。B 上经 `spooky-test` 在 `/Users/wgy/spooky-test/` 下新建测试目录，放一个裸仓库与一个让获取慢下来的脚本；本机的测试仓库只在本地配置里让 `origin` 的获取经过这个脚本，不改双方的 SSH 与全局 Git 配置：

```sh
m24_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m24.XXXXXX")"
m24_ssh() { ssh -o BatchMode=yes spooky-test "$@"; }
m24_remote="$(m24_ssh 'umask 077; mkdir -p /Users/wgy/spooky-test && mktemp -d /Users/wgy/spooky-test/m24-app.XXXXXXXX')"
m24_ssh /bin/sh -s "$m24_remote" <<'EOF'
cd "$1"
git init -q --bare -b main remote.git
printf '#!/bin/sh\nsleep 40\nexec git-upload-pack "$@"\n' > slow-upload-pack
chmod +x slow-upload-pack
EOF

export GIT_CONFIG_GLOBAL="$m24_root/gitconfig"
git config --global init.defaultBranch main
git init -q "$m24_root/m24-local"
cd "$m24_root/m24-local"
git config user.name 'Spooky Test'
git config user.email 'spooky@example.invalid'
printf 'base\n' > readme.txt
git add -A
git commit -q -m 'Start'
git remote add origin "spooky-test:$m24_remote/remote.git"
git push -q -u origin main
git push -q origin main:topic
git config remote.origin.uploadpack "$m24_remote/slow-upload-pack"
cd -
```

服务器仓库在 B 的测试目录里按同样的办法建一份 `m24-server` 工作区。启动 App 按 [M12](M12.md) 的 “启动 App” 进行。

## 排队与取消

1. 打开 `m24-local`，改 `readme.txt`，再新建 `extra.txt`。点工具栏 Fetch：活动区出现进行中的获取。
2. 获取期间依次双击侧边栏的 `origin/topic`、点工具栏 Pull、勾选 `readme.txt`、写提交信息点 Commit、在 `extra.txt` 的右键菜单里点 Discard：每一项都排进队列，活动区在获取下面按点的先后列出，第三行写 Waiting…；文件列表不变灰，`readme.txt` 先显示已暂存；提交区只读。
3. 在活动区停掉排在最后的丢弃：那一行的标题带 cancelled，留 4 s 后离开；`extra.txt` 还在。
4. 打开 Activity 窗口，Repository 页里等待中的记录右上角空着、状态写 Waiting；停掉其中的拉取：记录写 Cancelled，其余的照常排着。
5. 获取结束后其余的按先后执行；轮到时条件已不满足的记为 Skipped，输出写 Not run: the repository changed while this operation was waiting.，不弹框。

## 自动获取让路

1. 设置的自动获取间隔选最短，打开 `m24-local`，约 10 秒后活动区出现自动获取。
2. 获取期间双击 `origin/topic`：自动获取停下，检出随即执行；Activity 里自动获取的记录为 Cancelled，输出写 Stopped so that “<检出的标题>” can run first.。

## 服务器仓库断开

1. 照 [M8](M8.md) 打开 `m24-server`，给它的 `origin` 同样设慢的 `uploadpack`，点 Fetch，期间排上暂存与提交两项。
2. 只结束 Spooky 为这个仓库建立的 SSH 主连接，不动网络与 B 的 sshd：排着的两项记为 Cancelled，输出写 Cancelled because the connection to the server was lost.。
3. 重新连上后两项都没有执行：`git status` 与 `git log` 与断开前相同。

## 两个窗口

1. 用新窗口再打开 `m24-local`。先在第一个窗口点 Fetch，期间两个窗口各提交一项。
2. 两项按点的先后执行，`git log` 里提交的先后与点的先后相同。

## 删除仓库与分组

1. 仓库管理里删除 `m24-local` 的书签：询问框里有 Also move the repository folder to the Trash, including uncommitted changes，默认不勾；不勾时书签移除，目录还在。
2. 重新加入后再删，勾选：目录进了废纸篓，在 Finder 里能放回。它同时开在另一个窗口时，那个窗口换成丢失页。
3. 新建一个空分组，删除时不询问。
4. 分组里放一个本机与一个服务器仓库，删除分组：勾选框写 Also move 2 repository folders to the Trash…，说明写服务器上的仓库进那台服务器的废纸篓；勾选后本机的进这台 Mac 的废纸篓，服务器上的进 B 的废纸篓。
5. 书签的主机别名改成 `~/.ssh/config` 里没有的，勾选删除：书签删除，错误框 Couldn’t Move to the Trash 列出这一项与原因。
6. 去掉一个本机测试仓库父目录的写权限，勾选删除：错误框列出它，目录还在；测后恢复权限。
7. 在 B 上把一个服务器测试仓库的目录改名，回到仓库管理选中它的书签，等名称变灰后删除：询问框照常出现，勾选框是灰的、不能勾，Delete 只移除书签。把它与一个目录还在的本机仓库一起删：勾选框可以勾，写的是单数。
8. 测完从两边的废纸篓删掉以 `m24-` 开头的项。

## 设置

1. General 页的窗口一组下面有两个勾选框：Show Worktrees in Repository List 默认关，Show SSH Host Aliases in Repository List 默认开。
2. 给 `m24-local` 与 `m24-server` 各加一个工作树，打开列出工作树：两个仓库都能展开，列出的与仓库窗口侧边栏的 Worktrees 相同；双击工作树行在仓库窗口打开它。
3. 关掉显示主机别名：服务器仓库的行只写名称，悬停提示仍带主机前缀。

## 外观与 VoiceOver

浅色与深色外观、VoiceOver 各看一次活动区的等待行（读出标题、Waiting… 与停止按钮）、删除询问框的勾选框与工作树行。

## 清理

```sh
m24_ssh rm -rf "$m24_remote"
rm -rf "$m24_root"
```
