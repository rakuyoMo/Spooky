# M14：菜单、工具栏、窗口与对话框的对齐验收

M14 承接 [M13](M13.md)，修正前面各里程碑交付的主菜单、工具栏、窗口、对话框与空状态，M1–M13 的验收步骤继续适用：

- 应用菜单有系统的 Services；Edit 菜单有系统的文本项与五个子菜单；工作区文件列表、书签列表与文本框里按 ⌘⌫ 的行为不变，储藏列表里按 ⌘⌫ 询问删除所选储藏
- File › Open Recent 写仓库文件夹的名字，同名的带上一级文件夹名，末尾的 Clear Menu 清空列表而书签都在
- Repository、Working Copy、View 与 Window 菜单的标题、分组、分隔线与快捷键；⌃⌘U 只属于 Force Push with Lease…
- 窗口显示仓库管理时不能切换主视图，后退照常可用；Diffs in Changeset 的阈值上方有一行标题
- 工具栏：仓库管理入口叫 Bookmarks，后退 / 前进叫 Prev / Next，储藏两段叫 Apply / Save；各项的提示在显示文字与只显示图标两种模式下、按住 ⌥ 前后都对，服务器仓库的主机前缀排在最前
- 窗口变窄时搜索框、Parent Repository、Bookmarks、Create Branch 与 Force Push 最后才进溢出菜单；Fetch、Pull、Push、Push To 与 Force Push 是同一造型的一套图标，与 Clone 的图标不同，Activity 里获取、拉取、推送的记录用对应的图标
- 只显示图标时，有内层分栏的视图在工具栏上有一条跟随内层分隔线的分隔符；内层分栏左侧的列表不延伸到工具栏下面，它的底色与分隔线不穿过工具栏；刷新进行中 Refresh 与 ⌘R 照常可用
- 丢失页出现时与窗口每次成为主窗口时都重新读取仓库，仓库回来了就换回仓库界面；服务器仓库重试时不询问凭据
- File › Open… 的目录面板是单独的模态面板，确定按钮写 Open Repository；选了不是仓库的文件夹时以单独的模态对话框询问是否新建
- 还没有记下侧边栏宽度时，仓库视图的侧边栏宽 428 pt；“打开文稿时首选标签页” 为 “始终” 时，New Window 与 Dock 菜单的 New Window 都在当前窗口开一个标签页
- 引用、子模块、工作树、LFS、克隆与仓库管理的对话框是同一副骨架：宽 480，应用图标与单行标题，错误区带动画展开，Options 开关与选项区，底栏上方不画分隔线；服务器仓库在标题下写出位置
- 删除远端分支、添加与删除子模块、工作树与 LFS 传输的标题与主按钮；克隆对话框的两个勾选框直接在表单里，Initialize Submodules 默认勾上
- 新建与跟踪分支、获取、拉取、推送、发布、合并、同步、变基、安全强推与推送版本的对话框也是这副骨架：新建分支的标题是 Create New Branch，跟踪远端分支的主按钮是 Create，推送按本地分支是不是 HEAD 写 Push HEAD 或 Push Branch，同步的主按钮是 Sync HEAD；推送宽 450
- 对话框表单里的下拉填满输入列，不超过各自的上限；发布分支、发布标签、同步、安全强推与推送版本的 Skip Hooks 与说明相隔 4 pt；合并可行性预览在表单最后，安全强推的提交数在各自的下拉下方
- 改写、版本、储藏、工作区文件与外部工具选择的对话框也是这副骨架：组合框与输入框填满输入列，改写提交信息的标题写 Edit Commit Message of Revision “<短哈希>”，自动储藏用备选底栏；服务器上会改写历史的对话框在说明后另起一段，写明在哪台服务器上执行
- 添加服务器仓库的表单同样是这副骨架，标题不带省略号；体检失败时错误区写修复方向与原文，路径不存在或不是工作区时底栏多出 Create Repository；第一次连接时的环境变量提醒只有 Close
- 丢弃、删除储藏、恢复文件、移除 LFS 规则、远端设置、Reflog 恢复分支、续载提交与身份的确认是骨架的确认版，只有头部与底栏：标题是名词短语，主按钮写动作；丢弃一个文件时说明写出文件名，丢弃全部的标题是 Discard All Local Changes
- 丢弃块与行的确认在本机仓库同样有 Do not ask me again，与 General 页的 Warn when discarding changes in a chunk 是同一项；服务器仓库其余确认的 Do not ask me again 也在内容区；合并没有暂存的改动时，提交前的询问是系统提示框
- 强制删除分支、子模块的强制删除 / 强制添加 / 自动更新、停止跟踪已忽略的文件、删除书签、仓库管理里应用身份档案、外部工具的询问与提示、崩溃报告、Reset User Defaults 与提交信息含注释的询问同样是骨架的确认版或提示版：
  - 强制删除分支的标题是 Could Not Delete Branch，多个时 Could Not Delete Branches，主按钮是 Delete，不附 Git 原文
  - 要第三个按钮的用备选底栏，Cancel 与标题左对齐，另两个按钮在右；勾选框只在选了 Cancel 以外的按钮时生效
  - 崩溃报告在启动时是单独的模态对话框；底栏的按钮在 480 pt 里放不下时对话框随之加宽
- Git 错误框是骨架的错误版：头部是系统的警告图标，标题是简短的名词短语，说明先写原因、再写恢复说明，空一行后是类别与仓库；Git Error Message 默认展开，原文先 stderr 后 stdout，对话框可以拉大并记住尺寸；底栏只有 Close，打开仓库失败时另有 Choose Another Folder…
- 断线后的恢复说明、无效的 `spooky://` 链接与仓库设置里 Local Folder 核对失败的提示是骨架的提示版，只有 Close
- 回调中继的询问也是这副骨架：
  - 私钥口令的标题是 Enter Password for Private Key，说明写出主机与私钥路径；用户名与密码的标题是 Enter Username 与 Enter Password，说明写出主机与提示原文
  - 内容区是 Username: 或 Password: 一行输入框，密码与口令用安全输入框，下面是 Save in this Mac’s Keychain；输入框在出现时成为焦点，按钮是 Cancel 与 OK，输入为空时 OK 不可用
  - 编辑器中继的标题是 Edit Remote Text，内容区是带边框的等宽编辑区，按钮是 Cancel 与 Continue
- 空状态的图标、标题、说明与按钮行相隔 8 pt，标题 18 pt、比所在区域的中心低 32 pt（区域包括工具栏下面的那一段），标题与说明是三级标签色，背景铺满所在区域；没有说明时留出一行空白；按钮行由空状态排在说明下方，按钮是带细边框的工具栏样式、文字为次要标签色。大 Diff 的提示是没有图标的空状态，多选提交、丢失页与仓库管理多选的按钮都在按钮行里
- History 按分支、标签或远端分支筛选时，这个引用被删除或在获取时修剪后，侧边栏按原来的行号选中接替它的行（分组标题与文件夹也占行号），History 随之显示那一行；多选时只去掉消失的引用；后退 / 前进到筛选的引用都已删除的 History 时留在当前视图，再按一次接着往前或往后走

M14 新增与修改的自动测试覆盖：

- 主菜单：
  - 应用菜单 Services 的位置与两侧的分隔线
  - Edit 菜单的分组、各项的动作、快捷键与查找栏动作的 tag，Substitutions 的项不带快捷键
  - Repository、Working Copy、View 与 Window 菜单的标题、顺序、分隔线与快捷键，⌃⌘U 在整个主菜单里只出现一次
  - Diffs in Changeset 的标题行在分隔线之后且不可用
  - 改了标题与新加的菜单项的英文
- Open Recent：同名的项带上一级文件夹名，服务器仓库不带主机前缀，提示写完整位置；Clear Menu 之后列表为空、书签还在、Clear Menu 不可用，之后打开的仓库重新进入列表；清空时间重新读取偏好后仍在
- 显示仓库管理时 ⌘1–⌘6 与 ⌘0 不可用，后退可用
- 工具栏：
  - 显示文字时各项的提示，按住 ⌥ 时同步一组的快速操作提示
  - 只显示图标时带标签前缀的项与不带的项，按住 ⌥ 时 Quick Fetch 等前缀；换显示方式后提示随之重写
  - 服务器仓库：按钮与同步一组的提示在最前面加主机前缀，只显示图标时排在标签之前，Push To 不重复标签，Bookmarks、Prev / Next 与储藏两段不加
  - Bookmarks、Prev / Next、Apply / Save 的标签，Sync 在自定义面板里的名字 Synchronize，五项的可见优先级，新加与改过的英文提示
  - Fetch、Pull、Push 三段依次用获取、拉取、推送的模板图，Push To 与 Force Push 用加了角标的推送图；五张图都带 @1x 与 @2x，像素两两不同，也与 Clone 不同；Activity 行与侧边栏活动区里获取、拉取、推送的记录用同一套图
  - 只显示图标时 Working Copy 与 History 有跟随内层分栏的分隔符，紧跟侧边栏分隔符，换视图后改跟新的内层分栏；仓库设置、仓库管理与显示文字时隐藏，来回切换始终只有一个
  - 有内层分栏的八个视图里，左侧的列表不延伸到工具栏下面
  - 刷新进行中 Refresh 可用
- 窗口与仓库管理：
  - 丢失页出现时与窗口重新成为主窗口时的重试都换回仓库界面；仓库仍不在时页面原样留着，不弹错误，书签不标为失效
  - 重试在不允许询问用户的任务里验证位置，同一窗口上一次重试没结束时不发起新的重试；重试期间回到仓库管理的，仓库回来了也不换回
  - File › Open… 选好的文件夹因不是工作区这类原因打不开时，显示带 Choose Another Folder… 的错误 sheet
  - 还没有记下宽度时，仓库视图的侧边栏 428 pt，仓库管理 260 pt
- 对话框骨架：
  - 默认宽 480，指定宽度时照指定；头部图标 64 × 64，距左 40、距顶 20；超长的标题只占一行
  - Options 开关距左 20，选项区默认收起，按下开关展开，可以指定默认展开与开关文字
  - 底栏按钮至少 70 宽、相隔 8、距右 20；备选底栏的 Cancel 对齐输入列；提交中两个按钮都不可用；确认版只有两个按钮，提示版只有 Close
  - 错误文字里的网址是链接；服务器仓库在标题下写出位置，仓库不可写时错误区说明原因、主按钮不可用，本机仓库没有位置一行
  - 删除一个与两个远端分支的标题与主按钮；克隆对话框两个勾选框的顺序、默认值与位置
- 分支与同步的操作对话框：
  - 各种类标题与主按钮的资源键；新建分支、跟踪远端分支与同步读出的标题与主按钮
  - 推送 HEAD 分支时是 Push HEAD，指定了别的本地分支（同本地分支拖到远端分支）时是 Push Branch
  - 推送宽 450，其余 480
  - 行距 8，勾选框到说明、说明到下一个勾选框 8；合并里会变为不可用的三个勾选框在输入列；合并的 Skip Hooks 与说明相隔 8，发布分支与同步相隔 4
  - 下拉填满输入列：跟踪远端分支的下拉伸到右边距 20 处，安全强推的两个下拉正好 320，推送、拉取、合并与发布不超过各自的上限
- 改写、版本、储藏、工作区文件与外部工具的对话框：
  - 每一种都宽 480，窗口取到的高度与按 480 宽排出的高度相同
  - 改写提交信息的标题带短哈希；自动储藏的 Abort 对齐输入列，Do Not Stash 与 Stash Changes 在右、相隔 8、距右 20
- 添加服务器仓库：表单与环境变量提醒宽 480，标题不带省略号；体检失败时错误区先写修复方向、空一行后是原文；只有路径不存在或不是工作区时能新建仓库；环境变量提醒的底栏只有 Close
- 会话里的确认：
  - 丢弃所选与全部、删除一个与两个储藏、恢复文件、移除 LFS 规则、取消推送地址、删除两种 refspec、Reflog 恢复分支、续载提交、应用身份档案与设为全局身份的标题与主按钮，以及这些资源键的英文
  - 丢弃的说明：一个文件时写出文件名，两个文件时写文件数；本机、服务器移进废纸篓与服务器永久删除各一例
  - 本机仓库丢弃块与行的确认带 Do not ask me again，这项警告关掉以后直接丢弃
  - 确认对话框的勾选框距左 120；勾上并确认后关掉这项确认再执行，勾上后取消不改变设置；没有可以关掉的确认项时没有勾选框
  - 丢弃文件的确认挂成确认对话框的 sheet，空合并提交的询问是系统提示框，按钮是 Create Empty Merge Commit 与 Abort
- 其余的询问：
  - 强制删除一个与两个分支的标题与主按钮，说明写出这些分支
  - 子模块的强制删除、强制添加（备选按钮 Overwrite、主按钮 Reuse Git Directory）与自动更新（取消写 Do Not Update，有 Always auto-update submodules）；停止跟踪已忽略的文件（备选按钮 Skip Untrack）；外部工具改写的文件已在别处改过；删除两个书签与应用身份档案；提交信息含注释的询问挂成 sheet
  - 备选底栏的 Cancel 与勾选框距左 120，备选按钮的动作拿到勾选状态，勾上后取消时勾选不生效
  - 提交信息含注释的两种询问的按钮与勾选框；崩溃报告的两个按钮，勾上 Always send crash reports 后只有选 Report on GitHub… 才记下
  - Reset User Defaults 的确认对话框：Cancel 不执行，Reset 才执行
  - 底栏按钮放不下时对话框加宽，备选底栏的 Cancel 仍对齐输入列、主按钮仍距右边 20
- Git 错误与提示版：
  - 连接中断、认证失败、超时、推送被拒、没有上游、找不到远端、索引被锁与签名失败的标题，其余的 Git 失败用 Can’t execute Git command
  - 删除一个与两个没有合并的分支的单复数；本地改动挡住合并、变基、检出与其余命令时的标题
  - 说明先写原因、再接恢复说明，标题已说清的错误只有恢复说明；原文先 stderr 后 stdout，没有退出码，都为空时写 (No error message given)
  - 错误框挂成可以拉大的 sheet，以 `GitErrorDialog` 记住尺寸；拉高、拉宽时多出的尺寸都交给原文区
  - 错误框只有 Close，打开失败时 Close 左侧另有 Choose Another Folder…；Git Error Message 默认展开，说明后空一行是类别与仓库
  - 断线后的恢复说明、Local Folder 的提示与无效链接的提示只有 Close
- 认证询问：
  - 私钥口令、用户名、HTTPS 与 SSH 的密码、签名口令与编辑器请求的标题与输入的种类
  - 私钥口令的说明写出私钥路径，本机仓库另起一段说明会加入 SSH agent，提示里取不到路径时照写提示原文；其余询问写主机与提示原文
  - 口令询问的 Password: 是安全输入框，从输入列伸到右边距 20，钥匙串勾选框在输入框那一列；空口令时 OK 不可用，点 Cancel 先关掉对话框再交回取消
  - 用户名询问用普通输入框；编辑器请求的编辑区占满内容区、没有勾选框，点 Continue 先关掉对话框再交回编辑区的文本
- 空状态：标题中心比容器中心低 32，说明在标题下方 8，按钮行在说明下方 8、水平居中；标题的高度是 18 pt 系统字体的行高；没有图标时标题位置不变，没有说明时留出一行 13 pt 文字的高度；背景是铺满容器的 `contentBackground` 材质，窗口内容延伸到工具栏下面时背景同样铺到那里；按钮是工具栏样式、标题为次要标签色，`disabled` 让按钮不可用，按下执行动作
- History 按引用筛选时，筛选的本地分支、标签或远端分支消失：多选时留下仍在的引用，一个也不剩时侧边栏按原来的行号往下找接替它的行，下面没有可选中的行时选上面那一行；分支连同所在的文件夹一起消失时，选中落到原行号上的那一行；后退到筛选的引用都已删除的 History 时留在当前视图、记录不变，再后退接着往前走

## 准备

本机的测试目录放在系统临时目录下，测试结束后删除。Git 只读写这里的一份全局配置：

```sh
m14_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m14.XXXXXXXX")"
mkdir "$m14_root/config"
export GIT_CONFIG_GLOBAL="$m14_root/config/gitconfig"
export GIT_CONFIG_NOSYSTEM=1
git config --global init.defaultBranch main
git config --global user.name 'Spooky Test'
git config --global user.email 'spooky@example.invalid'
git config --global commit.gpgSign false

# alpha/demo 与 beta/demo 同名，alpha/demo 里有一个储藏、一处改动与一个未跟踪文件，远端是临时的裸仓库
for parent in alpha beta; do
    mkdir -p "$m14_root/$parent/demo"
    git -C "$m14_root/$parent/demo" init -q
    printf 'one\n' > "$m14_root/$parent/demo/a.txt"
    git -C "$m14_root/$parent/demo" add a.txt
    git -C "$m14_root/$parent/demo" commit -q -m first
done

git init -q --bare "$m14_root/remote.git"
git -C "$m14_root/alpha/demo" remote add origin "$m14_root/remote.git"
git -C "$m14_root/alpha/demo" push -q -u origin main
git -C "$m14_root/alpha/demo" push -q origin main:feature
git -C "$m14_root/alpha/demo" tag v1.0

printf 'stashed\n' > "$m14_root/alpha/demo/a.txt"
git -C "$m14_root/alpha/demo" stash push -q -m 'm14 stash'
printf 'changed\n' > "$m14_root/alpha/demo/a.txt"
printf 'new\n' > "$m14_root/alpha/demo/new.txt"

# 不是仓库的普通文件夹
mkdir "$m14_root/plain"
```
