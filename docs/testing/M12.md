# M12：系统集成与设置的对齐验收

M12 承接 [M11](M11.md)，在本机与服务器仓库上修正以下行为，M1–M11 的验收步骤继续适用：

- 去掉 Issue 追踪、SSH Agent 里的 1Password、终端程序 Prompt 与 Gerrit 推送，工具栏自定义面板去掉 Stage All 与 Commit
- 内置主题用新的默认配色，主题目录里仍是旧默认配色的内置主题文件在启动时换成新配色，改过的保留；Default 与 Default (Dark) 不能改名、删除；Themes 页由字体框、记号类别列表、胶囊形色块与 Diff 预览组成；`.spookytheme` 是 Spooky 的文稿类型，在 Finder 里双击或拖到 Dock 图标上导入
- Dock 图标的右键菜单只有 New Window；拖到 Dock 图标上的文件夹按普通打开处理，不是仓库时以单独的模态对话框询问；App 没运行时经链接或文件启动，只开目标窗口
- 克隆完成与自动归档分支之后发系统通知
- 新版本第一次启动时，仓库窗口的侧边栏底部出现新功能卡片；What’s New 列出历次版本，没读过的带蓝点；Settings › General 勾上 Show Developer menu 后主菜单出现 Developer
- 丢失页说明里的路径把主目录写成 `~`；失效的书签只有变灰的名字与警告图标
- Finder 的入口都叫 Show in Finder；服务器仓库按 B 的目录在这台 Mac 上的挂载交给 Finder，也能在仓库设置里指定本机目录；服务器仓库的文件交给 VS Code、VS Code Insiders 与 Cursor 时，经 Remote SSH 直接打开 B 上的文件
- 仓库设置的身份行、Line Character Limit 的 Set 与 Unset、Signing Key 与 Allowed Signers File 的弹出菜单；身份档案菜单在提交区、仓库设置与仓库管理详情三处相同
- Environment 默认读取登录 shell 的环境变量；Terminal 与 iTerm 按已有的窗口决定在哪里执行；只有 Kaleidoscope 比较目录，TextMate 用 App 包里的 `mate`
- Activity 的行高、Remote 行的标题与分条、进度条与日志区；检出的记录标题带上版本名
- ⌘Z 能撤销与重做远端、子模块、Git LFS 的启用、assume-unchanged、发布分支与标签和重命名远端分支
- 子模块行的右键菜单是 AppKit 菜单，Checkout Revision 子菜单分组列出分支与标签
- Dock 里的运行时图标与包内图标画法一致，透明与色调样式下不换图标；关于窗口是自己绘制的面板
- 新建工作树后窗口不变；储藏列表的行左右内边距 20 pt

## 准备

### 本机

本机的测试目录放在系统临时目录下，测试结束后删除。Git 只读写这里的一份全局配置；子模块从本机路径克隆，要允许 file 协议：

```sh
m12_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m12.XXXXXXXX")"
mkdir "$m12_root/config" "$m12_root/clones" "$m12_root/themes" "$m12_root/普通 文件夹"
export GIT_CONFIG_GLOBAL="$m12_root/config/gitconfig"
export GIT_CONFIG_NOSYSTEM=1
git config --global init.defaultBranch main
git config --global user.name 'Spooky Test'
git config --global user.email 'spooky@example.invalid'
git config --global commit.gpgSign false
git config --global protocol.file.allow always
```

```sh
# lib-src：子模块的来源，附注标签 v1 之后 main 还有一个提交
m12_lib="$m12_root/lib-src"
git init -q "$m12_lib"
printf 'lib\n' > "$m12_lib/lib.txt"
git -C "$m12_lib" add -A
git -C "$m12_lib" commit -q -m 'Lib start'
git -C "$m12_lib" tag -a v1 -m 'Version 1'
printf 'more\n' >> "$m12_lib/lib.txt"
git -C "$m12_lib" commit -q -a -m 'Lib more'

# 本机 仓库：裸远端 remote.git，子模块 lib，标签 v1
m12_repo="$m12_root/本机 仓库"
m12_git() { git -C "$m12_repo" "$@"; }
git init -q --bare "$m12_root/remote.git"
git init -q "$m12_repo"
printf 'base\n' > "$m12_repo/readme.txt"
printf 'notes\n' > "$m12_repo/notes.txt"
m12_git add -A
m12_git commit -q -m 'Start'
m12_git remote add origin "$m12_root/remote.git"
m12_git push -q -u origin main
m12_git submodule add -q "$m12_lib" lib
m12_git commit -q -m 'Add lib'
m12_git tag v1
m12_git push -q origin main

# topic：没有上游；old-topic：最后一个提交在 2000 年，自动归档时列出它
m12_git switch -q -c topic
printf 'topic\n' > "$m12_repo/topic.txt"
m12_git add -A
m12_git commit -q -m 'Topic work'
m12_git switch -q -c old-topic main
printf 'old\n' > "$m12_repo/old.txt"
m12_git add -A
env GIT_AUTHOR_DATE='2000-01-01T00:00:00Z' GIT_COMMITTER_DATE='2000-01-01T00:00:00Z' git -C "$m12_repo" commit -q -m 'Old work'
m12_git switch -q main

# 本机 工作树：分支 wt 的工作树
m12_git worktree add -q -b wt "$m12_root/本机 工作树"

# other.git：撤销远端操作时添加的远端
git init -q --bare "$m12_root/other.git"

# slow：获取时先停 30 秒，用来看进行中的行
printf '#!/bin/sh\nsleep 30\nexec git upload-pack "$@"\n' > "$m12_root/slow-upload-pack"
chmod +x "$m12_root/slow-upload-pack"
m12_git remote add slow "$m12_root/remote.git"
m12_git config remote.slow.uploadpack "$m12_root/slow-upload-pack"

# noisy：收到推送时逐行输出 300 行，用来看日志区跟随新输出
git init -q --bare "$m12_root/noisy.git"
printf '#!/bin/sh\nfor i in $(seq 1 300); do echo "line $i"; sleep 0.05; done\n' > "$m12_root/noisy.git/hooks/pre-receive"
chmod +x "$m12_root/noisy.git/hooks/pre-receive"
m12_git remote add noisy "$m12_root/noisy.git"

# 把本机路径写成 spooky://open 链接里的 repository 参数
m12_link() { python3 -c 'import urllib.parse,sys; print(urllib.parse.quote(sys.argv[1]))' "$1"; }
```

主题文件 `Aurora.spookytheme` 由内置的 Default 改出，背景是浅黄色：

## 主题

1. 按 [M6](M6.md) 的 “主题” 第 1–11 步验收，新的默认配色按 [M2](M2.md) 的 “主题、语言和入口审计” 第 2 步核对。
2. Settings › Themes 的版式：
    - 页面宽 900 pt：左边主题列表宽 200 pt，右栏宽 652 pt
    - 右栏从上到下是 250 × 20 的字体框、记号类别列表、色块行、横线与 Diff 预览
    - Diff 预览 652 × 222 pt，与右栏同宽；上方的横线两端贴齐右栏
    - + 与 − 在主题列表外框的左下角：+ 贴着外框左边，− 在 + 右边 2 pt
    - 色块是胶囊形，外圈约 3 pt 的深灰描边，正在编辑的色块外圈是蓝色
3. 旧默认配色的迁移：退出 Spooky，执行下面的命令，把两个内置主题文件写成旧的默认配色，`Default (Dark)` 的新增色另改成自己的颜色，再执行 `m12_open`。
    - `Default.spookytheme` 换成新配色：不可见字符 30%，新增与删除 12%
    - `Default (Dark).spookytheme` 是改过的，内容不变
    - 两个文件的名称、文件名与外观的选择都不变

```sh
python3 - "$HOME/Library/Application Support/Spooky/Themes" <<'EOF'
import json, sys

def rewrite(name, colors):
    path = f"{sys.argv[1]}/{name}.spookytheme"
    theme = json.load(open(path))
    theme["colors"].update(colors)
    json.dump(theme, open(path, "w"), indent=2)

# Default：旧的默认配色
rewrite("Default", {
    "invisible": {"hex": "#000000", "alpha": 1},
    "added": {"hex": "#28CD41", "alpha": 0.18},
    "deleted": {"hex": "#FF3030", "alpha": 0.18},
})

# Default (Dark)：旧的默认配色，新增色换成自己的颜色
rewrite("Default (Dark)", {
    "background": {"hex": "#000000", "alpha": 1},
    "selection": {"hex": "#FBD1AD", "alpha": 1},
    "added": {"hex": "#00FF00", "alpha": 0.18},
    "deleted": {"hex": "#FF453A", "alpha": 0.2},
})
EOF
```

4. 执行 `m12_open "$m12_root/themes/Aurora.spookytheme"`：Themes 列表多出 Aurora，`$m12_root/themes` 里的原文件还在。再执行一次：询问 Theme Already Exists；设置窗口开着时询问挂在它上面，否则单独弹出。点 Cancel。

## Dock、打开文件与冷启动

1. App 运行时右键 Dock 里的 Spooky 图标：App 自己的项目只有 New Window，其余是系统的窗口列表与 Options、Show All Windows、Hide、Quit。点 New Window 开一个显示仓库管理的新窗口。
2. 从 Finder 把 `本机 仓库` 拖到 Dock 图标上：在当前窗口打开它。
3. 把 `普通 文件夹` 拖到 Dock 图标上：
    - 弹出单独的模态对话框 No Git Repository Found，写明 “<完整路径>” 不是 Git 仓库并问是否在这里新建，按钮是 Cancel 与 Create Repository
    - 对话框不挂在窗口上，标题栏的关闭按钮与 Cancel 相同；点 Cancel 什么都不变
    - 把同一个文件夹拖进仓库管理窗口：同样的询问以 sheet 挂在窗口上
4. 把 `Aurora.spookytheme` 拖到 Dock 图标上：与 “主题” 一节第 4 步相同，按导入处理。
5. 冷启动：每一项都先退出 Spooky 再执行命令。
    - `m12_open "spooky://open?repository=$(m12_link "$m12_repo")"`：只开 `本机 仓库` 的窗口，没有另外的仓库管理窗口
    - `m12_open "$m12_repo"`：只开 `本机 仓库` 的窗口
    - `m12_open 'spooky://clone?url=https://github.com/rakuyoMo/Spooky.git'`：只开一个窗口，上面是预填地址的克隆对话框；点 Cancel
    - `m12_open "$m12_root/普通 文件夹"`：先弹出第 3 步的模态对话框，点 Cancel 后出现仓库管理窗口
    - `m12_open "$m12_root/themes/Aurora.spookytheme"`：先询问是否替换同名的 Aurora，点 Cancel 后出现仓库管理窗口
    - Settings › General 勾上 Show Quick Start Window on Launch 后重复最后两项：出现的是启动窗口；核对后取消勾选

## 系统通知

1. 克隆：File › Clone Git Repository… ⌃⌘C，地址填 `printf '%s\n' "$m12_root/remote.git"` 的输出，克隆到 `$m12_root/clones`。
    - 第一次发通知前，系统询问是否允许 Spooky 发送通知；之前拒绝过的，在 “系统设置 › 通知 › Spooky” 里打开允许通知

## 撤销

在 `本机 仓库` 里做下面的操作。每做完一项，Edit 菜单写 Undo <操作名>；按 ⌘Z 撤销、⇧⌘Z 重做，用每组后面的命令核对撤销后回到操作前、重做后回到操作后。连接远端的撤销与重做记在 Activity 的 Remote 页。

1. 远端，用 `m12_git config --get-regexp '^remote\.'` 核对：
    - Repository › Add New Remote…，Name 填 `backup`，Remote URL 填 `printf '%s\n' "$m12_root/other.git"` 的输出：Undo Add Remote Repository
    - 右键 `backup` → Rename “backup”…，改为 `mirror`：Undo Rename Remote
    - 单击 `mirror`，在 General 分段改 Fetch URL（Undo Edit Fetch URL）；Push URL 点 Set（Undo Edit Push URL），再点 Unset（Undo Unset Push URL）
    - Fetch Refspecs 点 Add Refspec 填 `+refs/tags/*:refs/tags/*`（Undo Add Fetch Refspec），再 Edit、Delete 这一条（Undo Edit Fetch Refspec、Undo Delete Fetch Refspec）
    - 勾选 Skip on “Auto-Fetch” and “Fetch All”：Undo Change Fetch Options
    - 右键 `mirror` → Delete “mirror”…：Undo Delete Remote Repository，撤销后地址、refspec 与选项都与删除前相同
2. assume-unchanged：执行 `printf 'mark\n' >> "$m12_repo/readme.txt"`，Working Copy 里右键 `readme.txt` → Mark › Set Assume Unchanged：Undo Set Assume Unchanged。
    - `m12_git ls-files -v readme.txt` 以 `h` 开头，撤销后以 `H` 开头
    - View › Working Copy Status › Show Assume-Unchanged Items ⌃⌘U 列出标记了的文件，它的 Mark › Unset Assume Unchanged 同样能撤销与重做
    - 核对后执行 `m12_git checkout -- readme.txt`
3. Git LFS：仓库设置的 Git LFS 段点 Enable Git LFS：Undo Enable Git LFS；`m12_git config --local --get-regexp '^filter\.lfs\.'` 列出 `filter.lfs.*`，撤销后没有输出。
4. 发布与远端分支，用 `git -C "$m12_root/remote.git" for-each-ref --format='%(refname)'` 核对：
    - 右键 `topic` → Publish Branch，推到 `origin` 并跟踪：Undo Publish Branch；撤销后远端没有 `refs/heads/topic`，`m12_git rev-parse --abbrev-ref 'topic@{upstream}'` 报错，重做后两者都回来
    - 右键 Tags 里的 `v1` → Publish “v1”…，发布到 `origin`：Undo Publish Tag
    - 右键 Remotes 下的 `origin/topic` → Rename “origin/topic”…，改为 `topic-renamed`：Undo Rename Remote Branch
5. 子模块，用 `m12_git submodule status` 与 `cat "$m12_repo/.gitmodules"` 核对：
    - Repository › Add New Submodule…，地址填 `printf '%s\n' "$m12_lib"` 的输出，路径填 `lib2`：Undo Add Submodule
    - 右键 `lib2` → Rename “lib2”…，名称改为 `library`：Undo Rename Submodule；重做后这一行写 `library`
    - 单击 `library`，在 Shared Config 与 Local Config 段改 Remote URL（Undo Edit Submodule URL）、Update Strategy（Undo Set Submodule Update Strategy）、Ignore Mode（Undo Set Submodule Ignore Mode）与 Fetch Mode（Undo Set Recurses Submodules Option）
    - 右键 `library` → Move “library”…，移到 `vendor/lib2`：Undo Move Submodule
    - 右键 `lib` → Checkout Revision ▸ 里的标签 `v1`：Undo Checkout Submodule Revision；`git -C "$m12_repo/lib" describe --tags` 输出 `v1`，撤销后 `git -C "$m12_repo/lib" rev-parse --abbrev-ref HEAD` 输出 `main`
    - 右键 `library` → Delete “library”…：Undo Delete Submodules，撤销后它的工作区、`.gitmodules` 的段与本地配置都回来
    - 执行 `printf 'dirty\n' > "$m12_repo/vendor/lib2/dirty.txt"`，再删除 `library`，询问 Force Delete 时确认：Edit 菜单写 Can’t Undo Delete Submodules
6. 提交身份与忽略规则的修改不能撤销，按 [M7](M7.md) 的 “Reflog 与撤销” 第 5 步验收。

- SMB、NFS、AFP、sshfs 与 WebDAV 的真实挂载：Show in Finder 的自动查找，以及在仓库设置里手动指定的目录核对通过的情形，自动测试只用指向同一目录的符号链接代替挂载
- Cursor 登录账号后的编辑区，以及 VS Code 与 Cursor 经 Remote SSH 打开真实的 B
- Araxis Merge：命令行经 Apple 事件控制 App，第一次比较时弹出授权框

前两项由维护者按 “服务器仓库” 一节验，Araxis Merge 在发布后按用户反馈验证。

## 收尾

```sh
defaults delete com.rakuyo.spooky 2> /dev/null
test -e "$m12_root/no-preferences" || defaults import com.rakuyo.spooky "$m12_root/preferences.plist"
rm -rf "$HOME/Library/Application Support/Spooky"
test -d "$m12_root/application-support" && ditto "$m12_root/application-support" "$HOME/Library/Application Support/Spooky"
find "$HOME/Library/Logs/DiagnosticReports" -name 'Spooky-*.ips' -newer "$m12_root/config/gitconfig" -delete
m12_ssh "rm -rf '$m12_remote'"
rm -rf "$m12_root"
./scripts/build-app.sh
```

最后一行重新生成开发 Bundle，去掉验收时放进去的更新说明。
