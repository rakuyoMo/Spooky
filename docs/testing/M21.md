# M21 工作区、历史与提交详情的验收

范围：Working Copy 的状态头、空状态、文件列表的表格与偏好、状态徽标、冲突与已解决状态、重载后的选择与动画、文件级写操作的局部忙态、工作区类写操作的整页进度、文件菜单与空白处菜单、删除并暂存删除；History 的提交行、引用徽标、加载与分页、选择与右键、日期条件与视图设置、签名、Autosquash 横幅与 Reflog；提交详情的头部、变更集、文件菜单、导出与操作条，整页提交详情，文件历史与搜索补全；删除正在使用的主题。M1–M20.5 的验收步骤继续适用。

所有命令在仓库根目录执行。界面验收需要已解锁、显示器正常显示的 macOS 会话；深色与浅色外观各验一遍，截图用 2×，坐标以窗口左上角为原点，单位 pt。

- `RepositorySessionTests`：工作区类写操作的整页进度，检出、合并、拉取、变基、重置与同步的拉取步骤各自的标题，停止后进度清空、HEAD 不动。

- `RepositoryLFSTests`：Git LFS 是否启用的判断（过滤器与仓库的 pre-push 钩子）。
- `HistoryListTests`：提交行的分隔线、日期写法、引用徽标的折叠、首屏加载行的延迟出现与延迟收起、分页与读取后的选中、右键的作用对象与 Reveal in History、导出条目的覆盖确认、窗口副标题、视图设置的默认值、Since Dates 建议。

- `SignatureVerificationTests`、`CommitSignatureDisplayTests`：签名的短标识、SSH 与 OpenPGP 的区分，详情头部的签名行。
- `RepositoryRewriteTests`、`RepositoryReflogTests`、`ReflogSessionTests`：可以自动压缩的提交数；Reflog 每页 30 条、重读后的选中与带时间的两种写法。
- `CommitDetailHeaderTests`、`ChangesetFileMenuTests`、`ChangesetPresentationTests`、`CommitFileListTests`：详情头部的行与日期；变更集菜单的作用文件、标题与复制内容；变更文件行的点选、方向键与滚动；整页详情的作者行与文件数。
- `RevisionExportTests`：导出条目进已有目录，替换同名条目、保留其余内容、部分失败如实报告。
- `RepositoryFileViewsTests`、`FileViewsTests`：文件历史的四种搜索范围、整个仓库的作者与提交人、补全的子序列匹配与分组、按月分组、打开即选第一个提交与重读后的选中。
- `ThemeStoreTests`：删除正在使用的主题后，选着它的外观回到同外观的内置主题。

## 准备

按 [M7](M7.md) 的 “准备测试仓库” 在本机执行准备脚本，后文沿用它的 `history`、`refs`、`rewrite` 与 `m7_root`、`m7_git`。另建一个工作区仓库 `wc`：

```sh
m21_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m21.XXXXXX")"
m21_git() { "$m7_root/git" -C "$m21_root/wc" "$@"; }

"$m7_root/git" -c init.templateDir= init -q -b main "$m21_root/wc"
m21_git config --local user.name 'Spooky Test'
m21_git config --local user.email spooky@example.invalid
m21_git config --local commit.gpgSign false

# 已跟踪的文件：普通、部分暂存、assume-unchanged、带通配符的路径、很深的中文路径与两份冲突用的文件
mkdir -p "$m21_root/wc/dir" "$m21_root/wc/文档/很长的一级目录/再长一级的目录"

for name in plain.txt partial.txt hidden.txt 'dir/[x].txt' conflict-a.txt conflict-b.txt; do
    printf 'one\ntwo\nthree\n' > "$m21_root/wc/$name"
done

printf 'deep\n' > "$m21_root/wc/文档/很长的一级目录/再长一级的目录/发布 说明.md"
printf '*.log\n' > "$m21_root/wc/.gitignore"
m21_git add --all
m21_git commit -q -m 'Add the files'

# conflict 分支与 main 改动两份文件的同一行
m21_git switch -q -c conflict
printf 'one\ntwo (conflict)\nthree\n' | tee "$m21_root/wc/conflict-a.txt" > "$m21_root/wc/conflict-b.txt"
m21_git commit -q -am 'Change on conflict'
m21_git switch -q main
printf 'one\ntwo (main)\nthree\n' | tee "$m21_root/wc/conflict-a.txt" > "$m21_root/wc/conflict-b.txt"
m21_git commit -q -am 'Change on main'

# 工作区：未暂存修改、部分暂存、assume-unchanged、未跟踪与被忽略
printf 'changed\n' >> "$m21_root/wc/plain.txt"
printf 'staged\n' >> "$m21_root/wc/partial.txt"
m21_git add partial.txt
printf 'unstaged\n' >> "$m21_root/wc/partial.txt"
m21_git update-index --assume-unchanged hidden.txt
printf 'new\n' > "$m21_root/wc/untracked.txt"
printf 'log\n' > "$m21_root/wc/debug.log"

./scripts/build-app.sh
open -n -a .build/Spooky.app "$m21_root/wc"
```

慢暂存用的大文件在用到时再建，测完删除。导出在 A 上另建一个目录接收：`m21_exports="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m21-exports.XXXXXX")"`。

## 工作区与文件列表

1. 截图核对状态头：分支名、分离 HEAD 与未出生分支的写法与颜色；工作区干净时文件列表留空，右侧是 No file selected，历史详情没有选中时也是同一句。
2. 表头排序：点表头换排序，关掉窗口重开、退出重启后排序不变；字号与截断方式同样跨窗口与重启保留，已有的偏好不被默认值覆盖。
3. 徽标：普通两列状态、未跟踪 “?”、被忽略 “!”（打开 Show Ignored Items）各看一次，列宽 68 时左右两格的位置；文件名前是按名称取的文件图标。
4. 冲突：`m21_git stash -q` 收起工作区的改动后 `m21_git merge conflict`，两份文件是带圆角底与叠加标记的冲突行；解决其中一份后它显示已解决的对勾并保留到合并结束；选中与深浅色各截一次。第 10 步的合并冲突也在这时核对，之后 `m21_git merge --abort` 与 `m21_git stash pop -q`。
5. 重载：平铺、树形与输入过滤词三种情况下，分别丢弃、暂存与提交选中的一行：行有增删动画，多选里留下的行仍选中，选中的行全部消失时选中它的下一行（没有下一行时上一行）。
6. 局部忙态：`dd if=/dev/urandom of="$m21_root/wc/big.bin" bs=1m count=1024`，勾选 `big.bin` 暂存：执行期间只有这一行禁用并显示目标状态，其它行的勾选框可点，点下后在这次暂存之后执行；结束后两项都已暂存。在终端 `touch "$m21_root/wc/.git/index.lock"` 后再勾选：失败报告一次，行回到真实状态；删掉 `index.lock` 与 `big.bin`。
7. 整页进度：在 `refs` 里依次检出分支（含远端分支建跟踪分支）、Check Out Revision、Reset HEAD、合并、拉取、变基、交互式变基：期间整个工作区换成进度页（标题、进度条、停止按钮与 Git 的最后一行输出），侧边栏 Working Copy 行转圈；点停止后进度页消失，刷新后是仓库的真实状态。新建分支勾选检出、Update Branch 与 Sync 的拉取步骤同样有进度页，Sync 的获取与推送没有。
8. 文件菜单：单选、多选、选区外的一行、目录各右键一次，标题点名或计数（目录算一项），选区外右键不改选区与右侧详情；Copy File Path、Discard Local Changes… 的写法；Open in Terminal 单个文件进所在目录、目录进该目录、多选禁用。
9. 空白处右键：有选择时作用于原选区、选择不变；没有选择时暂存、丢弃、删除等禁用，Open 不打开文件，Quick Look 不预览，Show in Finder 与 Open in Terminal 指向仓库根，储藏四项以通用标题列出并禁用。
10. 冲突子菜单：普通文件、单个与多个冲突文件各右键一次，两个父项都能展开，标题点名或计数，分支名带引号；没有冲突过的文件 Restore Unmerged Version 禁用。按 [M16](M16.md) “冲突向导” 一节制造储藏引起的冲突，标题写 Applied Patch or Stash，不加引号。
11. Mark ▸：不打开 Show Assume-Unchanged Items，打开 Show Non-Modified Items，`hidden.txt` 只有 Unset 可用，`plain.txt` 只有 Set 可用。
12. Compare ▸：只有已暂存改动、只有未暂存改动、两者都有、未跟踪、冲突、多选与空白处各核对一次项目、分隔线与可用状态；空白处比较整个工作区。
13. LFS ▸：在 `wc` 里右键，三项禁用；本机装有 git-lfs 时执行 `m21_git lfs install --local` 后再右键，三项可用，仓库设置 Git LFS 段同样显示已启用。

## 删除并暂存删除

1. 先执行 `m21_git ls-files -s -v` 记下结果。打开 Show Non-Modified Items，选中 `partial.txt` 与 `hidden.txt` 按 ⌘⌫，再右键 `dir/[x].txt` → Move to Trash：文件进废纸篓，列表里是已暂存的删除；`m21_git status --short` 三项都是 `D `。
2. 取消暂存其中一个删除，再按 ⌘Z 依次撤销取消暂存与两次删除：文件回到原处，`m21_git ls-files -s -v` 与第 1 步记下的相同，`partial.txt` 已暂存的内容还在，`hidden.txt` 仍是 `h`。
3. 删除 `untracked.txt` 与被忽略的 `debug.log`：只进废纸篓，索引不变。
4. `chmod 555 "$m21_root/wc/dir"` 后删除 `dir/[x].txt` 与 `plain.txt`：错误框标题是没有全部删除，原文先列已移走的项再接原始错误；之后 `chmod 755 "$m21_root/wc/dir"`。

## 历史列表

打开 `history`。

1. 截图核对中号、小号、关掉提交图与窄窗口四种行；未拉取的提交选中时文字仍是次要色。头像的提示是 “姓名 <邮箱>”，提交行与列表头的引用名没有提示。关掉提交图后改回，保存的行高不变。
2. 打开 `refs`：一个提交上的 HEAD、本地分支、远端分支与标签按顺序排列，窄窗口里从放不下的那个起折叠成 “…”；在终端移动一个分支后徽标跟着刷新。
3. 首屏读取慢于 0.5 s 时第一行出现加载行，读完后收起；滚到末尾续页时表格末尾是 Loading commits… 与 Cancel，点 Cancel 后不再续读；搜索没有结果时第一行居中是 No commits。
4. 打开与换看引用后自动选中第一个提交；按住 ⌘ 选中两个提交后右键选区外的第三个：复制与写操作只作用于被点的提交，选区与详情不变。Copy Commit Info 的每行是 “短哈希 标题”。双击打开整页详情，Return 与 Enter 没有动作。
5. 在某个分支的历史里右键提交 → Reveal in History：切到全部历史并选中它；多选时没有这一项。
6. 第一次打开的视图设置按日期排序、按月分组；工具栏搜索框输入 `2026-01-01` 一类日期，补全第一条是 Since。
7. 打开 Verify Signatures：签名提交的按钮是绿点，系统设置 › 辅助功能 › 显示 › 区分时不仅依赖颜色 打开后红点与黄点换成方块与三角；点开弹窗，SSH 签名写 Signing Key，详情头部的签名行写 Signing Key 与 Signing Status。
8. 打开 `rewrite`：横幅写出可以自动压缩的提交数，按钮是 Autosquash…，右上角可以关闭；关闭后这次不再出现。
9. Reflog：看 HEAD 与某个分支各一次，副标题分别是 Reflog 与 Reflog (<分支>)；两种日期格式下每行带时间；打开即选第一条，换引用、搜索与刷新后选中的规则见自动测试；滚过 30 条后续页。

## 提交详情

1. 详情头部默认展开，点三角收起后换窗口、重启仍是收起；展开时是 Author、Author Date、Committer、Committer Date、Refs、Commit Hash、每个父提交一行 Parent Hash、Tree Hash，收起时是 Author、Author Date、Refs；没有引用时没有 Refs。看 `history` 里 Carol 与 Release Bot 的提交、合并提交与根提交。
2. 变更集文件行：未选中时路径是次要色，选中且列表有焦点时白字，没有焦点时文字颜色不变，状态图标都不变。
3. 变更文件多于一屏时用 ↑ ↓ 与 ⇧ ↑ ↓ 把选中移出可见范围：刚好滚到露出；已可见时不滚动。
4. 在三角左侧、行的上下边缘与文件名右侧的空白处右键与拖动，与点在文件名上相同；点三角只展开或收起。
5. 变更集菜单：在历史右侧详情、整页详情、Pull Request、比较视图与文件历史里各右键一次，标题写仓库内的完整路径（深路径与中文路径各一次），最前是 Copy File Path 与 Copy Relative File Path；多选时是 Open Diff Tool for N Items、Restore N Items 与 Export N Items。
6. 导出：选中一个文件与一个目录 → Export 2 Items，选 `$m21_exports`；再导出一次，弹出 Item Exists，取消时不动已有内容，Overwrite 后替换。把目标里一个子目录设为只读后再导出，错误框列出没导出的条目。
7. 操作条：在 HEAD 分支的提交详情上，鼠标进入详情后 ROLLBACK | REVERT | DIFFTOOL 出现在头部与提交说明之间的分隔线上，Tab 能聚焦，VoiceOver 读出三个按钮。
8. 整页详情：工具条在上、卡片在下；文件行两行（文件名与增删数、路径）；工具条的文件数在读取中与 0 个时不显示，空提交写 No changes.。双击一个文件，打开的内容是所选提交里的版本，不是当前工作区。返回用 ⌘[ 或工具栏。

## 文件历史

1. 在 `history` 里对 `log.txt` 打开文件历史：时间线按月分组，组名是大写的 “月份 年份”；打开即选中第一个提交并显示 Diff；头部的按钮只有文件名，点开仍是文件选择器。
2. 每个提交行有 32 pt 的头像，浅色、深色与选中状态下都正常。
3. 搜索范围菜单的标题是 File History，依次是 Message（默认）、Commit Hash、Author、Committer；按说明、哈希与人员各过滤一次。
4. 在 Message 范围输入 `al`：建议分 Authors、Messages、Committers 三组，人员是 “姓名 <邮箱>”，同名不同邮箱各一项；选中一个作者后范围切到 Author。在历史搜索框里作者与提交人的补全是同一份数据。
5. 在终端提交一次让 HEAD 移动：时间线后台重读，原选中还在时保留，不在时选中第一个。
