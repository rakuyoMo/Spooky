# M18 侧边栏与拖放验收

范围：Working Copy 行的标记、提示与右键菜单，分支、引用、分组与文件夹菜单，⌘⌫ 删除，双击、程序化选中与同名分支的跟踪检出，引用的公共顺序与侧边栏默认值，跟踪与父分支子菜单，归档建议与归档对话框，拖放落点、拖动影像上的动作名与 Push Branch 对话框。

所有命令在仓库根目录执行。界面验收使用临时仓库，需要已解锁、显示器正常显示的 macOS 会话。

## 自动验证

```sh
mise run swift:lint
mise run build
mise run test
swift build --product Spooky
./scripts/build-app.sh
```

- `SidebarTreeTests`、`SidebarSettingsTests`、`SidebarSessionTests`：六个优先分支名、其它名字、文件夹、远端与标签的公共顺序，侧边栏三个默认值与显式保存值，Pinned 只出现一次；Working Copy 行的数量、进行中操作的图标与提示，远端行的拉取与推送地址。
- `OperationWiringTests`：Working Copy 菜单七组的标题、顺序与 ⌥ 变体，Publish… 打开发布仓库而分支菜单的 Publish 只发布该分支；HEAD、非 HEAD 与远端分支的菜单差异，文件夹前缀，⌘⌫ 对不同选择的路由；非 HEAD 分支的安全强推绑定被点击的分支，远端变化后按租约拒绝；父分支子菜单的建议、当前值与移除；引用落点区分 Working Copy 与 HEAD，拖动影像上的动作名，Push Branch 对话框的预选与单分支推送。
- `BranchManagementTests`、`SidebarSessionTests`、`RepositorySidebarViewTests`：同名本地分支的跟踪检出、工作树占用与检出失败后的 HEAD、提交与上游；双击 HEAD、不能检出、别的工作树与同名的远端分支；程序化选中展开分组与文件夹并滚动到可见，分离 HEAD 的行名是短哈希。
- `BranchDialogTests`：新建分支的 Parent Branch 候选随起点核对。
- `BranchesReviewTests`：陈旧的当前分支进入归档建议，归档对话框的初始空选、全选与计数、取消与失效的候选，归档后 HEAD、提交、索引与工作区不变。
- `LocalizationTests`：八种语言的资源完整性与格式参数。

服务器上的同类写入由默认跳过的远端测试覆盖，`RemoteReferenceManagementTests` 在 B 上核对同名跟踪的检出、工作树占用与检出失败，父分支的设置与移除、归档与撤销不动引用与 HEAD，非 HEAD 分支的安全强推与单分支推送：

```sh
SPOOKY_REMOTE_TESTS=1 swift test --no-parallel --filter 'RemoteReferenceManagementTests|RemoteSidebarTests|RemoteBranchesReviewTests|RemoteBranchSyncTests'
```

## 准备

测试只使用临时的全局配置和仓库，不改用户的 Git 配置。`demo` 的当前分支 `feature/old-head` 与 `zeta`、`pinned-old` 只有早于 6 个月的提交，`pinned-old` 已置顶；`samename` 与 `origin/samename` 各有提交且不跟踪；`wt-branch` 在附加工作树里检出；`ahead` 比 `origin/develop` 多一个提交。`merging` 与 `picking` 分别停在合并与摘取的冲突上：

```sh
m18_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m18.XXXXXXXX")"
mkdir "$m18_root/config"
export GIT_CONFIG_GLOBAL="$m18_root/config/gitconfig"
export GIT_CONFIG_NOSYSTEM=1
git config --global user.name 'Spooky Test'
git config --global user.email 'spooky@example.invalid'
git config --global commit.gpgSign false
git config --global init.defaultBranch main

old='2025-01-10T10:00:00'
m18_commit() { git -C "$1" commit -q --allow-empty -m "$2"; }
m18_old_commit() { GIT_AUTHOR_DATE="$old" GIT_COMMITTER_DATE="$old" m18_commit "$@"; }

git init -q --bare "$m18_root/remote.git"
git clone -q "$m18_root/remote.git" "$m18_root/demo"
d="$m18_root/demo"
printf 'one\n' > "$d/notes.txt"
git -C "$d" add -A
m18_old_commit "$d" 'Initial'
git -C "$d" push -q -u origin main

for name in develop next alpha feature/search topic samename; do
  git -C "$d" switch -q -c "$name" main
  m18_commit "$d" "Work on $name"
  git -C "$d" push -q origin "$name"
done

git -C "$d" switch -q main
git -C "$d" branch -q -D topic alpha
git -C "$d" switch -q samename
git -C "$d" reset -q --hard main
m18_commit "$d" 'Local samename work'

for name in zeta pinned-old; do
  git -C "$d" switch -q -c "$name" main
  m18_old_commit "$d" "Old $name work"
done

git -C "$d" config branch.pinned-old.spooky-pinned true

for name in release/1.x feature/a-very-long-branch-name-for-checking-how-the-sidebar-truncates-names wt-branch; do
  git -C "$d" switch -q -c "$name" main
  m18_commit "$d" "Work on $name"
done

git -C "$d" switch -q main
git -C "$d" worktree add -q "$m18_root/demo-wt" wt-branch
git -C "$d" tag v1.0 main
git -C "$d" tag v2.0 develop
git -C "$d" tag release/v3.0 next
git -C "$d" branch -q --no-track ahead origin/develop
git -C "$d" switch -q ahead
m18_commit "$d" 'Ahead work'

git -C "$d" switch -q -c feature/old-head main
m18_old_commit "$d" 'Old head work'
printf 'stash\n' >> "$d/notes.txt"
git -C "$d" stash push -q -m 'Saved notes'
printf 'two\n' >> "$d/notes.txt"
printf 'scratch\n' > "$d/scratch.txt"

for name in merging picking; do
  r="$m18_root/$name"
  git init -q "$r"
  printf 'base\n' > "$r/a.txt"; git -C "$r" add -A; m18_commit "$r" 'Base'
  git -C "$r" switch -q -c other
  printf 'other\n' > "$r/a.txt"; git -C "$r" add -A; m18_commit "$r" 'Other'
  git -C "$r" switch -q main
  printf 'main\n' > "$r/a.txt"; git -C "$r" add -A; m18_commit "$r" 'Main'
done

git -C "$m18_root/merging" merge -q other || true
git -C "$m18_root/picking" cherry-pick other || true
```

## Working Copy 行与菜单

1. 打开 `demo`：Working Copy 行的数量为 2；悬停提示写出本地 HEAD 分支 `feature/old-head` 与 2 个未提交的文件，远端行 `origin` 的提示分别写出 Fetch URL 与 Push URL。
2. 右键 Working Copy：依次为 Check Out 子菜单（全部本地分支，HEAD 打勾，分隔线后是 Check Out Revision…）、Create Snapshot…、Push… / Push Revision To… / Pull… / Publish…、Discard All Local Changes… / Reset to Revision…、Merge With Revision… / Rebase On Revision… / Apply Patch…、Compare 子菜单、Copy File Path / Show in Finder / Open in Terminal，组间有分隔线。按住 ⌥：Create Snapshot… 变为 Quick Create Snapshot。
3. 在一个停在合并冲突上的仓库与一个停在摘取冲突上的仓库里，Working Copy 行不显示数量，分别显示两种不同的图标。

## 分支与引用菜单

1. 右键非 HEAD 的 `main`：有 Check Out “main”、Publish “main”…、Push “main” To…、Force Push with Lease…，没有 Push… 与 Merge；末尾有 Export Files from “main”…、Compare “main” with Revision…、Reveal in History。HEAD 分支的菜单没有检出组，有 Pull…、Push…、Merge With Revision…、Rebase On Revision… 与 Rebase Onto Revision…。
2. 右键远端分支：第一项是 Pull “origin/…”…，有 Track “origin/…”…、Copy Remote Branch Name to Clipboard，没有 Merge。
3. 右键分支文件夹 `feature`：只有 Create New Branch…，名称预填 `feature/`；标签文件夹 `release` 只有 Create New Tag…。Branches、Tags、Remotes 的标题分别有 Create New Branch…、Create New Tag…、Add Remote Repository…。
4. 选中 `zeta` 按 ⌘⌫：出现删除确认；取消后 `zeta` 仍在。选中两个本地分支时菜单标题为 Delete 2 Branches…。

## 双击与同名分支

1. 双击 HEAD 分支：没有动作，也不响铃。双击 `main`：检出 `main`。
2. 双击 `wt-branch`：打开 `demo-wt`；按住 ⌘ 双击时在新标签页打开。
3. 双击 `origin/samename`：询问检出已有的本地分支并跟踪远端分支。Cancel：HEAD、`samename` 的提交与上游都不变；Continue：HEAD 为 `samename`，提交不变，上游为 `origin/samename`。
4. ⌘0 或在历史里定位折叠在文件夹里的分支：展开分组与各级文件夹，选中并滚动到可见。

## 归档

1. 点侧边栏底部的归档按钮：对话框列出 `feature/old-head` 与 `zeta`，原因为橙色的 Stale，不列 `pinned-old` 与 `main`；初始都不勾选，Archive 不可用，右上为 0 of 2 selected。
2. 勾 Select All：计数变为 2 of 2 selected；Archive 后两个分支的 `branch.<名称>.spooky-archived` 为 true，`git for-each-ref refs/heads` 与 `git status` 不变；⌘Z 后两项配置都被删除。

## 拖放

1. 把远端分支拖到 HEAD 分支行并按住 ⌥：拖动影像上显示 Track，松开后 HEAD 的上游改为这个远端分支；拖到 Working Copy 行按住 ⌥ 时没有动作名，松开不改上游。
2. 把远端分支拖到 Branches 标题：拖动影像上显示 Track；再拖到无效的位置，动作名消失，松开不执行。
3. 把本地分支拖到远端 `origin`：显示 Publish；移到历史列表上松开，不执行。再把同一个分支拖到 `origin`：仍显示 Publish，松开打开发布对话框。
4. 把 `ahead` 拖到 `origin/develop`：打开 Push Branch，只有 Local Branch 与 Remote Branch 两个下拉，分别预选 `ahead` 与 `origin/develop`。Cancel 不推送；Push Branch 后远端 `develop` 指向 `ahead`，远端没有标签，`ahead` 不设上游。
