# M3：工作区、Diff 与提交验收

M3 承接 M1、M2；[M1](M1.md) 的窗口、最近记录、错误恢复和五语界面，以及 [M2](M2.md) 的服务器连接、重连、终端和主题验收继续适用。

## 自动验证

在仓库根目录执行：

```sh
swift build --package-path SpookyKit
swift test --package-path SpookyKit
swift build --package-path SpookyKit --product Spooky
./scripts/build-app.sh
```

远端测试默认跳过。显式启用全部测试：

```sh
SPOOKY_REMOTE_TESTS=1 swift test --package-path SpookyKit
```

只运行 M3 的服务器流程：

```sh
SPOOKY_REMOTE_TESTS=1 swift test --package-path SpookyKit --filter RemoteWorkingCopyTests
```

测试沿用 `spooky-test`、专用密钥、禁用 PTY 与 agent 转发的配置。每次只在 `/Users/wgy/spooky-test/` 下建立独立目录并清理，不修改双方 SSH 或全局 Git 配置。

自动测试覆盖：

- 新增、修改、删除、重命名、复制状态、类型变化、二进制、冲突与空文件。
- 空格、中文、引号、反斜杠、通配符；Git 补丁另覆盖制表符、换行、非 UTF-8 内容和 NFC / NFD 路径。
- 单块、后续块的行号定位、非连续行、CRLF、末尾无换行、删除文件的部分暂存和恢复、整块新增 / 删除、旧快照拒绝。
- UTF-8 提交正文、NFC 规范化、SHA-1 / SHA-256、Amend、实际提交人、钩子错误与草稿保留。
- 三态勾选的乐观更新与失败回滚、本机 FSEvents 自动刷新、暂存后选区保留。
- 合并冲突采用一侧、标记解决、双亲提交、中止，以及变基 / 摘取 / 反转的进行中状态识别。
- SFTP 特殊路径读写、按行暂存与服务器提交、Amend、永久丢弃、断线提交失败和重连核对。

## 本机 App 提交闭环

先按 [M1 的临时仓库步骤](M1.md#准备临时仓库) 创建仓库。提交身份仅写入该测试仓库：

```sh
env GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1 \
    /usr/bin/git -C "$m1_directory/仓库 with spaces" \
    config --local user.name 'Spooky Test'

env GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1 \
    /usr/bin/git -C "$m1_directory/仓库 with spaces" \
    config --local user.email spooky@example.invalid

env GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1 \
    /usr/bin/git -C "$m1_directory/仓库 with spaces" \
    config --local commit.gpgSign false

printf '第一行\n第二行\n第三行\n' > "$m1_directory/仓库 with spaces/你好 [draft].txt"
```

1. 执行 `swift run --package-path SpookyKit Spooky`，按 ⌘O 打开测试仓库。截图核对三栏、当前分支、改动数量、标题 / 正文输入与提交人。
2. 选中文件。核对 Unstaged 中的新增行；未选文件显示空状态，二进制只显示提示。
3. 点击第一、第三行的行号。确认选区只作用于改动行，块头变为 “暂存所选行”。点击暂存后，勾选框呈半选；Staged 只有选中行，Unstaged 保留第二行。
4. 输入标题与多行正文，按 ⌘↩ 提交。确认成功后输入清空，尚未暂存的第二行仍存在。
5. 暂存剩余改动并提交，确认列表为空、分支仍正确。截图保存干净状态。
6. 在终端修改测试文件，确认不按刷新也自动出现。再验证 ⌘R。分别通过菜单、右键和勾选框暂存 / 取消暂存，选区在刷新后保留。
7. 切换平铺 / 树形，重新打开仓库，确认偏好保留。树形目录可展开，多选后点击已选行的勾选框作用于整个选择。

## Diff、丢弃与修补

1. 修改文件两处，间隔超过 6 行；分别测试整块、单行、非连续行、拖动连选及 ⇧ 范围选择。正文可选择复制，点击正文不改变行号选区。
2. 在显示 Diff 后从终端再次修改文件，再执行原选区操作。确认报出文件变化并刷新，终端的新内容没有被覆盖。
3. 对文件、块、行和全部改动分别选择丢弃。每次必须确认；取消后内容不变。文件丢弃包含暂存改动，未跟踪文件会被删除。
4. 在 General 把大 Diff 阈值调低，打开超阈值文本补丁。确认先显示字节数与 Show Diff，点击后加载；切换文件后恢复警告。二进制仍显示二进制提示。验收后恢复 `20,000 kB`。
5. 勾选 Amend，核对最近提交信息被载入；确认框明确说明改写最近提交。取消确认保留草稿，成功修补后提交数量不增加。
6. 信息框外按住 ⌥，核对 Commit → Amend、Stage All → Unstage All；松开恢复。标题 / 正文聚焦时按 ⌥ 不切换信息编辑模式。
7. 添加失败的 `pre-commit` 钩子，提交后确认错误原文可复制，标题与正文保留；移除钩子后重试成功。

## 冲突收尾

只在测试仓库的终端中创建两条修改同一文件的分支，执行合并以产生冲突。

1. 横幅显示合并状态与冲突数量；文件为 U 徽标和浅红背景，提交区在冲突未解决时隐藏。
2. 分别通过详情和右键采用 ours / theirs；也测试手工修改后勾选 “标记已解决”。缺失的一侧按删除收尾。
3. 全部解决后检查预填提交信息，提交并验证得到两个父提交。
4. 重新构造冲突并中止，确认工作区回到合并前状态。
5. 在终端发起变基、摘取、反转并使其停在冲突处，确认横幅类型正确。变基说明必须写清 ours 为上游、theirs 为正在重放的提交；仅在合适状态显示 Continue / Skip。

## 服务器 App 提交闭环

按 [M2 的准备步骤](M2.md#准备-app-测试仓库) 创建本次专用服务器仓库。通过相同测试密钥和别名修改其中的文件，禁止访问其它仓库。

1. 从 App 的添加服务器表单打开 `spooky-test` 与测试路径，重复本机的 “查看 Diff → 按行暂存 → 提交 → 状态干净” 流程，并分别截图。
2. 修改文件后等待前台约 2 秒刷新；切后台后验证 10 秒轮询，重新激活立即刷新。
3. 文件 / 块 / 行丢弃的确认必须标明服务器和永久删除 / 覆盖；确认后核对 B 上的实际内容。
4. 只关闭本次 Spooky 的专属控制 socket，确认断线期间写按钮禁用；写入中断时保留输入并显示错误，不能误报提交成功或自动重试。
5. 重连后核对分支、暂存状态和进行中操作，再由用户显式重试。
6. 关闭仓库并退出本次 App，清理本次服务器测试子目录。

## 入口与可访问性核对

| 动作 | 入口 | 快捷键 / 变体 |
|---|---|---|
| 暂存 / 取消暂存文件 | 勾选框、Working Copy 菜单、文件右键 | 文件列表空格 |

| 聚焦提交标题 | Working Copy 菜单、工具栏 | ⇧⌘C |
| 提交 / 修补 | 提交区 | 编辑信息时 ⌘↩、小键盘 Enter；信息框外 ⌥⌘↩ 修补 |
| 丢弃文件 | Working Copy 菜单、文件右键、多选详情 | ⇧⌘⌫；始终确认 |

## 实现说明与限制

- 丢弃文件、块、行始终确认，不提供跳过确认的设置；服务器确认明确说明在 B 上永久删除或覆盖。
- 大 Diff 统一按补丁字节数计算，保留 `256 MiB` 输出硬上限；二进制内容只显示提示。
- 标题与正文在 Working Copy 中保持可见，Amend 提交前明确确认。
- 服务器提交信息始终通过 stdin；实际提交人取仓库所在机器的 `GIT_COMMITTER_IDENT`。
- 系统 SFTP 批处理不能表示含 CR / LF 的路径，相关文件访问明确失败；Git 补丁的路径仍可包含换行。
- 现有 Prompt 3 / Local Terminal 的终端入口保留 M2 的一处 `#warning`，本次没有新增未核实的 Swift TODO。
