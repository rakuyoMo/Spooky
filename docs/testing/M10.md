# M10：工作区与提交的对齐验收

M10 承接 [M9](M9.md)，在本机与服务器仓库上修正以下行为，M1–M9 的验收步骤继续适用：

- 工作区状态头只有一行当前分支与跟踪分支，文件列表铺到底；刷新、写入与刷新失败时工作区不显示文字
- 提交区的提交人取仓库所在机器上生效的 `user.name` 与 `user.email`，没有配置时留空
- 丢弃未跟踪文件、Discard All Changes… 里的未跟踪文件与删除的文件移进废纸篓，服务器仓库移进 B 的废纸篓，⌘Z 移回原处
- 服务器仓库里删除或覆盖文件前的确认可以勾选 Do not ask me again，Settings → General 逐项列出
- 服务器仓库的未跟踪文件很多时照常列出
- 修补不弹确认；Hard Wrap 只改显示，提交时不断行
- 冲突向导里两侧都要保留时交给合并工具

## 自动验证

在仓库根目录执行：

```sh
mise run swift:lint
mise run build
mise run test
swift build --product Spooky
./scripts/build-app.sh
```

M10 新增与修改的自动测试覆盖：

- 丢弃：已跟踪的改动恢复到最后一次提交，未跟踪文件进废纸篓、内容不变；永久删除只在服务器没有废纸篓、用户确认后使用
- 撤销与重做：丢弃与删除移进废纸篓的文件和目录，撤销时移回原处，重做时重新移进废纸篓并记下新的位置；废纸篓里的项已经不在时撤销被拒绝，仓库保持原样；会话里 Discard All Changes… 与删除的撤销
- 服务器的废纸篓：在本机执行 B 上用的同一份 `/usr/bin/trash -v` 脚本，名字带引号、换行与中文时取出各项在废纸篓里的位置；移回前先核对，原位置被占用时一项也不移动；输出格式不符的项没有位置；体检脚本找到的废纸篓程序
- 服务器仓库的确认：关掉以后直接执行；丢弃块与 General 页已有的 Warn when discarding changes in a chunk 共用一个偏好
- 提交：Hard Wrap 下超长的正文原样提交，修补不弹确认，提交人来自 `user.name` 与 `user.email`
- 提交正文的显示：Hard Wrap 时不折行、可以横向滚动，超长的行整行铺警告底色；Soft Wrap 时只标出超出的部分

`SPOOKY_REMOTE_TESTS=1` 开启的服务器测试里，丢弃与删除使用确认后的永久删除，不写 B 的废纸篓。

## 准备

### 本机

本机的测试目录放在系统临时目录下，测试结束后删除。Git 只读写这里的一份全局配置：

```sh
m10_root="$(mktemp -d "${TMPDIR:-/tmp}/spooky-m10.XXXXXXXX")"
mkdir "$m10_root/config"
export GIT_CONFIG_GLOBAL="$m10_root/config/gitconfig"
export GIT_CONFIG_NOSYSTEM=1
git config --global init.defaultBranch main
git config --global user.name 'Spooky Test'
git config --global user.email 'spooky@example.invalid'
git config --global commit.gpgSign false
```

测试仓库：

```sh
# 工作区：一个已提交的文件
m10_repo="$m10_root/本机 仓库"
git init -q "$m10_repo"
printf 'base\n' > "$m10_repo/tracked.txt"
git -C "$m10_repo" add -A
git -C "$m10_repo" commit -q -m 'Start'

# 冲突：main 与 side 改了同一行
m10_conflict="$m10_root/冲突"
git init -q "$m10_conflict"
printf 'first\nsecond\nthird\n' > "$m10_conflict/conflict.txt"
git -C "$m10_conflict" add -A
git -C "$m10_conflict" commit -q -m 'Base'
git -C "$m10_conflict" switch -q -c side
printf 'first\nsecond (side)\nthird\n' > "$m10_conflict/conflict.txt"
git -C "$m10_conflict" commit -q -am 'Side'
git -C "$m10_conflict" switch -q main
printf 'first\nsecond (main)\nthird\n' > "$m10_conflict/conflict.txt"
git -C "$m10_conflict" commit -q -am 'Main'
```

### 服务器

B 是 macOS 15 或更高版本。服务器上的测试目录只经 `spooky-test` 在 `/Users/wgy/spooky-test/` 下新建，测试结束后删除；移进 B 的废纸篓的文件名都以 `m10-` 开头，收尾时从 B 的废纸篓删掉：

```sh
m10_ssh() { ssh -o BatchMode=yes spooky-test "$@"; }
m10_remote="$(m10_ssh 'umask 077; mkdir -p /Users/wgy/spooky-test && mktemp -d /Users/wgy/spooky-test/m10-app.XXXXXXXX')"
m10_ssh /bin/sh -s "$m10_remote" <<'EOF'
cd "$1"
git init -q -b main workspace
cd workspace
git config user.name 'Spooky Test'
git config user.email 'spooky@example.invalid'
printf 'base\n' > m10-tracked.txt
git add -A
git commit -q -m 'Start'
EOF
```

### 启动 App

先退出正在运行的 Spooky，记下偏好域与应用支持目录的状态，验收结束后恢复：

```sh
defaults export com.rakuyo.spooky "$m10_root/preferences.plist" 2> /dev/null || touch "$m10_root/no-preferences"
ditto "$HOME/Library/Application Support/Spooky" "$m10_root/application-support" 2> /dev/null || true

./scripts/build-app.sh
open --env "GIT_CONFIG_GLOBAL=$GIT_CONFIG_GLOBAL" --env GIT_CONFIG_NOSYSTEM=1 .build/Spooky.app
```

## 工作区状态

打开 `本机 仓库`。

1. 状态头只有一行 “main › No Tracking”，下面没有 ahead、behind 与改动数量；文件列表一直铺到窗口底部，下面没有状态栏。
2. 在终端改动 `tracked.txt`，⌘R 与暂存、提交进行中，工作区都不显示文字。
3. 执行 `chmod 000 "$m10_repo/.git/index"` 后 ⌘R：弹出刷新失败的错误，工作区仍显示上一次的结果，没有说明文字。`chmod 644 "$m10_repo/.git/index"` 后再 ⌘R 恢复。
4. 打开 `冲突`，在终端执行 `git -C "$m10_conflict" merge side`：状态头仍是一行 “main › No Tracking”，“Merging “side” into “main”” 只写在横幅里。

## 提交区

回到 `本机 仓库`。

1. 展开提交区：头像左侧是 Spooky Test 与 spooky@example.invalid，打开仓库时不显示读取中的文字。在终端执行 `git config --global --unset user.name` 与 `git config --global --unset user.email` 后 ⌘R，两行都留空；验收后改回。
2. 暂存一个改动，勾选 Amend：复选框写出 “Amend <短哈希>”，按钮变为 Amend，标题与正文载入最近的提交信息。点 Amend 直接修补，不弹确认；`git -C "$m10_repo" rev-list --count HEAD` 不变。
3. 焦点不在输入框时按住 ⌥：按钮变为 Amend，点它同样直接修补；松开 ⌥ 恢复 Commit。
4. Settings → Editor 的 Body line wrapping mode 选 Hard Wrap（或点正文底部的折行按钮）：标题与正文变为等宽字体；正文写一行超过 72 个字，不折行而出现横向滚动，72 列处有参考线、右侧区域变浅，这一行整行是黄色底色。切回 Soft Wrap 后按视图宽度折行，只有超出 72 个字的部分是黄色底色。
5. 在 Hard Wrap 下提交：输入时不插入换行，`git -C "$m10_repo" log -1 --format=%B` 里那一行完整保留。Edit → Reformat Paragraph ⇧⌘W 仍按上限重排光标所在的段落，可以 ⌘Z 撤销。

## 丢弃、删除与废纸篓

### 本机仓库

1. 新建未跟踪文件 `m10-untracked [x].txt`，右键 Discard Changes：确认框写明已跟踪的文件恢复到最后一次提交、未跟踪文件放进废纸篓。确认后文件出现在 Finder 的废纸篓里；Edit → Undo Discard Changes（⌘Z）把它放回原处，内容不变；⇧⌘Z 再放进废纸篓。
2. 改动 `tracked.txt` 并新建 `m10-untracked [y].txt`，Working Copy → Discard All Changes…：确认后 `tracked.txt` 回到最后一次提交，`m10-untracked [y].txt` 在废纸篓里；⌘Z 后两者都回到丢弃之前。
3. 右键 `tracked.txt` → Move to Trash，或在列表里按 ⌘⌫：不确认，直接进废纸篓；⌘Z 放回原处。
4. 再丢弃一个未跟踪文件，然后在终端删掉废纸篓里的这个文件（`rm -- "$HOME/.Trash/<文件名>"`）：⌘Z 提示 Files can’t be put back from the Trash，写明仓库没有任何改动。

### 服务器仓库

在仓库管理窗口添加 `spooky-test` 上的 `$m10_remote/workspace`。

1. 右键 `m10-tracked.txt`：删除项写作 Move to Trash。按 ⌘⌫ 不确认，文件进入 B 的废纸篓：`m10_ssh 'test -e ~/.Trash/m10-tracked.txt && echo yes'` 输出 yes。⌘Z 把它移回原处，B 上的废纸篓里不再有它。
2. 在终端新建未跟踪文件：`m10_ssh "printf 'new\n' > '$m10_remote/workspace/m10-untracked.txt'"`。右键 Discard Changes：确认框写明已跟踪的文件在服务器上被最后一次提交覆盖、未跟踪文件移进服务器的废纸篓，下面有 Do not ask me again。确认后文件进入 B 的废纸篓；⌘Z 移回。
3. 改动 `m10-tracked.txt` 并新建 `m10-untracked-all.txt`，Discard All Changes…：确认后已跟踪的改动在 B 上被覆盖，`m10-untracked-all.txt` 进入 B 的废纸篓；⌘Z 都回来。
4. 再次丢弃时勾选 Do not ask me again 并确认：之后丢弃这个服务器仓库的改动不再询问。Settings → General 里与 Warn when discarding changes in a chunk 列在一组的有 Warn when discarding changes in a server repository、Warn when permanently deleting files in a server repository 与 Warn when restoring files in a server repository，刚才那一项没有勾选；勾选后丢弃时再次询问。勾选框只在确认时生效，勾选后点 Cancel 不改变设置。
5. 丢弃块或行的确认同样有 Do not ask me again：勾选并确认后，General 页的 Warn when discarding changes in a chunk 变为不勾选，本机仓库丢弃块时也不再询问；验收后改回。
6. 文件历史的 Restore… 与文件树的恢复：确认写明在服务器上覆盖，有 Do not ask me again，对应 Warn when restoring files in a server repository。
7. 编辑器副本写回前 B 上的版本已经变化时的覆盖询问不在这组设置里。
8. 未跟踪文件很多时照常列出：`m10_ssh "cd '$m10_remote/workspace' && mkdir many && for i in \$(seq 1 1200); do : > many/m10-\$i; done"`，⌘R 后全部列出，文件列表上方没有提示。删掉这个目录。

B 上没有可用的废纸篓程序时（macOS 14 及更早，或 Linux 上没有 `gio` 与 `trash-put`）：删除项写作 Delete，确认框写明在服务器上永久删除，可以勾选 Do not ask me again；丢弃的确认写明未跟踪文件在服务器上永久删除。

## 冲突向导

回到 `冲突`，合并仍停在冲突上。

1. 选中 `conflict.txt`：头部是冲突类型与重新载入；“Version from “main”” 与 “Version from “side”” 两张卡片各有 Resolve Using；下方是合并工具的按钮，没选合并工具时写 Choose Merge Tool。没有由 Spooky 写出两侧合并结果的按钮。
2. 在 Settings → Git Config 选一个合并工具后，按钮变为 Merge in <工具名>：在工具里保留两侧的行并保存，文件写回并标记解决，横幅的冲突数变为 0。

## 入口核对

| 动作 | 菜单与快捷键 | 工具栏与视图内控件 | 右键与拖放 |
|---|---|---|---|
| 丢弃 | Working Copy → Discard Changes ⇧⌘⌫、Discard All Changes… | 多选时详情区的 Discard Changes | 文件右键 Discard Changes；侧边栏 Working Copy 右键 Discard All Changes… |
| 删除 | — | 多选时详情区的 Move to Trash（服务器没有废纸篓时为 Delete） | 文件右键 Move to Trash / Delete；列表里 ⌘⌫ |
| 撤销 | Edit → Undo ⌘Z、Redo ⇧⌘Z | — | — |
| 确认的开关 | — | Settings → General | 服务器仓库确认框里的 Do not ask me again |
| 折行 | Edit → Reformat Paragraph ⇧⌘W | 正文底部的折行按钮 | Settings → Editor 的 Body line wrapping mode |
| 冲突向导 | — | 版本菜单、Resolve Using 各按钮、合并工具按钮与重新载入 | 文件右键的 Resolve Merge Conflicts、Restore Merge Conflict Versions |

## 还没实测

- 真实 B 在 “远程登录” 里关闭或打开 “允许远程用户完全磁盘访问” 时的废纸篓
- B 上确实没有用户登录图形界面时的废纸篓
- Linux 上的 `gio trash` 与 `trash-put`：文件按 freedesktop 规范放进 `~/.local/share/Trash`；这两个程序不报告废纸篓里的位置，这些丢弃与删除不能用 ⌘Z 移回

以上三项在发布后按用户反馈验证。

## 收尾

```sh
defaults delete com.rakuyo.spooky 2> /dev/null
test -e "$m10_root/no-preferences" || defaults import com.rakuyo.spooky "$m10_root/preferences.plist"
rm -rf "$HOME/Library/Application Support/Spooky"
test -d "$m10_root/application-support" && ditto "$m10_root/application-support" "$HOME/Library/Application Support/Spooky"
m10_ssh "rm -rf '$m10_remote'; cd ~/.Trash && rm -rf m10-tracked.txt m10-untracked.txt m10-untracked-all.txt"
rm -rf "$m10_root"
```

B 上的进程没有完全磁盘访问权限时列不出废纸篓里的文件，只能按名字删除；同名文件进废纸篓时名字后面会加上时间，这类文件在 B 的 Finder 里删掉。本机废纸篓里 `m10-` 开头的文件同样删掉。
