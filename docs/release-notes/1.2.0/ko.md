### 새 기능

- 저장소 윈도우가 좁아져 세 개의 열이 들어가지 않으면 좁은 윈도우용 레이아웃으로 바뀝니다. 사이드바 대신 도구 막대 아래의 행에서 “작업 사본”, “기록”, “스태시”를 전환하고, 목록이 위에, 세부사항이 아래에 놓입니다. 행 맨 앞의 “사이드바” 버튼을 클릭하면 전체 사이드바가 보기 위에 겹쳐서 열립니다. 윈도우를 넓히면 세 개의 열이 원래 너비 그대로 돌아오고, 현재 보기, 선택한 항목, 쓰고 있던 커밋 메시지는 그대로입니다
- 좁은 윈도우에서는 도구 막대에 들어가지 않는 버튼이 » 메뉴로 들어가고, “가져오기”, “풀”, “푸시”는 도구 막대에 남습니다
- “저장소” 윈도우도 좁아지면 레이아웃이 바뀝니다. 저장소 목록이 위에, 선택한 저장소의 세부사항이 아래에 놓이고, 둘 사이의 선을 드래그해 높이를 조절할 수 있습니다
- “보기” 메뉴의 “윈도우 레이아웃”에서 “좁게” 또는 “넓게”를 선택하면 윈도우 너비와 상관없이 그 레이아웃을 사용합니다. 기본값인 “자동”을 선택하면 윈도우 너비에 따라 레이아웃이 바뀝니다. 이 선택은 모든 윈도우에 적용됩니다
- “저장소” 윈도우에서 저장소를 제거하고 다시 추가하지 않아도 위치를 바꿀 수 있습니다. 세부사항의 “위치” 행에 포인터를 올리고 “편집” 버튼을 클릭합니다. 서버 저장소는 호스트 별칭이나 경로 중 하나만 바꿀 수도 있습니다. 들어 있는 그룹과 직접 바꾼 이름은 그대로입니다
- 리퀘스트 세부 정보의 “CI/CD” 보기에서 로그가 있는 검사나 작업을 펼치면 그 행 아래에 로그가 표시됩니다. GitHub Actions 작업은 끝난 뒤에 로그를 볼 수 있습니다. GitLab 파이프라인의 작업은 모두 펼칠 수 있고, 실행 중인 작업은 로그도 상태와 함께 업데이트됩니다
- “대화”에서 리퀘스트의 레이블을 추가하고 제거할 수 있습니다. 레이블 이름 뒤의 ×를 클릭하면 제거되고, “추가”를 클릭하면 프로젝트의 레이블 중 하나를 고를 수 있습니다. “새 레이블…”로 레이블을 새로 만들어 리퀘스트에 추가할 수도 있습니다
- 리퀘스트의 댓글이나 답글을 쓰거나 댓글을 편집할 때 @를 입력하면 누군가를 언급할 수 있습니다. 리퀘스트에 참여한 사람과 프로젝트의 멤버가 나열되고, 사용자 이름이나 이름을 이어서 입력하는 동안 목록이 좁혀집니다. Return을 누르면 사용자 이름이 들어갑니다

### 개선

- 풀 리퀘스트와 머지 리퀘스트 목록이 제목 뒤의 텍스트 대신 제목 앞의 아이콘으로 상태를 표시합니다. 열려 있는 리퀘스트는 초록색, 초안은 회색, 닫힌 리퀘스트는 빨간색, 병합된 리퀘스트는 보라색입니다
- 설정의 “업데이트” 페이지에서 릴리스 채널이 “안정 버전”, “베타 버전”, “알파 버전”으로 바뀌었습니다. 베타 버전과 알파 버전은 1.2.0-beta.1처럼 버전 번호에 beta나 alpha가 붙어, “Spooky에 관하여”와 업데이트 윈도우에서 바로 구별할 수 있습니다

### 수정

- Spooky를 업데이트할 때마다 계정의 토큰이나 키체인에 저장한 자격 증명을 읽으면서 키체인 암호를 다시 묻던 문제를 수정했습니다. 이 버전을 설치한 뒤에는 저장된 항목마다 처음 읽을 때 한 번 더 묻습니다
- 설정의 “SSH 호스트” 페이지에서 별칭을 바꾼 뒤, 책갈피에 있는 그 호스트의 저장소가 이전 별칭으로 연결하다 실패하지 않습니다. 이 저장소들의 설정과 키체인에 저장한 자격 증명도 새 별칭으로 옮겨집니다
- 풀 리퀘스트나 머지 리퀘스트를 보고 있을 때 “새로 고침”과 ⌘R로 목록과 선택한 리퀘스트를 다시 읽습니다. 같은 윈도우에서 이 저장소로 돌아올 때도 목록을 다시 읽습니다
- 풀 리퀘스트나 머지 리퀘스트 목록을 다시 읽어도 목록 뒤쪽에 있는 리퀘스트의 선택과 세부사항이 사라지지 않습니다
- 설정의 “일반” 페이지에서 “저장소 목록에 작업 트리 표시”를 끈 상태로 작업 트리를 열어도 더 이상 책갈피가 자동으로 추가되지 않습니다
