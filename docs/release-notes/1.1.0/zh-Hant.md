### 新增

- 設定新增 “SSH 主機” 頁，可以檢視、加入、編輯與刪除 ~/.ssh/config 裡的主機別名，按兩下別名或按 Return 鍵即可編輯；Spooky 只改你動過的那幾行，其他選項與註解保持原樣
- Pull Request 與 Merge Request 列表可以從 “開啟中” 切換到 “全部”，連已關閉與已合併的請求一起列出
- 請求的標籤顯示在列表與 “討論” 裡
- 請求詳情新增 “CI/CD” 視圖，顯示整體狀態與每一項檢查或作業的結果，等待或執行中時自動更新；列表的每一列也顯示 CI/CD 狀態

### 改進

- 伺服器儲存庫的連線、Git 命令、檔案讀寫與取消都更快，網路延遲高時尤其明顯；連線中斷時也能更快察覺
- 在 “提交標題” 裡貼上多行文字時，第一行留在標題，其餘內容放進 “詳細說明”
- 在 “儲存庫管理” 視窗裡，按 Return 鍵改為重新命名選取的書籤或群組，不再開啟儲存庫，按 Esc 取消；開啟儲存庫用按兩下，按一下已選取列的名稱也不再進入重新命名
- 儲存庫視窗的預設工具列加入 “Finder”、“終端機”、“安全強制推送” 與 “新增分支”，“快速操作”、“同步” 與 “合併” “重定基底” 改為按需從 “自訂工具列…” 加入；想完整換成新的排列，在那裡把預設的一組拖到工具列上
- 刪除書籤時，如果伺服器上已經沒有這個儲存庫的資料夾，移到垃圾桶的註記框是灰的，只移除書籤
- 再次開啟 GitLab 儲存庫時，一開始就以 Merge Request 稱呼請求，不用等讀出遠端
- Merge Request 關閉或合併滿 14 天後，GitLab 會刪掉它的來源分支參照；這時擷取它的提交會提示 “提交已無法取回”
- 切換分支、暫存等操作因為找不到 git-lfs 而失敗時，錯誤提示為 “Git LFS 無法使用”，並依本機或伺服器儲存庫說明怎樣設定 PATH
- 伺服器上 ~/.spooky/bin 裡超過 30 天沒有用過的舊版輔助指令碼會自動刪除
- 各語言介面文字的用詞與標點更一致

### 修正

- 在伺服器儲存庫裡寫入檔案時中途斷線或取消，不再損壞原檔案
- 網路短暫停頓時，伺服器儲存庫的連線與正在執行的命令不再中斷
- 取消伺服器儲存庫的檔案寫入後，不再顯示已連線、之後的寫入卻被拒絕
- 伺服器儲存庫裡 Git 新建的檔案依登入時的 umask 設定權限，與直接登入伺服器執行 Git 時相同
- 遠端位址裡帶的密碼不再出現在活動記錄與錯誤訊息裡
- 路徑看起來相同、位元組不同的兩個伺服器儲存庫不再共用一條連線
- 連續更換 App 圖示時，最後選的那一組生效
- 工具列的 “複製” 項目可以移動和移除，“自訂工具列…” 裡也一直列出它
- 拉取時，活動的摘要不再顯示 Git 寫出的原始擷取結果
