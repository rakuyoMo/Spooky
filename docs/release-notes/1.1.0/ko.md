### 새 기능

- 설정에 “SSH 호스트” 페이지가 생겨 ~/.ssh/config의 호스트 별칭을 보고, 추가하고, 편집하고, 삭제할 수 있습니다. 별칭을 이중 클릭하거나 Return을 누르면 편집할 수 있으며, Spooky는 편집한 줄만 바꾸므로 다른 옵션과 주석은 그대로 남습니다
- 풀 리퀘스트와 머지 리퀘스트 목록을 “열림”에서 “전체”로 바꾸면 닫히거나 병합된 리퀘스트도 함께 보입니다
- 리퀘스트의 레이블이 목록과 “대화”에 표시됩니다
- 리퀘스트 세부 정보에 “CI/CD” 보기가 추가되어 전체 상태와 검사나 작업별 결과를 보여 주며, 대기 중이거나 실행 중인 항목이 있으면 자동으로 갱신합니다. 목록의 각 행에도 CI/CD 상태가 표시됩니다

### 개선

- 서버 저장소의 연결, Git 명령, 파일 읽기와 쓰기, 취소가 빨라졌습니다. 지연이 큰 네트워크일수록 효과가 크고, 연결이 끊긴 것도 더 빨리 알아챕니다
- “커밋 제목”에 여러 줄을 붙여 넣으면 첫 줄은 제목에 남고 나머지는 “상세 설명”에 들어갑니다
- “저장소” 윈도우에서 Return을 누르면 저장소를 여는 대신 선택한 책갈피나 그룹의 이름을 변경하고, Esc로 취소합니다. 저장소는 이중 클릭으로 엽니다. 선택된 행의 이름을 클릭해도 더 이상 이름 변경이 시작되지 않습니다
- 저장소 윈도우의 기본 도구 막대에 “Finder”, “터미널”, “강제 푸시”, “브랜치 만들기”가 들어가고, “빠른 동작”, “동기화”, “병합”, “리베이스”는 필요할 때 “도구 막대 사용자화…”에서 추가합니다. 새 배치로 완전히 바꾸려면 그곳에서 기본 세트를 도구 막대로 드래그하세요
- 책갈피를 삭제할 때 폴더가 더 이상 서버에 없는 저장소는 휴지통 체크상자를 선택할 수 없고 책갈피만 제거됩니다
- GitLab 저장소를 다시 열면 원격을 읽기 전부터 “머지 리퀘스트”라고 표시합니다
- GitLab은 머지 리퀘스트가 닫히거나 병합되고 14일이 지나면 소스 브랜치 참조를 삭제합니다. 그 뒤에 커밋을 가져오려 하면 “커밋을 더 이상 가져올 수 없음”이라고 알려 줍니다
- 브랜치 전환이나 스테이지 같은 작업이 git-lfs를 찾지 못해 실패하면 오류 제목이 “Git LFS를 사용할 수 없음”으로 바뀌고, 로컬 저장소와 서버 저장소에 맞게 PATH 설정 방법을 안내합니다
- 서버의 ~/.spooky/bin에서 30일 동안 쓰이지 않은 이전 버전의 도우미 스크립트는 자동으로 삭제됩니다
- 모든 언어에서 화면의 용어와 문장 부호를 통일했습니다

### 수정

- 서버 저장소에서 파일을 쓰는 도중 연결이 끊기거나 쓰기를 취소해도 원래 파일이 손상되지 않습니다
- 네트워크가 잠깐 멈춰도 서버 저장소의 연결과 실행 중인 명령이 중단되지 않습니다
- 서버 저장소에서 파일 쓰기를 취소한 뒤 연결된 것으로 표시되면서 다음 쓰기가 거부되던 문제를 수정했습니다
- 서버 저장소에서 Git이 새로 만드는 파일의 권한이 로그인할 때의 umask를 따르므로, SSH로 로그인해 Git을 직접 실행할 때와 같습니다
- 원격 URL에 들어 있는 암호가 활동 로그와 오류 메시지에 나타나지 않습니다
- 경로가 같아 보여도 바이트가 다른 두 서버 저장소가 더 이상 연결을 공유하지 않습니다
- 앱 아이콘을 연달아 바꾸면 마지막에 선택한 그룹이 적용됩니다
- 도구 막대의 “복제” 항목을 옮기거나 제거할 수 있고, “도구 막대 사용자화…”에도 항상 표시됩니다
- 풀할 때 활동 요약에 Git의 가져오기 결과가 그대로 표시되지 않습니다
